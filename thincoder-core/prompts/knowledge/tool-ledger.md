  - `trigger` = `归批` / `条件` / `认账不排期` (optional).
  - `resume_when` = the sentence saying when the entry resumes (optional; when given it may not be blank, and it may carry an anchor `@YYYY-MM-DD` (judged) or `@<event>` (not judged by machine)).
  - **The `task_book` gate** — same on `add` and `update`, judged on what this call writes. An entry that ends up in `在途` / `待核销`, or a call that sets `trigger` = `归批`, must carry `task_book`: absent / empty / blank is refused.
  - A call that writes `task_book` (non-empty), or that sets `trigger` = `归批`, is also held to the pointer: its file part, the text before the first `§`, must resolve, with that file on disk, else refused.
  - A call that does not touch the pointer is not judged: a stale pointer left by an earlier call never blocks a `status` / `evidence` / other-field update — "is the file on disk" is the `taskBookOnDisk` reading, not a gate.
  - **Reserved pointer** — put the marker `（预定）` at the tail of the value (`docs/batches/<x>.md（预定）`) to register the intent to work a record that does not exist yet; that pointer passes the gate while its file is absent (`taskBookOnDisk` stays `false`, a reading not a gate). It must be a project-relative path — no declared-repo prefix and no absolute path, or it is refused; and once that record is on disk the marker is surplus and refused (drop it).
  - `batch create` on that same path later **claims this row** instead of opening a second one: the pointer is rewritten to the plain form, the row goes to `在途`, and no new row appears. Omit `ledger` and `newDebt` there and a reserved row for the path wins before the same-face check. Two reserved rows on one path are refused and named one by one — picking one would silently drop the other's intent.
- `update`: moves an entry along the six-state table, edge by edge — `待讨论→待设计` / `待讨论→在途` / `待设计→在途` / `在途→待核销` / `在途→待讨论` / `待核销→已核销` / `待核销→在途` / `待核销→待讨论` / any unsettled state → `已废弃`. `已核销` and `已废弃` are terminal; every edge not on that list is refused.
  - `待讨论→在途` is the ignition path: opening a batch moves its coverage rows straight to `在途`, never through `待设计` (`待设计` means design is scheduled, not that ignition happened).
  - `待核销→在途` is the reopen or manual return path and always writes the current session as executor. An explicit old executor does not override it.
  - `在途→待讨论` and `待核销→待讨论` return unfinished work to the waiting pool. They require this call's non-blank `evidence` as the reason, append it to the row, clear `executor` / `task_book` / `trigger`, preserve `created_at`, and return `reason` in the receipt.
  - Give exactly one of `id` / `batch`.
  - `status` omitted = update only the fields you passed; `resume_when` omitted = unchanged; `executor` omitted = entering `待设计` / `在途` writes this session, and leaving `在途`, returning to `待讨论`, or withdrawing clears it.
  - `evidence` appends (old value non-empty ⇒ `old｜new`, nothing around `｜`; old empty ⇒ written as given). `evidenceReplace: true` together with `evidence` replaces the whole text; the flag alone, or a blank new value, is refused.
- `update --batch`: one migration across a batch (`batch` = the batch-record pointer; the rows whose `task_book` sits on that record are handled together).
  - With `status` ⇒ every row is re-judged against the migration table; without `status` ⇒ a pure field patch, `status` untouched.
  - Receipt `{ batch, status, applied, skipped }`; each skipped row is named `{ id, from, why }` (`why` = that row's own refusal text) and the rest still land; a transaction-level failure rolls the whole batch back.
  - A `batch` that does not resolve to a record on disk is refused.
- `close`: settle (`待核销 → 已核销`) — the one settling edge. `待讨论` / `待设计` / `在途` are refused, naming the current state and that state's way out. Withdrawal is allowed only from an unsettled state; both archived states reject further archival writes.
  - Settlement requires non-blank work `evidence` after applying this call. Existing evidence is sufficient; a blank replacement is refused and leaves the row unchanged.
  - **Archiving a row is tied to its batch record.** Before either archived target lands (`已核销` to settle, `已废弃` to withdraw), the record its `task_book` points at is read: a record whose §1 status line reads `进行中` refuses the write — `批档未收口 … 请先 batch close（同笔结算并冻结档）` for a settlement, and `先退回 待讨论（携理由）再 已废弃，或先 batch close` for a withdrawal from `在途` / `待核销`. The row is left unchanged either way, and `batch close` settles the row and freezes the record in one action.
  - `update` to either archived state is held to the same gate, and `close --batch` / `update --batch` name each refused row in `skipped` with that gate's own words. A record whose §1 status line cannot be read (missing, or two or more in the §1 header zone) is refused separately and names its repair: exactly one status line in that zone, written by the main agent as an ordinary document write.
  - Four cases pass the gate without a record to judge, and the receipt carries one `notices` entry per such row — `{id, reason, message}`, key omitted when there is none — for a single-row receipt and at the top level for a `batch` one: the pointer resolves to a file that is not a batch record (`pointer-not-a-record`), the pointer has no file part (`no-task-book`), the pointer does not resolve or its file is not on disk (`record-not-on-disk`, a record may be cleaned up), or the row is a `待讨论` / `待设计` retro-close (`retro-close`). A gate side-step is not work evidence, so it never touches `evidence`.
  - Soft delete: the row keeps its content and gains a `closed_at`, and a settled row's settled time is the close, not an update.
  - `status` is required on a single-row close: `已核销` to settle, `已废弃` to withdraw. Give exactly one of `id` / `batch`. `evidence` / `evidenceReplace` behave as in `update`, and an omitted `evidence` leaves the row's own text as it stands.
