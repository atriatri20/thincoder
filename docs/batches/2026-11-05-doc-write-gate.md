## 这道门不管什么（写进设计，免得以为什么都能挡）

- **判不了内容对不对**：两处说反、尺寸档越线、验收里塞整套测试——一条都抓不到，那是评审的活。
- **判不了「该不该有这段」**：缺用例、缺先例行、缺三问，都不是锚也不是段长。

## 边界

- 只补门，不改判据本体（`thincoder-core/doc-check/**` 的阈值与两支判据不动）。
- 不做「写入前先美化 ∥ 自动重排」——打回由作者自己改。
- 极端性能问题（大档每次写都要整档扫）不在本批优化，先量一条读数再说。

## 已定决定

- **已定决定**：「接长」不是已知漏点，**写时就要判得到**——`edit` ∥ `insert_after` ∥ `hashline_edit` ∥ `apply_patch` 的判面**从「插入的那段字」扩到「本次写入落入的那个段落」**：先算改后整档，定位被触碰的段落，判该段整段（含原有字）。 · 用户原话：「一句接一句的问题其实也是可以在写的时候检查的啊！」 · 时间：2026-11-05 02:52

## 判面（修正后 · 四形）

| 情形 | 判面 |
|---|---|
| 改动落在某段内部（改字 ∥ 接句子 ∥ 换行只在段内） | **改后那一段整段**（原有字 + 本次新字） |
| 改动插入空行（一段拆两段） | **拆出来的两段** |
| 改动删行（两段并一段） | **并出来的那一段** |
| 本次写入不触碰任何既有段（纯新增段 ∥ 判面为空） | 只判新增的那段；空判面 ⇒ 零判 |

**为什么不是判整档**：整档判会把作者改不动的旧账变成他的写入门槛（用户 02:47 已裁：只判自己写的那部分）。**判被自己触碰的段落**是「自己写的那部分」的自然边界——段落就是读者读到的单位，判到段为止既不越界也不漏。

**代价（明写）**：`edit` 每次要多算一次改后整档 + 定位段落（局部计算，不扫全档判据）。这笔代价换掉的是「接长永远判不到」。

### 一、`root` 缺省回落的界——**改设计，不改代码**

- 设计档 §3.26「入参缝」现写：缺省回落 = `owningProject(abs, cwd)`。

  - 「取根面（`projectRootView`）传**目标所在盘根**（向上无界——目标由调用方指名）」
  - 「台账面（`resolveLedgerRoot`）传**会话锚**（越界即停——用户 2026-10-25 19:09「不能跑到工作目录以外去」）」
- **为什么这条不能含糊**：拿 cwd 当界时，`owningProject` 那句 `if (!isInsideOrEqual(dir, edge)) return null` 会让写项目外的档取不到根 ⇒ **零判**；而同一目标在 `faceDetail` 里（上溯无界）判成 `doc-root` ⇒ **门把自己关掉，且关掉的样子与「不该判」一模一样**。一个会静默失效的门比没有门更坏。

## 关键决策

1. **判集只判新写的字**（用户 2026-11-05 02:47 原话）：整档判会把改不动的旧账变成写入门槛，谁写该档谁被拒；窄判集把死锁从根上去掉。
2. **剥公共前后缀取改动区、再扩到段落 ∥ 围栏边界，不逐 hunk 拆**：第二套 diff 引擎的代价与收益不成比例；段划法借引擎谓词族（单源 `thincoder-core/doc-check/paragraph.mjs`），不另立第二套。
3. **片段档住目标档同目录**：锚解析序 ② 与落盘后同源；前缀用 `.docgate-` 与批档门的 `.gate-` 分开——两门各清各的残留，互不误报。
4. **不缓存 manifest 读数、不做写入前美化**：本批只补门（§1 边界照旧）。
5. **判面从「新写的字」扩到「触碰的段落」**：用户 2026-11-05 02:52 原话「一句接一句的问题其实也是可以在写的时候检查的啊！」——把 40 字接到 280 字段落尾部，只判那 40 字看不见越线；段落是读者读到的单位，也是「自己写的那部分」的自然边界。原窄口登记同轮删除：门自己判得到，不留兜底。
6. **用例编号 = DD-164–DD-173**：`DD-157`–`DD-163` 已被本档 §3 用例表的列表项符号集那批判据占用（本席实读：`docs/core/design/DOC-DISCIPLINE.md` §3.18 用例表列表项符号集块），本批新例顺延，免两处同号。
