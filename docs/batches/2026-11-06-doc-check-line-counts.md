### 为什么做进工具而不是脚本

**脚本要先被想起来才会去调。**做进工具，它在手上。

更关键：**尺子只要还在人手里，就永远有人拿自己的。**`doc_check` 是每次设计 / 开发轮都要跑的门，行数读数长在里面，量法就没有第二种。

### 要什么（目标态）

1. `doc_check` 能报**给定文件清单的行数**——逐档一个数，量法单源 = 引擎的 `countContentLines`（**函数本体为准，本档不重述算式**——重述一次就多一份会漂的抄本）；**口径单源，不在描述里重述算法**
2. 报数同时给出**是否越线**：`>500` 软线（主动审视）∥ `>800` 硬限（必须拆）；数值单源 = `docs/core/design/DOC-DISCIPLINE.md` §3.10
3. **成为唯一量法**：别的量法（shell 计数 ∥ 编辑器状态栏 ∥ 读工具行号）量出的数不是「另一种口径」，是错的
4. 工具描述里写清这条唯一性，以及「本读数只回答该不该拆，不构成对文档内容的判断」

### 边界

- **不改** `doc_check` 既有的两条判据（锚 ∥ 段长）与 `report` ∥ `gate` 两态语义

- **不把行数写回文档**：读数在工具输出里，不在状态档里（用户 12:26 已裁「行数不写进文档」）

### 一、机制设计

**1. 量法的家：实现搬核，脚本转再出口缝。**

现实现住 `scripts/doc-check-linecounts.mjs`，本席实读其函数体首行 = `const parts = text.split("\n");`（末元素为空则 pop 一次，返回段数）。产品内核对 `scripts/**` 的 import 点必须为 0（同档 A-DD29 ⑤ ∥ A-DD31 ⑦），故搬入 `thincoder-core/doc-check/index.mjs` 并导出同名函数；脚本侧的函数体删除，改为从产品档位再出口。

先例 = `scripts/doc-check-paragraph.mjs`（薄档 · 零逻辑 · 逐名再出口，机制住 §3.20「产品档位」）。缝档**保留**（父侧本轮裁定）：头注写明「实现已迁核，本档只转出」——缝是永久薄壳，不是带到期日的兼容分支。

**2. 读数面 = 新参数 `lines`（仅 `report` 面）。**

`lines`：可选数组，元素为相对 `target`（解析基准）或绝对的档路径，收**任意在盘档**（源 / 单元测试 / `.md` 皆可）。语义 = 逐档出一行行数；**不是判据**——不进 `hits`、不进 `gate` 首行 verdict、不改既有跳过行与「读不到」行。

去重后按路径升序（同 `resolveRange` 的既有形）。`docs` 语义零改：仍是被判集、仍只收 `.md`（非 `.md` 直报 `not a markdown document`）、`report` 面不可判档照旧整次零判定。

**3. 档位标记的档类判据（闭集）。**

标 = 扩展名 ∈ `.mjs` / `.cjs` / `.js`（源 / 单元测试档）；其余档含 `.md` 只出数、`tier = null`。阈值 = `fileSoftMax` 500 ∥ `fileHardMax` 800，判据是**严格大于**：`>800` 标 `越 800 硬限（必须拆）`，`>500` 标 `越 500 软线（主动审视）`，`500` 及以下不标。

`.md` 不标是用户裁定下的行为，不是遗漏：依据 docs/core/design/DOC-DISCIPLINE.md「用户裁定：尺寸档位判据**只约束程序代码（源 / 单元测试档）**，文档**不受行数限制**」。

阈值本身单源 = 同档 §3.10：依据 docs/core/design/DOC-DISCIPLINE.md「文件档 `>500` **主动审视**；`>800` **必须拆**（封口语义，无豁免通道）。`.md` 档零尺寸档位义务。」

**4. 报面形（读数块 · 固定句形）。**

位置 = 「读不到」行之后、「行号坐标」清单块之前；块内无空行；报面末行仍是既有 `结论：…`（末行位不动）。示例（数字为形，不是读数）：

```text
行数读数（量法 = countContentLines · 档位标记只给源 / 单元测试档；.md 档只出数不标）
  812  thincoder-core/agent-tools/batch.mjs  · 越 800 硬限（必须拆）
  520  thincoder-core/doc-check/index.mjs  · 越 500 软线（主动审视）
  301  thincoder-desktop/renderer/mount-composer.mjs
  合计 3 档（越硬限 1 · 越软线 1 · 未越线 1）
```

返回对象新增 `lineReads: [{ file, lines, tier }]`，`tier ∈ "hard" | "soft" | null`；`hits` 形状零改。

**5. 报错面（fail-closed，不静默）。**

`lines` 非数组 ⇒ 报错；空数组 ∥ 全空白元素 ⇒ 报错（清单不指任何档 = 什么都没量）；条目非字符串 ⇒ 报错点名下标；条目不在盘 ∥ 读不到 ⇒ 报错点名该档、整次零读数。

`lines` 的校验与 `docs` 的入参错误走同一条抛错通道：抛 `Error`，串首 `doc_check: `，点名该档 ∥ 该下标；调用方见 `Error: doc_check: …` 且 `ok: false`，整次零读数、不产报面（抛点住 `thincoder-core/doc-check/index.mjs`，`thincoder-core/agent/dispatch-run.mjs` 把抛错转成 `Error: <message>`）。

`mode:"gate"` 且给了 `lines` ⇒ 同一条抛错在开判之前拒绝（读数不是判据，gate 面不接），该次零判定、**不产 `DOC-CHECK GATE:` 首行**；gate 判据集与首行零改动由回归判（同一清单去掉 `lines` 再跑，与改前逐字相等）。**不静默忽略**——静默忽略会让调用方以为量过（业务门纪律：该失败就失败）。

**6. 常量面 4 → 6 键。**

`DOC_CHECK_BUILTINS` 增 `fileSoftMax` / `fileHardMax` 两键；D3 要求计数与键数同改：同档 §7「F2 常量面」表 4 行 → 6 行、计数句改 `计数 = 表行数 = **6**`。
