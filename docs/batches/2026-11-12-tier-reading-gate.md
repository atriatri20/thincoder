**为什么判域是全部、不是只有越线的**：用户原话「要要求它的输出里包含**每个代码文件**的原始行数」；`docs/core/standards/METHODOLOGY.md` F-R24a 的判域原文也是「本批将改的源 / 测试文件，**逐档报出该档的原始行数**」。收窄成「只报越线的」＝把用户的话改小，且倒因为果——**越没越线正是量了才知道的事**；只判越线的档，等于让 480 行那一档永远不必量，而它正是下一批越线的那一档。

**为什么比对目标是基线、不是收口时的盘上长度**：`docs/core/standards/CODE-TIER.md` §2 ① 定「**基准 = 改代码前的长度**：判本批改动**之前**该档的读数。不是改动之后的行数」；F-R24a 定「只报一个数——设计时量到的那一次读数」。本批实施就是要改长度，拿改后长度去比，每个改过码档的批都被自己拒（本批自身即反证，见「四」的两列读数）。

**A6 的三支**：

- **① 快照挂得上**：建档后 `refs/thincoder/baseline/<批档名>` 存在，`git rev-parse` 解出的提交里，`git ls-tree -r --name-only <sha>` 含建档时在盘、尚未跟踪的码档。可指名的物 = `thincoder-core/agent-tools/batch-tier-gate.mjs`；今天 `git show a3daddd8:<该档>` 报 `exists on disk, but not in`，正是反面对照。
- **② 基线读不到即拒**：门取内容的路径只有一条 = §1 记入行的 sha（ref 的职责是让那个对象活着，不是取内容的入口——设计档 §8「取内容照旧走 `git show <批起 sha>:<档>`」）。该 sha 读不到 ⇒ `baseTextOf` 返 `undefined` ⇒ 整批一条「批起基线不可判」拒，不逐档比、不静默退回头。
- **③ 存量批照旧**：无该 ref（记入行的 sha = HEAD）⇒ 走 sha 直读，行为与今天一致——已跟踪档比数，未跟踪档只认 `新`。本批自身即此形。

**A6 红侧怎么造**：

- ① 的正侧 = 建档后 ref 在、树里有未跟踪码档。红侧 = **该有 ref 却没有**：`git update-ref -d refs/thincoder/baseline/<批档名>` 后重跑，① 红——它判的是建档侧建没建这个 ref，删掉即红。
- ① 与 ② 各验各的：删 ref 不让门改判（门不判 ref，拒因单源在 ②），所以 ① 的红绿看 ref 在不在，不看拒文。
- 拿「从没建过 ref 的存量批」当红侧，走的是 ③ 那条路径，照样绿，验的是空。
- ② 的红侧 = sha 读不到 ⇒ 拒文含「批起基线不可判」；改前同一输入不被拒（今天门里没有这条支）。
- ③ 的红侧由 ② 那支承担：它是放行支，改前同样放行。

**A6 的实施面**（本批须一并落，否则 ①② 无从变绿）：

- 设计档 §8 的「快照怎么取」与「快照对象必须挂 ref」两条，今天仓内零落地代码。
