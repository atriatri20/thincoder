## 机制设计（三条的答案）

- **D10**：**部分可机判**，答案分三类写死（见 D10 细则表）。① 台账行号 = 可机判（抽取面 = 围栏外 ∧ 行内 code span 外），但**先清后立**——交付物面现盘非零，立了就全红，判据会被当噪声忽略；本批只立判据、不落引擎。② 批档路径 = 与 **D4 细则二**同源（规范档禁引批档），判据不另立语义（D2），形态判法 = 「具体名（无 `*`、无 `<…>` 占位段）∧ 在盘命中 ⇒ 引用」。③ 批档 `§N` = 与②同一 token 一并判；裸「批档 §N」不判。
  **示形处置（任务书点名的难点）**：抽取面与锚判同源——围栏块整块跳过、可执行行整行跳过、行内 code span 先剥。三门之后夹具形 `ledger:"#999999"` 落不进判面；**判不出是可接受的结果，判错不是**（假阳会拦一次合法收口）。
  **判域**：规范档（`docs/**/requirements/**` · `docs/**/design/**`）∪ 签字件（`test/RTM.md` 类）；**排除 `docs/batches/**`**（批档引批档不管——同寿命）。

- **D11**：声明面四步 = 逐字判据句 → 编号与闭枚举形 → 代码符号名 → 逐命中归四类（声明 / 引用 / 记录 / 参照历史）。**与实际不符时的处置**：只命中一处 ⇒ 先认定「串太窄」而不是「只有一处」，换同义词 / 语言 / 符号名重扫；真只有一处才写「声明面 = 一处」，并记下扫过的串。**分写权**：同轮 = 同批，各写域各落，落不完上抛。

- **D12**：三态**定形**（`改前 <量>（<量法> · <日期>）` ∥ `目标：<量>` ∥ `当刻 <量>（<量法> · <日期>）`）。机检能管的那半 = **形**（前缀 / 量法 / 日期在不在、状态档有没有裸绝对值）；管不了的那半 = **数对不对**（要跑，还要判量法能不能复现）⇒ 归判读。落点 = 状态档只携关系式，绝对值住批档 §5 与命令输出——**本段自身的读数即按此落**。
