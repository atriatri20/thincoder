### 最小形（防止被做成一套体系）

- **锁不删**：`session.lock` 仍在，但它退化成**同实例内的自卫**（每份 profile 一把）——即「我这一个实例不会同时开两个浏览器」，而不是「全机只能有一个实例用浏览器」。
- **旧的跨实例拒文不再出现**：`browser profile in use by another ThinCoder instance (pid N)` 在新键下**只会在同一份 profile 被同实例重复拿时触发**。

### 键的候选与取舍（设计席定，父侧只给约束）

| 候选 | 是否满足「跨重启留登录」 | 是否满足「多开」 |
|---|---|---|
| 进程 pid | ❌ 每次起进程换键 = 每次重登 | ✅ |
| 端名（cli ∥ vsc ∥ desktop） | ✅ 稳定 | ✅ 跨端；同端两个实例仍撞 |
| 端名 + 项目根 | ✅ 稳定 | ✅ 不同项目可并行；同端同项目仍撞 |

**判据**：**先满足「跨重启留登录」**（pid 直接出局），再在剩下两个里选能把「同端多开」也解开的那个；**同端同项目仍撞**这一点如果解不掉，就接受，但必须明确报错点名 pid。

## 「为什么不能共享 profile」的实测（父侧 · 2026-11-05 12:23）

用户问：**为啥不能共享 profile？**

**答：不是我们的锁在挡，是 Edge ∥ Chromium 本身单实例。**

**实测（绕过 `session.lock`，只测浏览器层）**：

| 步 | 读数 |
|---|---|
| A 用共享 profile 启动（headless） | **成功**，`port=62215` |
| B 用**同一份** profile 启动 | **失败**：`browser failed to start: DevToolsActivePort not written within 25s` |
| A 的结局 | **仍活着**（未被杀） |

**机制**：`--user-data-dir` 是 Chromium 的**单实例目录**——第二个进程认到同一 profile 后把请求交给已在跑的那一个、自己退出，因此**永远不会写出 `DevToolsActivePort`**，我们的启动等待就超时。

⇒ **我们那把 `session.lock` 不是原因，它只是把同一件事提前变成一句可读的话。**

⇒ 也解释了原始症状的形状：**它本来就是「起不动 + 超时」，不是「EBUSY」**；台账记的 `EBUSY` 是当时的措辞，机制是单实例交接。

### 对设计的影响

- **共享一份 profile 这条路在浏览器层就死了** ⇒ 「多开」只能靠**每实例一份 profile**（即上一条裁定的 A 档），没有第二种做法。
- **锁仍然保留**，但只作同一份 profile 的自卫（同实例重复开）。
- **不必做 broker ∥ 跨进程 CDP 共享**——除非要「多实例共用一个浏览器」，那是另一个需求；本次裁定要的是**各开各的**。

## 终裁：共享一个浏览器 + 首开末关（父侧 · 2026-11-05 12:24）

- **已定决定**：多实例**共用一个浏览器**；**第一个实例要用时拉起、最后一个实例释放时关闭**（引用计数）；**`headless` ∥ 有头由第一个实例决定，后来的实例沿用并被明确告知**；每个实例开**自己的标签页**。 · 用户原话：「共享一个浏览器 + 首开末关（引用计数）：全机登录一次；模式由第一个实例定」 · 时间：2026-11-05 12:24

**这条取代前两条**（12:22「A 各实例独立 profile」与 12:21「不独占、允许多开」）——前两条的方向仍是「允许多开」，**只是载体从「各开一份」改成「共一份、按用者计数」**。**登录态从「按端各存」变成「全机一份」**。

### 为什么要它（三条已知代价，已向用户逐条说明并获接受）

1. **谁拥有**：现在 `close` 杀整棵进程树；共享后必须按**用者计数**决定何时关，否则一个实例关了把别人的一起带走。
2. **空闲关**：现在单会话闲置 15 分钟就关；共享后**必须等所有用者都闲着**才关——一个实例闲不能关掉另一个在用的。
3. **模式**：同一浏览器只有一个 `headless` 值，**后加入者只能沿用**；两个实例要不同模式时，这是共享的硬代价。

### 设计要点（约束，非方案）

- **用者登记**：每实例一条 `{pid, tab 标识}`；**活性按 pid 判**，死进程的条目自动摘掉（沿用「陈旧锁接管」同款判据）。
- **首开的原子性**：两个实例同时发现「无人持有」时，**必须只有一个真的去拉起**——要一条创建式的原子领取，不能「先查后建」。
- **末关**：摘掉自己后计数归零才关；**关之前再核一次活性**（防止计数被死条目撑着）。
- **现有 `session.lock` 的语义要重写**：它今天是「全机互斥」，共享后变成「共享浏览器的持有者登记」，**不再是拒写的理由**。
- **`headless` 沿用**：后加入者拿到实际模式并**在回执里告知**（不得静默）。

**不做**：不做 broker 进程、不做跨实例标签互斥锁（各开各的标签即可）、不做实例名配置项。

### 这条选择的硬后果（已向用户说明，用户仍选此条）

- Chromium 的单实例限制**按 profile**（本席实测：同一 profile 起第二个进程 ⇒ `DevToolsActivePort` 25 s 不落盘）。⇒ **两个池必须各用一份 profile 目录**，否则同池也起不来第二个。
- ⇒ **登录态分成两份**：`headful` 登了，`headless` **不共享**。
