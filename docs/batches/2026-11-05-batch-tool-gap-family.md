## 判据（设计席要落进 §2）

**「单写者」与「可删除」不是一回事。**状态行只能由 `status` 写——这条是对的，不要动；缺的是**在唯一写者之外的清理路径**。同理，「已核销行无回退边」是对的（账要冻结），缺的是**给现役档补挂一行**的动作。

四件的共同形状 = **对称性缺口**：`append` 有的门 `edit` 没有、`status` 能写却没人能清、`create` 能挂行而现役档不能。

## 顺序（有依赖，别并行改）

1. **先对齐三面拒因**（#1）——它改的是门挂点，后三件都要落在同一处。
2. **再补删除路径**（#2）——依赖 #1 改完后的拒因表。
3. **#3 补挂行动作**与 **#4 作者可判**可并行，但都要在 #1 之后——它们涉同一批读写面。

## 边界

- **不动 `status` 的单写者语义**（它是本工具最硬的那条纪律）。
- **不动三段的作者白名单**。
- 与拆档族 `#2067` 同档但不同事：**若两批同一天做，先拆后补**——拆完再补判据，免得判据写在要搬走的半边上。

| # | 内容 | 为什么是 🔴 |

| 1 | §4.21.2 写「可读状态行 = 该段段头区内的**第一行**」，§4.21.4 写「可读状态行的判据 = 段头区内**恰一条**」 | 两种判据在**同一份活输入**上给出相反结论。而 `BR-96` 与 §4.21.2 的正格要求「先 `status`、再 `edit` 删」，§4.12 与 §4.21.4 的反例夹具② 要求「两条以上 ⇒ `status` 拒」 ⇒ **`BR-96` 与正格物理上过不了** |

**裁**：**拆成两个名、各写一次**——

- **受保护行** = 段头区内的**第一个**出现（位置义，`edit` 不许碰的那行）；
- **可读行** = 段头区内**唯一**的那条（计数义，`readBatchStatusLine` ∥ `readSectionStatusWord` 的返回值）。

**并把修复顺序统一成一条**：先 `edit` 删掉多出的那条（区内回到 1 条、通道仍开），**再** `status` 改写余下那条——`BR-96`、§4.21.2 正格、§4.21.4 反例夹具② 三处照这个顺序重写。**这样「`status` 单写者」不变，而两条以上时先删再写，不需要给门开例外。**

**第 2 条**：§4.9 门① 的解析域就地收窄到段头区、把它补进校正清单，并把那份零条档的**改前 ∥ 改后判定**写进 §4.21.4 的代价段（否则「既有面」是一句没核的话，而它背后是一份会冻结的档）。
