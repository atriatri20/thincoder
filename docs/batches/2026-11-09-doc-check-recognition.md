- **识别面**：`DOC_EXTS` 12 项闭集退役，换三个件——`NAME_CH`（Unicode 字母与数字 + 原 ASCII 符号集）· `EXT_PART`（ASCII 点 + 首字符字母 + 长度 1–10）· `DEFAULT_DOC_EXTS`（缺省扩展名清单），外加谓词 `isDocToken`；**边界对 `TOKEN_LEFT_GUARD` ∥ `TOKEN_RIGHT_GUARD` 一并转导出面**。今天 `ANCHOR_RE` 与 `NAME_RE` 是两条各自写的正则（字符类各一份字面、左界各一份，且两处左界本就不同：一个含 `<>`、一个不含），本批收敛成一个定义处；四条抽取式同吃这一组（设计 §2.6 KD-R1）。收敛的一处行为差 = `NAME_RE` 的左界改为含 `<>` 的那一份 ⇒ 名字前紧贴 `<` ∥ `>` 的 token 不再被抽，方向是漏报。
- **候选的两条腿**：**路径形**（含路径分隔符）过形护即是候选，**不看清单**；**裸名**扩展名在清单内才是候选，清单 = `index.docCheckExts`（缺省 `DEFAULT_DOC_EXTS`，并集只增不减）。形护进正则（是「形」，且抽出再丢会动归属窗），清单进谓词（是项目声明，随根变、报面要点名）。
- **为什么代码表达式族进不来**：`JSON.parse` ∥ `console.log` ∥ `process.env` 全是**裸名**，扩展名 `parse` ∥ `log` ∥ `env` 不在清单内 ⇒ 不成为候选。这一条是本轮 🔴① 的落点——改前那版「无 ASCII 点加字母的裸词不构成候选」是**假前提**：`DOC_EXTS` 从来没有这三个后缀，放开扩展名后它们会全部成候选。
- **豁免面**：`index.docCheckExemptions` 一条 = 档 + 判据类 + 命中文本 + 理由 + 复审，**识别键不用行号**；装配处（`runDocCheck`，三条判据跑完之后）按档根分类，未登记进 `hits`（拦），已登记进 `exempted`（不拦、照列）（设计 §2.7 KD-X2 ∥ KD-X4）。
- **排除面不动**：`index.docCheckExcludePaths` 仍是 schema 键、仍缩判集、全排除仍免检放行；本批只**新增** `index.docCheckExemptions`（拦不拦）与 `index.docCheckExts`（裸名扩展名清单）两键（设计 §2.7 KD-X5）。
