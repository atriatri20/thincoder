### 关键决策

**KD-A 索引源 = 文件系统遍历，否决 `git ls-files`**（父侧留我判，判完给理由）

| 面 | 读数 | 判 |
|---|---|---|
| `git ls-files` | 1549 档 | 答的是「跟踪了吗」，不是「在盘吗」 |
| 文件系统遍历 | 1753 档，其中 **240 档在盘未跟踪** | 答的正是「在盘吗」= 既有判据那句 |

两条否决理由，都是可复现的：

1. **索引文件 ≠ 盘**：`git ls-files` 列的是索引，工作树里删掉而尚未暂存的档仍被它列出 ⇒ 假绿；同一份清单里 240 个在盘未跟踪的档它一个不列 ⇒ 假红。判据句是「档在盘」，只有走盘才和它同义。
2. **判据跑在提交之前**：本轮批档 `docs/batches/2026-11-08-pointer-debt.md` 自己就在这 240 个未跟踪档里。若索引吃跟踪面，一个与源码同轮新增、尚未 `git add` 的档，在它被引用时恒判红——门会逼人先提交再改文档，次序反了。

跳过面**各持一张、不合并**：

- 后缀索引自持 `thincoder-core/path-resolve.mjs` 的一处新常量 `SUFFIX_SKIP_DIR_NAMES`（dot 名 ∥ `_archive` ∥ `node_modules` ∥ `dist` ∥ `build` ∥ `coverage` ∥ `obj`）：不跳 `node_modules` 一类，索引面就是整块盘（含全部依赖树）。
- 同名候选那一张（`SAME_NAME_SKIP` = `"_archive"` + dot 名）**一字不动 ⇒ 既有 `档缺` 报文的「盘上同名」列零变**：`dist` 下那份也是「盘上有这个名」，提示面要如实说。
- 「单源」管的是同一件事不要两处描述；这两处判据不同（KD-B），本就不是同一件事。
- **不含 `bin`**：`bin/thincoder.cjs` 与 `thincoder-cli/bin/thincoder.cjs` 都在盘且是指针的合法目标，把 `bin` 放进表里的后果是这两个 token 恒零后缀命中、被判成真死。

**KD-B 后缀索引与 `sameName` 是两张表，不合并**

硬理由 = **界不同，而且不能放宽**：`sameName` 每根封顶 `SAME_NAME_MAX_HITS` = 20 个命中、每根深 ≤3；复用它当判定面，第 21 个同名档会被藏起来、两名判成假唯一——而本步的判据恰是「全树恰一」。一条界不能既当提示又当判定。

**两张表各走一遍树是有意的，不是未评估**：同名索引按三层基根各自起算（含 `bases` / `scanBases`，可能有项目根之外的根），后缀索引按项目根全树一遍；共用要先裁两套不同的根集与深度帽，且同名索引只在 `dangling` 路径上跑、后缀索引惰性建——常见路径上省不到开销。

**KD-C ≥2 落 `dangling`，不落 `ambiguous`**

锚面四类命中（`档缺` / `节缺` / `引缺` / `环引`）与两个 verdict 词不动。多名裸名今天就是 `档缺` + 同名候选，≥2 分支落回同一形 = 报文零变；新造 `ambiguous` 会给锚面加第五类与第三个词。

**KD-D 只在文档锚面开**（`opts.suffixFallback`，缺省 `false`）

其余六面（批档读面 ∥ 评审 `documents` ∥ 台账 `cwd` …）的受理判据是各自写死的，后缀兜底会放宽它们的受理面。与 `declaredRepos` 同形：只有文档锚面传。

**KD-E 索引域 = 项目根，不含声明仓根**

声明表是跨仓的唯一入口（设计档 §2.7）。索引若覆盖声明仓根，后缀兜底就成了第二个入口——未声明的跨仓命中会转绿。
