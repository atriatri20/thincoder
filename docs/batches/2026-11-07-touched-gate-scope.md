### 需求：批档机检门的「触达账」改判改动区（不是整档）

**现场**（2026-11-07 11:05 实撞，`docs/batches/2026-11-07-tool-face-review-route.md` 修正轮）：

某批先改设计档、再写批档 `§2`——**设计档一进「本 run 已触达」集，此后每次 `batch edit` 全被拒**。拒文形如：命中 137 条 · 「触达账（锚 137 条）」· 逐条列为 `锚·档缺`。

**那 137 条全是存量**（其中 118 条已裁归 `#2077`）。同一份批档单独送门是 `PASS`。

**⇒ 挡住写入的不是本轮的笔，是别人的债。**而且这条禁令没写在任何地方——它把「先改设计档、后写批档」这个常规顺序变成了硬顺序，顺序错了只能另起一次 spawn 重来。

### 父侧裁定（2026-11-07 11:12）

- **已定决定**：触达账只判**本次改动区**，不判整档；存量债在收口门判。 · 用户原话：「你为什么没治？」 · 时间：2026-11-07 11:11

**判据（先例为准，不新发明）**：`docs/core/design/DOC-DISCIPLINE.md` §3.26 条目 Z 的写前门已定同一口径——「写前门判的**不是整档**，也不是「新写进去的那几个字」，是**本笔触碰到的那个段落**，整段入判」。用户的原始动因是「一句接一句的问题其实也是可以在写的时候检查的啊！」。

**⇒ 同一个关切，两个门两个口径**：写前门判区域，批档触达账判整档。**分工本该是**：轮内写判改动区（别把自己新写坏）· 收口判整档（交付门已经这么判）。

**轮内判整档 = 把收口门提前到每一次写**，而被判的存量债不属于这一轮。

### 边界

- **不放松收口门**：`gate` ∥ `close` 对整档的判据一字不动。
- **不取消触达账**：它仍要保证「本轮新写进去的字是干净的」。
- **不动写前门**：它的区域判已经是准的，不因为本批而改。

### 验收

1. 造最小复现：目标档**带 1 条存量锚债** + 改它 + 再写同一批的 `§2` ⇒ **写入成功**（今天这条路径是失败）。
2. 同一次改动里**新写坏一处**（自己制造的锚缺）⇒ **仍被拒**（改动区判据没有失效）。
3. 收口时该档**整档仍判**（存量债照旧拦收口，交付门不变）。
4. 落点 = `thincoder-core/agent-tools/batch-gate.mjs` 的触达账判面。

### 第二件（同批并入）：围栏内行号坐标豁免（`覆盖账 = #2121 ∥ #2122`）

- **已定决定**：围栏内的行号坐标不判；围栏外照判。 · 用户原话：「这条要改，围栏内要豁免行号坐标。」 · 时间：2026-11-07 11:13

| 件 | 判面问题 |
|---|---|

### 现场（2026-11-07 11:13 实撞，就在本档）

本档 §1 第一次 append 被拒，逐字：`DOC-CHECK GATE: REFUSED（命中 1 条——本次写入文本（1 处行号坐标））`。

**被拒的是什么**：我逐字引用了批档机检门**自己的拒文**——那段拒文里带着一处「档路径 + 冒号 + 数字」形。

**⇒ 引用一条真实读数，就不可能通过这道门。**要么篡改原文，要么写不进去——**判据与「读数照原文引」这条记录纪律直接打架**。

### 为什么该豁免（判据）

**行号坐标的害处是「它会漂」**——所以它不能当指针用。但**围栏里的东西是逐字证据**：日志 / 拒文 / diff / 前后对照，**它是某个时刻的快照，本来就不跟着盘面走**。

**⇒ 它不是指针，是证据。**对证据判「你写的行号对不上今天的盘面」，等于要求引用时改写原文。

### 边界（不许扩大）

- **围栏外照判**——现行判据一字不变。
- **围栏块是整块免判区**：锚 ∥ 引文 ∥ 行号坐标 ∥ 段长**四类同免**——**这是锚面一直以来的行为**（`thincoder-core/doc-check/anchors.mjs` 的「围栏块整块跳过」），**本批只让坐标面跟上它**。原写「只免行号坐标、其余照判」是写反了，2026-11-07 12:26 改正。
- **不是「围栏里可以随便写」**：围栏外的指针仍然一条也不许带行号。

### 验收

1. 围栏内写一处「档路径 + 冒号 + 数字」⇒ **不再拒**（本档 §1 那次 append 即为现成复现）。
2. **围栏外**同一形 ⇒ **仍拒**（判据没被削弱）。
3. 围栏块内一处 `档缺` ⇒ **照旧 `0 条`**（锚面从未判围栏内，本批零改）；**围栏外**同一形 ⇒ **仍拒**（判面没被放宽）。
4. 声明面同拍：`thincoder-core/tool-docs/doc_check.md` 那句「Fenced blocks count too …」必须与本改动**同一轮**改掉（现在它写的是「围栏不豁免」）。

### 一条判据线（两件共用的裁定口径）

**门的判面划在「今天的读者会拿它去盘上找东西」的那部分内容上。**两句派生：

- **`#2121`**：别轮写进去的字不是这一笔的东西——读者撞上坏字时，那不是本笔留下的 ⇒ 轮内只判本笔改动区，存量归收口面。
- **`#2122`**：围栏内的坐标是**它引的那份原文里的位置**（跟着原文走，快照证据），读者不拿它去找今天的盘面 ⇒ 不判；围栏外的坐标是**指向今天的指针** ⇒ 照判。

**射程（一句话）**：围栏块**整块免判**（档名 ∥ 锚 ∥ 引文 ∥ 坐标 ∥ 段长同免），围栏外照判、一条不放宽——理由 = 围栏里是**逐字证据**，钉的是被引的那份原文，不随盘面漂。锚 ∥ 段两条本来就是这个行为，本批只让坐标面跟上它们，不改那两条一字。

**实现面不共用代码**：两件判面各自独立（一件在批档门、一件在引擎）；共用的只有这条裁定口径与评审面——两件合批的理由是「同一个面」，不是「同一段代码」。

### 机制设计

**判面句（一句话）**：`writer` 面（写段面）的触达账腿，判的是**写者本 run 写进那一档的那些字**（扩到段落为止），不是整档；整档累积的存量债留给收口面。

**改动区怎么取（四态判定 · 判据单源 = `docs/core/design/DOC-DISCIPLINE.md` §3.20「改动区取法（基线两级 · 四态判定）」）**：

1. 批档 §1 有 `批起 sha = <sha>` 行 ⇒ 基线 = 该 sha。取法单源 = `docs/core/design/DOC-DISCIPLINE.md` §3.20「② 的范围」下的「`<批起 sha>` 的取法（唯一）」条，收口面已在用同一条腿。**实现侧符号名 `baseShaOf` = `unverified`**（本席审查面内未核到该名字；实施轮首动作实读 `thincoder-core/agent-tools/batch-gate.mjs` 定名，本设计不押该名）。
2. 无该行 ⇒ 基线 = `HEAD`（写工具不提交 ⇒ 本 run 的文档笔迹默认在工作树里未提交）。
3. **四态判定**——先问「在不在 git 仓」、再问「该档在不在跟踪面」，两问都「在」才用得上基线：

| 态 | 条件 | 改动区 |
|---|---|---|
| ① | git 仓 ∧ 该档在跟踪面 ∧ 基线可解析 | 按改动区判 |
| ② | git 仓 ∧ 该档**不在**跟踪面 | **整档**——写工具不提交，未跟踪的 `.md` 只可能是本轮新建的档，整本即本轮的笔（与批档自身同一条理由） |
| ③ | git 仓 ∧ 该档在跟踪面 ∧ 基线不可解析 | **未定**——例：只 `git add` 过、仓内零提交，`HEAD` 不可解析 |
| ④ | **非** git 仓 | **未定**——仓外没有跟踪面，一档一档当整档判正是本批要治的病 |

4. **③ ④ 同一支的处置**：零强制 + 回执明示「触达账改动区未定——只明示、不阻本次写；收口面整档判」，由收口面整档判兜底。**降级方向 = 不阻写，不是判整档**。

**场景出处**：四态各有一条实撞场景与一条可跑用例，单源 = 设计档同块的「场景出处」段 ∥ 用例表 DD-218 四态（本处不复制）。

每档一次 `git diff -U0 <基线> -- <该档>`，解析 `@@ -a,b +c,d @@` 得**改后行号区间表**（不是单区——一次改动可以有多段）。

**扩区单源（D2）**：区间表交给 §3.26 的扩区表扩成片段区——段落整段 ∥ 与围栏块相交则整块连标记行 ∥ 只动空行时并入紧邻两段。实现 = 由 `thincoder-core/tools/doc-write-gate.mjs` 导出（现为同档私有），批档门只调用、不复制一张类名表。「什么叫一段」仍只有一个出处（`thincoder-core/doc-check/paragraph.mjs` 的谓词族）。

**命中分流（`writer` 面触达账腿）**：

- 命中行落在扩区后的改动区内 ⇒ 进**强制集**，当场拒（R2）。
- 落在改动区外 ⇒ 进**明示集**：回执只出一行计数，逐字 `触达账存量命中 N 条——不属本次改动区，不阻本次写；收口面整档判`。**N 是唯一变量，行是固定字面**——判据面不留可扩展形，实施席照这一句写断言。**不逐条列**（137 条逐条列正是本批要消的现场）；收口面照旧逐条列。
- 批档自身（或其 `edit` 视图）的判法**不动**：批档生于此轮、档内没有别轮存量可排——该裁定与理由仍住 §3.20，本批不改。

**回执与首行（机器可见契约）**：拒写首行按腿分列，第三段标签 = `触达账改动区（锚 N 条）`；前两段（本次写入文本 ∥ 批档整档）字面不变。实施席按这三段写单元用例。

**新对外串三问（三个串各答一次，答完再谈新造）**：

- `触达账改动区`——`existing but unusable` · 现名 = `触达账（锚 N 条）`（`thincoder-core/agent-tools/batch-gate.mjs` 拒写首行第三段）· 不可用的理由 = 该段原判整档，沿用旧字面会让回执照旧读成「整档已判」，与改动区判面读成两件事。消费面 = 拒写首行 ∥ 实施席用例断言。
- `触达账存量命中 N 条`——`none found:`（查过面 = `thincoder-core/agent-tools/**` ∥ `thincoder-core/tool-docs/**` ∥ `docs/core/**`，现盘无同义行）· 语义承接既有「只入回执、不阻写」的明示族，不新起一族。
- `围栏内行号坐标 N 处`——`none found:`（同三面）· 句形对齐 `docs/core/design/DOC-DISCIPLINE.md` §3.23 既有清单块（量法行 ∥ 零态行同一族）。

**边界（不做）**：不做「存量债豁免清单」；不改 `thincoder-core/doc-check/**` 的判据本体（阈值 ∥ 三支判据零改）；不改收口面范围与 `ERROR` 消费（fail-closed 照旧）；不改写前门（§3.26）的判面与挂点。

**最近先例（对齐 ∥ 偏离）**：先例 = `docs/core/design/DOC-DISCIPLINE.md` §3.26 条目 Z 的写前门（判本笔触碰的段落）。**对齐** = 同一个「改动区 + 扩区」判面、同一张扩区表、同一个段落谓词单源。**偏离** = 写前门在落盘前判（零字节），本腿在批档写时判已落盘的档——所以基线只能取自 git，不能取「盘上旧档 vs 本次新内容」（那一份旧内容在这里已不存在）。

**公共源勘察证据行**：`PROJECT-MANIFEST.json` 的 `index.publicRepos` = `[]`（本席实读）⇒ 已查，工作目录内无独立公共文档仓、无相关公共源可引。

**数据事实核对**：本设计对数据面只作一条断言——「存量命中条数随档走、与本轮无关」。该断言由 §1 的实撞现场承载（一次拒文点名 137 条、同一档单独送门 `PASS`），不需要另读数据；其余判断全部由代码与文档落定 ⇒ 无待读数据项。
