### 现状：设计说照判，实况是拒

**设计已定（`F17` ∥ 设计 §2.1–§2.4）**：

```
声明根 = 调用方给的坐标系（target ∥ 会话锚）
普通目录 ∥ 多项目工作区 都能当声明根 ⇒ 照它判
```

**盘上实况（父侧本进程实测，2026-11-07 17:07）**：

| 调用 | 结果 |
|---|---|
| `{mode:"gate", docs:[…]}`（不给 `target`） | `DOC-CHECK GATE: ERROR（多项目工作区：请指名 target）` |
| `{mode:"report", docs:[…]}`（不给 `target`） | `doc_check: D:\teamcode is a workspace holding 2 projects — pass the project root explicitly via target` |
| `{…, target:"D:\\teamcode\\thincoder"}` | **正常判**（`PASS` 或 `REFUSED` + 逐条命中） |

**⇒ 两种模式都走进了「调用方给了 `target`」那个分支**，而两个分支的守卫都是 `args?.target !== undefined`。**调用方并没有给。**

**父侧撤回过一次自己的推断**：先判「旧模块在跑」，复验后不成立——**这一条记在此处，是因为它说明「推断不成立时立刻撤回」比「保住一个能自圆其说的解释」重要**。

### 两处待查（不预设结论）

**① `target` 从哪来**：是否由运行时按「项目状态 = 工作区」注入。**判法** = 追调用链，找出注入点或证明无注入（无注入则另有分支）。

**② 域表凭什么只读一个根**：`thincoder-core/doc-check/anchors.mjs` 的 `docRootBaseKeys(root)` 调 `readManifest(root)`，读不到就返回空集；`batchDocBases` 同式。**⇒ 判定是「每档一根」，域表却仍是「一个根」。**
**这不是同一批的遗漏吗**：`#2141` 那批把判定改成逐档定根，域表面没跟——**要判它是「本可一起做而漏了」还是「域表本就该按声明根读一次」**。**判据在 `§2` 给，不在此处定。**

### 已定决定

- **已定决定**：域表按各档自身项目根读（甲案）——与判定同一条规则，一次调用可读多份 manifest；**不是**「按声明根读一次、工作区下空集降级」。 · 用户原话：「**甲**」 · 时间：2026-11-07 17:10
- **推论（供设计席采纳，不是裁定）**：既然域表也按各档自身项目根读，「一个 `target` 覆盖整批」在两处同时被否——**工作区锚就更没有理由被拒**：它的每一档都有自己的项目根，域表也各有其主，**声明根本身是不是项目，从头到尾不参与判断**。

### 病因更正（父侧 17:16 实测，推翻 §1 前面两版判断）

**同一份档、同一组参数，在两个进程里结果不同**：

| 调用 | 本会话工具面 | 新进程（直调 `thincoder-core/agent-tools/doc-check.mjs`） |
|---|---|---|
| 不传 `target`（锚 = 工作区） | `ERROR（多项目工作区…）` | **`PASS`** |
| `target: null` | `ERROR` | **`ERROR`** |
| `target: ""` | `ERROR` | **`PASS`** |

**⇒ 两件事同时成立，不能混成一件**：

1. **「恒拒」的主因 = 会话进程里跑的是旧模块**。**盘上这份码，不传 `target` 是 `PASS` 的**——即「工作区锚照判」这半已经在盘上成立。
2. **盘上仍有一个真 bug**：`target: null` 被当成「调用方给了 target」（守卫写的是 `args?.target !== undefined`，而 `null !== undefined` 为真）。
3. **`target: ""` 在盘上走不到那分支**：`resolvePathTarget` 对空串返回 `dangling`，不是 `ambiguous`——**故本会话观察到的「三形同报」是旧模块的形，不是盘上逻辑**。

**父侧两次判断都错过，逐条记下（不为免责，为下一个人少走这趟）**：

- **第一次**判「旧模块」——**对**，但当时没有证据，只是推断；
- **随后撤回**、改判「运行时注入」——**错**：全树 `grep` 无注入点；
- **再改判**「守卫写松」——**部分对**（`null` 那形确是真 bug），但**把 `""` 也并进来是错的**，因为那是旧模块的读数。

**⇒ 教训一条**：**同一现象在两个载体（本会话 ∥ 盘上）里表现不同时，先分清载体，再谈成因。** 父侧三次都在「一个载体上量、在另一个载体上解释」。
