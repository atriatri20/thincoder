## 讨论记录

### 缘起（用户 2026-11-05 16:01，逐字）

> 「对了，我倒是不觉得需要阔射程，但是我希望改成拦，在写入检查时就拦，这样干脆不让他落进档。」

**这句话是对我三个选项的回答**：我给的是 A（扩射程 + 拦）∥ B（扩射程，仍只报）∥ C（不动）。用户选了**第四种**——**射程不动，把效力从「只报」改成「写入面拦」**。

### 现场（同一晚 39 分钟内的实证）

| 时刻 | 事 |
|---|---|
| 15:20 | 设计档写「`1. **Requirements**` 为**第 49 行**」 |
| 15:57 | 实施席在该节上方插入 13 行 |
| 15:57 | 盘上变成**第 62 行**——**而判据（「在 `1. **Requirements**` 之前」）照样成立** |

**⇒ 只有那句读数成了谎，且失效是静默的**：没人会为了核对一个行号去数一遍。

### 现状实读（`docs/core/design/DOC-DISCIPLINE.md` §3.23 条目 W）

- 抽取式 = **一个档名之后出现的冒号加数字**；三形（紧贴 ∥ 承名 ∥ 段落承名）只分档名从哪儿来。
- 效力 = **清点，不是判据**：不产 verdict、不进 `gate`、不计入 `hits`、**不阻断任何写入**；采集器**只在 `report` 分支被调用**（结构兜底，原文写着「清单构造上挡不了人」）。

**⇒ 所以这一批要动的不是抽取式，是那条结构兜底。**

### 已定决定

- **已定决定**：行号坐标在**写入面**即拒（判本次写入文本，不判存量）；抽取式**不扩**（中文「第 N 行」不进抽取面）。· 用户原话：「我倒是不觉得需要阔射程，但是我希望改成拦，在写入检查时就拦，这样干脆不让他落进档。」 · 时间：2026-11-05 16:01

### 父侧必须说清的一件事（诚实告知，不是追问）

**抽取式不扩 ⇒ 今晚这种写法「第 48 行」仍然拦不住。**

它没有档名紧跟冒号，走不到抽取面。**所以这一批挡住的是「档名 + 冒号 + 数字」这一形，不是中文「第 N 行」那一形。**

用户的选择我照办；但这条边界必须写进需求（§13.27 边界第 3 条），否则下一个人会以为从此中文行号也进不来了。

### 附带一条实证（本段自己撞的）

本节第一稿里我用了一个「某档 + 冒号 + 数字」做示例，**被写入面的文档机检当场拒写**（判为档缺死锚）。

**⇒ 这恰好说明这条机制是通的**——只是它现在判的是「档在不在盘」，不是「这是不是行号坐标」。本批要加的正是后一条。

### 批次边界

- **不追存量**（`#2077` 那批另算，本批零触）。
- **不改** §3.23 的两条 gate 判据（锚 ∥ 段落长度）。

### 设计席要回答的三个问题（不要扩面）

1. **拦在哪一层**：`doc_check` 的 gate 分支加一条判据，还是写入面（`batch-record-write.mjs`）单独判？两者判的对象不同——gate 判整档、写入面判本次文本。**用户要的是「写入检查时」，边界 = 本笔新增**。
2. **怎么不误伤**：存量行号（`#2077` 那 40 处）绝不能因为这一条把所在档判成改不动。今晚 `docs/TODO.md` 已经演过一次这种事故。
3. **拒文说什么**：要能让人一眼改对（点名那个坐标 + 给出替代形：节号 ∥ 符号名 ∥ 逐字引文）。
