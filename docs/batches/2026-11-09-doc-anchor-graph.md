#### ① 宽度上限 `LAYER_CAP = 200` + 紧跟自述行

- 某层边数超 200 ⇒ 取排序后前 200 条打印，紧接该层末行印：`本层并列 M 条，此处印前 200 条；收窄办法 = kind=<取值>（第 n 跳）`。
- `M` = 该层**真实**条数，不是印出来的条数。
- **哪一层截就在哪一层说**：自述行跟在该层边行之后、下一层 `第 n 跳` 之前。不许静默截，也不许只在末尾总说一句。
- 深度截断行照旧（`已截断（depth = N）：k 个节点未展开`）。两种截断各印各的，不合并成一行。
- 自述行点名的 `kind` 必须是闭集内、且该层真实有的那几类（点名闭集外的值 = 把读者送进拒文）。一层里闭集内一个都没有 ⇒ 改印 `本层无可收窄的 kind（截断部分只有投影类边）`。
- 算完成：本仓跑 `req:F16`/`depth` 6，凡超限层各印前 200 条 + 一行自述，且 `M` 与库内该层条数一致。

#### ② 同层排序补成全序

- 盘上现状：`doc-graph.mjs` 的 `chainOf` 里 `layer.sort(...)` 已按 `dst` → `kind` 排，**这两条键不用重写**。
- 缺的是同 `dst` 同 `kind` 时的第三、第四键。不加，前 200 条就落在库内行序上，「同一跑两次相同」只是碰巧成立。
- 补到 `dst` → `kind` → `src` → `evidence`，使排序与输入顺序无关。
- 算完成两条：① 同一 `chain` 调用连跑两次，第 1 跳前 200 条边行**逐字节相等**；② 单测里构造三条同 `dst` 同 `kind`、`src` 不同的边，输出序按 `src` 字典序。

#### ③ `chain` 的 `kind` 收窄入参

- 三个读动作（`forward` ∥ `reverse` ∥ `chain`）的可选入参：逗号分隔的子集，闭集 = 设计 §2.2 六类（`cites` ∥ `cites-req` ∥ `mentions-case` ∥ `case-file` ∥ `cites-symbol` ∥ `imports`）。
- 作用点 = 读出的那一批边：**先滤 → 再排序 → 再分层 → 再按上限印**。收窄后那一跑是完整的一跑，不是「大回执里抽了几行」。
- 缺席 = 六类全收，且首行恒印本次生效的集合——缺席的含义印出来，不靠记。
- 闭集外的值 ⇒ 拒并点名那个值（形如 `doc_graph：kind 非法（"mentions"）——取值 ∈ {…}`）。**不许静默当空集**，不许回「该节点没有边」。
- `forward` ∥ `reverse` **不设上限**：单节点直查的条数由首行印出，截它等于不回答；嫌多由 `kind` 收窄。

#### ④ 判据同步（这条不同步，上面三条落完也是白落）

- **AC-1（设计 §5 首行）＝两半**：走查面判第 1 跳与每条自述行（该层只印 200 条 ∥ `M` 大于印出条数 ∥ 上限 200 ∥ 点名的 `kind` 在闭集内）；五跳面由无上限的 `forward` ∥ `reverse` 逐条直查。
- **为什么不是「收窄重跑再判」**：枢纽节点上任何保住通路的收窄都压不到上限内（实读见 §5 的「已知限界」），拿它当判据等于给判据留一个永远判不了绿的格子。
