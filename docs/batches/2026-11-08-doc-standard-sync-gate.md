### 这批要治的到底是什么

**不是「有人写裸名」，是「规范要求一件门禁不判的事」。**

查一下事实就好懂：`docs/core/design/DOC-DISCIPLINE.md` 的 D4 条写着「**书写只有一个答案：全路径。**」，而门禁（`doc-check` 文档锚面）判的是另一件事——读者顺着这个 token 能不能解到盘上那一件。第 6′ 步唯一后缀兜底（提交 `506c5415`）让「全仓恰一件同名」的裸名判绿，于是：

```
全仓 4464 条锚里，3156 条按包内相对写、且唯一可定位 ⇒ 门禁判绿
D4 却要求它们全部写成全路径        ⇒ 规范判不合规
```

**两边都自认为对，而没有人能说清哪边算数。**`pointer-residue` 那十本批档就是为补这个分叉开的——每来一批要管书写形，就得自造一把扫描器。**这是分叉的固定成本，且每把尺都会漂**（`-c` 那本里漂了两次：花括号看不见、桶归属写错）。

**消掉分叉，这批补丁就不必再存在。**

### 为什么不反过来（把门禁提到全路径）

用户的裁是「标准降下来」，不是「门禁升上去」。而且升上去的代价已经量过：3156 条红，其中绝大多数是**合法的包内相对写法**（同一包内部互相引用，本来就没有歧义）。一律判红会让检查天天误报，最后没人跑它——**保护的宽度归零，比不保护更糟。**

**② ③ 块 · 两段替换文（逐字）**：其中「裸名只在『该名全仓恰一处』时解得到」是**性质说明**，不是第二份规格——四条腿与判法单源仍是 §4.2.2，这句只交代「靠的是当下盘面」。

```text
**书写只有一个答案：解得到。** ① 与 ② 解释的是**机检行为**（同目录裸名能过、跨目录裸名只在能唯一定位时才过——判法见 §4.2.2）。③ 给的是**书写规范**：**写法不限，解不出就是错的**——读者顺着这个 token 解不到盘上那一件，那一处就没写完。仓根路径恒可解；裸名只在「该名全仓恰一处」时解得到，而那靠的是当下盘面，不是写法本身。**同名多份的位置必须写出能区分的形**（带目录段 ∥ 带层前缀）——那里谁都无法判断你指哪一件，机器也给不出唯一答案。
```

```text
**这条底线是「今天解得出」，不是「永远解得出」。** 全仓恰一件同名时裸名判绿；同一天第二件同名档上盘，那一处裸名当日转红。这不是缺陷，是这条判据的已知性质——遇到时按上一条改成可区分的形即可，不必去找门禁的 bug。
```

**为什么写成「解得到」而不是把要求删空**（§1 指令 ②）：删掉之后读者会问「那我该怎么写」。答案必须留在原位：写法不限，**解不出就是错的**；有同名兄弟的位置，**必须**写出可区分的那一形。这是从「一种写法」改成「一条底线」。

**为什么「仓根路径恒可解」要留**：它让底线有一个永远成立的正例。压成「随便写，能解就行」之后，读者遇红时不知道往哪写；给出恒可解的那一形，红转绿的动作是确定的。

### 2.3 判法总则（逐处判的四类 · 不许正则批量替换）

**判域的界 = 这条规则的各写法，不是「全路径」三个字。** 上一版本席把界划在串上，于是同一条规则用「完整路径」写着的四处（D4 纪律行 ∥ D4 细则标题 ∥ 第 ③ 条 ∥ 锚形态规范句）全在表外——改完 `docs/core/design/DOC-DISCIPLINE.md` 会同时说「写法不限」和「书写依据只此一处 = 锚写自仓根完整路径」。这一版把界收回到规则本身：**两族串并联扫描 + 评审点名补漏**（量法与族界见 §2.5）。

判的对象是**这句话在干什么**，不是它含不含「全路径」三个字。四类，各有处置：

| 类 | 判据 | 处置 |
|---|---|---|
| **异义句** | 那个「全路径」说的是别的事（cwd 全路径 ∥ 全路径头 ∥ host 装配全路径 ∥ 全路径段标记 ∥ 按名寻址的全路径） | **零触**。改它即把一句对的话改成错的话 |
| **机制描述句** | 说的是机器/解析序在干什么（「解析序 ① = 仓根相对全路径」「零命中 ⇒ 档缺」） | **照实装判**。实装未变 ⇒ 零触；与实装不符才改（本批只认实读） |
| **要求句** | 命令读者怎么写（「一律写全路径」「必须写仓根完整路径」「须带层别全路径」） | **改写**成 §2.2 那一族（解得到即可；同名多份写可区分形） |
| **判据行 / 用例行** | 断言某写法会被判红或判绿（「本次写入文本含裸档名 ⇒ 拒」「改成全路径 ⇒ 落盘」） | **按新底线重推两侧**：解不到 ⇒ 红；解得到（含裸名唯一同名）⇒ 绿。旧行若断言「裸名一律红」，它断言的是已退役的规则，改 |

**批量替换为什么更坏**（写进本节，供后市引用）：把描述句一并换成「解得到即可」之后，档里就出现一句与实装不符的话——下一轮读者照它判门禁，或照它改代码。**那是把规范文改成假话，比留着原文更坏。** 本批的每一处处置在 §2.5 表里逐行给出，改法与原文片段并列。

### 2.4 关键决策

**KD-1｜标准降、门禁不动。** 反方向（把门禁提到全路径）在本仓的代价是实测的：`docs/core/requirements/DOC-CHECK.md` F3 记「`docs/**` 锚命中里 3156 条仓内唯一可定位」——一律判红即 3156 条误报，检查天天响，最后没人跑它，**保护宽度归零**。用户裁定原文：「就不要强行要求全路径了」「反正门禁和标准要一致」。

**KD-2｜新标准 = 门禁的四条解析腿，一句不多。** 实装实读（`thincoder-core/doc-check/anchors.mjs` 头注与 `resolveDoc`）：① 仓根相对全路径 → ② 引用方档所在目录 → ③ 声明仓腿 → ④ 唯一后缀兜底；四步不中 ⇒ 悬空。故标准句只能写「解得到」，写下任何一条腿的具体次序都是第二份规格，且会随实装漂。

**KD-3｜条目 AA 不撤，只换内容。** AA 治的病是「规则不在落笔的面」（该节成因第 2 条），那个病没消失：新底线同样要在写入面读得到。**覆盖原则（凡写档名的面都有一句可判的要求句）原样保留**，换的是那句要求句的内容。撤掉 AA 等于让新底线只活在设计档一处，回到同一病。

**KD-4｜写入门禁与收口门禁本批零改，故 AC 不建在门上。** 本批改的是文本面。判据只能落在「文本面逐字在册 + 门禁读数不变」两类上——建在门行为上的 AC 本批动不了，写了也是假判据。

**KD-5｜三件事必须同轮（D11）。** 同一条规则活在三层：设计档 D4（语义）、§3.27 AA 与其 A-DD42（覆盖与判据）、写入面九档（模型读到的句子）。任何一层漏改，下一轮就有人按旧句干活。§2.5 与 §2.7 是这三层的逐处清单。

**KD-6｜「今天解得出」这条性质写进规范，不停在批档。** 理由：它是判据的性质，不是本批的过程。不写，下一个人遇到「昨天还绿的今天红了」会当成新 bug 去查门禁；写进去，它就是已知边界，处置动作是确定的（改成可区分形）。

### 2.6 花括号形（`#2191` · 与 C1 同一底线 · **§4 已裁并办**）

**这一节治的不是写法，是「门禁看不见」。** §1 已裁「按并进来出方案，单列一节」。

**现场（逐字引文 · 真实出现三处）**：

- `docs/server/design/webui/CHAT.md` 的「`i18n-{zh,en}-core.mjs` 在盘（键 = 核件原名」——前缀 `i18n-`、组 `zh,en`、后缀 `-core`、扩展名 `.mjs`，正是 `#2191` 那一形。
- `docs/server/design/webui/I18N.md` 的「门面 `i18n-{zh,en}.mjs` 各 +1 import」——组后直接接扩展名。
- `docs/server/design/webui/WEBUI.md` 的「`i18n-{zh,en}-{shell,me,admin,sandbox,system,core,project,ledger,mcp}.mjs`」——两组相套。

**事实（实读）**：抽取式的档 token 字符类只有 `[A-Za-z0-9_.\-]`（坐标 = `thincoder-core/doc-check/anchors.mjs` 的 `ANCHOR_RE` 源串），`{` `,` `}` 都不在类内。依据 `thincoder-core/doc-check/anchors.mjs`「文档指针 = 档 token（含 `.md`，可带目录段）」。

于是这三种形两头都落空：人解不出（一个 token 指两件），正则也匹配不上——`{` 处折断，而末段 `core.mjs` 的左界被 `-` 挡住（`-` 在左界守卫的排除类里）。**它既不红也不绿，它不在判面里。**

**复现（两条读数必须不同，否则说明没测到盲区）**：

```text
① 在系统临时域建夹具档 a.md，正文一行写 引 `i18n-{zh,en}-core.mjs` 一处
② doc_check({mode:"report", docs:[该夹具档]})  ⇒ 该行 0 条锚（今天的状态）
③ 同一行改成两个具体名（i18n-zh-core.mjs ∥ i18n-en-core.mjs），同跑
   ⇒ 各判存在性：不在盘 ⇒ 2 条 `档缺`；在盘 ⇒ 0 条
```

**为什么不能靠「要求大家展开写」**：用户裁定是「不要强行要求全路径」，同一句话也否掉了「强行要求写法」。花括号的正路是**让门禁看见它**，看见之后它自然按「解不出就红」处理——与本批新底线同一条判据，不新增第二条规则。

**设计（KD-7）**：抽取面加一支**花括号组展开**。

- **形**：`<前缀>{<名1>,<名2>[,…]}<后缀>.<扩展名>`——前缀 ∥ 后缀各自匹配 `[A-Za-z0-9_.\-]*`，成员匹配 `[A-Za-z0-9_.\-]+`，扩展名 ∈ `DOC_EXTS`。**嵌套形不匹配**（后缀里再出现 `{`）⇒ 不展开：`docs/server/design/webui/WEBUI.md` 那一处就是嵌套，它今天不入判，明天仍不入判——本支不假装治了它。
- **处置**：展开成 N 个具体档名，**逐名**走同一解析序判存在性（复用锚判现成的解析面，不新增第二套解析）。
- **命中**：每个解不到的展开名出一条 `档缺`，该行点名**原花括号 token** + 缺失的那个展开名（读的人才知道该改哪一行，而不是看到 `i18n-zh-core.mjs` 这个他文档里可能从没写过的名字）。
- **守卫一（组内含 `/` 或 `*` ⇒ 不展开）**：现场 = `docs/core/design/AGENT-LOOP-SUBAGENT.md` 的 `{ running / queued / done }`——那是取值枚举，不是文件名列举；不设这一支会凭空造出三个不存在的名字。
- **守卫二（组内成员 < 2 ⇒ 不展开）**：现场 = `docs/vsc/design/WEBVIEW-PROTOCOL.md` 的 `${count}` 与 `docs/vsc/design/PROJECT-SWITCHER.md` 的 `📁 {name}`——单成员花括号是模板占位。
- **撤掉的那一支（原「后缀不在 `DOC_EXTS` 内」）**：说不出现场——抽取式本来就只认闭集内的扩展名，非闭集后缀连 token 都不成，展开无从触发。**这一支走不到，就删掉**：留一个没人走的守卫，下一次就没人敢动它。

**否掉的替代**：

- **新增命中类**（如 `形缺`）：与 `docs/core/design/DOC-DISCIPLINE.md` §3.20「不新增判据条数、不新增 verdict 词」相抵。先例是 `环引` 并入「锚 N 条」，本支同理，故走 `档缺`。

**carve-out 进 C3（评审 Y8）**：§3.27 的边界句现读「不改 `thincoder-core/doc-check/anchors.mjs` 的判据」、§5 `A-DD42` ⑤ 现读「`thincoder-core/doc-check/**` 本批 `git diff` 空」——本支一开，这两句都成假话。两句改成带 carve-out 的写法：「判据本体（解析序 ∥ 判决词 ∥ 豁免谓词 ∥ 阈值）零改；**花括号组展开是抽取面新加的一支**」。AC-12 判它。
