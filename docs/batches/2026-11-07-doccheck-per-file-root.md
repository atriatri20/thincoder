### 需求：判域按档所属项目根解析（不是整批一个坐标系）

**现场（三症状同源）**

`doc_check` 拿**一个** `target` 当整批的坐标系。本机 `D:\teamcode` 是工作区，下有两个项目（`thincoder` ∥ `thincoder.com`）：

| 输入 | 结果 |
|---|---|
| `target = thincoder`，档清单含 `thincoder.com` 的档 | 按 `thincoder` 的根解析 ⇒ **判 `档缺`** |
| 不传 `target`（多项目工作区） | **`ERROR（多项目工作区：请指名 target）`** |

**三个症状是同一件事**：

1. **三份评审拿不到令牌**——批档与设计档跨项目时，判域解析不出根；
2. **后续每一次跨仓写入**——写门的判域同一套坐标系；
3. **底层伸手到业务仓**——判定面拿一个坐标系去覆盖两个项目，方向问题与此同源。

**已定决定**：判域改为**按档所属项目根解析**——清单里每个档用它自己的落点定根，不因为清单里混了别的仓就判档缺。· 用户原话：「**一处改动，能一次性解掉：三份评审拿不到令牌；后续每一次跨仓写入；以及你指出的『底层伸手到业务仓』这个方向问题——它俩是同一件事：判定面不该跨仓混用一个坐标系。**」· 时间：2026-11-07 14:31（提议）/ 14:32「开」

### 边界（这一批不做什么）

- **不改判定内容**：锚 ∥ 段长 ∥ 行号坐标 ∥ 引文的判法一字不动，**只改「拿哪个根去解析」**。
- **不放松错判**：解析不到根时**照旧显式报错**（`ERROR` 是 `ERROR`），不静默兜底、不回落到一个猜的根。
- **不动写门之外的门**：收口门 ∥ 写前门的判据面不变；若它们的根解析同病，**本批只登记不越界改**。

### 验收方向（设计席据此写判据，主 agent 不替它定稿）

1. **跨两个项目的档清单能出 `PASS`**（每个档按自己的根解析）；

3. **解析不到根 ⇒ 仍是显式 `ERROR`**，且拒文点明是哪个档、为什么解析不出。
