## 判据（本批最重要的一条）

**一个永远命不中的判据，和一个永远误报的判据，都会让闸失去意义。**前者更坏：误报会有人骂，假绿不会。

所以本批的验收方式是**喂反例**，不是「跑一遍全绿」：

- 改 1：传错参数位 ⇒ **必须抛**（不是静默返回空）。
- 改 2：一行两个码段 + 空档含 `cd` ⇒ **必须判**（不许整行跳过）。
- 改 3：全批档面一次跑完 ⇒ **有界**（给一个可接受的上限，超了就说明缓存没做对）。
- 改 4：`test/` 开头的仓根相对路径 ⇒ **可解析**（或明确改成一条写法规范，并写清为什么不做引擎侧）。
- 改 5：谓词由 `paragraph.mjs` 导出，写前门消费它；**两处不得各留一份正则**。

## E4 的裁定：换成本轮实读到的那个缺陷（父侧 · 2026-11-05 05:21）

设计席的做法**我认**：E4 复现不出，它就**不把一条复现不出的判据写进设计档**，而是把查到的同族真缺陷举出来。**「写一条查不出的判据 = 把『查过了』写成『是这样』」**——这句话是对的。

### 裁：走 ①，把 E4 换成整 token 边界剥除

**证据面**（设计席实读）：提示词面剥操作数时**按子串整串删除**，`见 test/RTM.md` 被剥成 `见 test/` —— 路径前缀被吃掉，**该指针在提示词面不被判（漏报）**。

**为什么 ① 而不是 ②**：

1. **它有实读复现**（② 要的是「另给复现坐标」，我们给不出——E4 那个形态根本不存在）。
2. **它与 E2 同族**：E2 是「码段判面算错导致整行跳过」，E4 这个是「剥除面算错导致 token 被吃掉」——**两处都是「判面边界算错」，一起修才叫修完一类**。
3. 落点在声明文件内的 `thincoder-core/doc-check/anchors.mjs`（`stripCanonOperands` 一侧），不动判据松紧。

**判据**：剥除只吞「整 token」（左界与右界都成立的 `CANON_OPERANDS` 名），**剥完的行仍保留路径前缀**；夹具 = 一行 `见 test/RTM.md` 与一个操作数名相邻 ⇒ 剥除后该指针**照常被判**。

### 另外两处我认可并要保留判断

## 「要不要加一条集成行」的裁定（父侧 · 2026-11-05 05:43）

设计席问：本族是否该有一条「提示词面悬空指针被门拦下」的集成行？它自己判**零差量**，并指出：要立就得先有需求面来路（业务场景或生产事故），否则是「无场景的常驻用例」。

**裁 = 不加，零差量成立。**

**判据三条**：

1. **它是工具内部机制**——`doc_check` 的判据面变了，**没有业务用户在「门怎么抽 token」这个面上进入产品**。

**⇒ 一句留给后来者**：**「这个改动很重要，所以该有一条用例」不是来路。**来路只有两个：**产品真需要的业务场景**，或**生产真发生过的问题**。两个都没有 ⇒ 记「零差量」并说明理由，**不造用例**。

## 逐处根因坐标与改法（符号名，不写行号）

**E1 —— `checkParagraphs`（`thincoder-core/doc-check/paragraph.mjs`）**

- 根因：形参解构只校验两条阈值；`files` 缺省 `[]`。第二实参被静默丢弃，判定集因此为空。
- 改法：① `files` 必须是数组，非数组/缺失 ⇒ 抛；② 形参后接 `...rest`，非空 ⇒ 抛（把「参数位传错」整族变成硬错）；③ `files: []` 保持合法（判 0 档不是错，`gate` 面空清单有既定语义）。
- 反例夹具：`checkParagraphs(cfg, [档])` · `checkParagraphs(cfg)` · `checkParagraphs({...cfg, files: 字串})` ⇒ 三形各抛，报串点名收到的值与正确形。
- 回归：正确形仍 1 条命中；`files: []` 仍 0 条不抛。

**E2 —— `isExecutableLine`（同档）**

- 根因：三支正则都以裸反引号起止（`` `[^`\n]*…` ``），任意两枚反引号之间的文本都被当码段。
- 改法：新增谓词 **`codeSpans(line)`** ⇒ `{ start, end, text }[]`（按反引号出现序配对；已落设计 §3.18「谓词面」的码段族，谓词数 11 → **12**，再出口缝名单同轮加一名）；三支判据改为判**每个码段的内容**；`inCodeSpan` 同取该切分（一处配对规则，不留第二份）。
- 反例夹具：`见 \`甲\` 与 cd \`乙\` 的组合` ⇒ false；`运行 \`cd docs && ls\` 即可` ⇒ true；锚面同上「悬空指针必须报出来」。
- 回归：单码段命令 ∥ 搜索模式串三支原判不变。

**E3 —— `checkAnchors`（`thincoder-core/doc-check/anchors.mjs`）与解析层消费面**

- 根因：每个悬空 token 调一次同名候选扫描，对 `roots + scanBases` 每根各走一遍目录树（深 ≤3、命中 ≤20）；热门批档一条就几十个悬空 token。
- 第二个无记忆点：`sectionOnDisk` 每次重读目标档（同一档被 N 个指针引用 ⇒ 读 N 次），而引文面 `citedTextOf` 有同轮记忆——同一次调用里两种读法。
- 改法：① 同名候选改为**一次 `checkAnchors` 建一份按档名的索引**（同 `docRoot` 各根、同深度界、同命中界），悬空 token 查表；② `sectionOnDisk` 的标题号集合按绝对路径记忆；③ 解析结果按（token ∥ 引用方目录）记忆。
- 上限：全 `docs` 面一次 `doc_check` ≤ **60 s**。
- **结构判据（可跑形 · 两条读数并列）**：同一夹具档，两种形态各跑一次 `checkAnchors`——① 悬空 token 数 = N（每行一枚，互不同名）；② 同一批 token 再抄一遍 ⇒ 悬空 token 数 = 2N。
  **数法** = 单元测试档里对 `node:fs` 的 `readdirSync` 打桩计数（`t.mock.method` ∥ 局部替换），跑完读调用次数。**期望**：两次的走查次数**相等**（成本与悬空 token 数脱钩）；改前同法 ⇒ 2N 形态的走查次数 ≈ 2 倍（先红证据）。两个数都记 §5。

**E5 —— 标题谓词（`paragraph.mjs` 导出面 + `thincoder-core/tools/doc-write-gate.mjs` 消费面）**

- 根因：`paragraph.mjs` 的谓词族缺标题谓词，写前门只好自带 `HEADING_RE`；两处「什么算标题」各自成文。
- 改法：导出 `headingMark(line)` ⇒ `{ level, text }` ∥ `null`（形对齐既有 `fenceMark`）；段判据的标题栈与写前门的正文行谓词同消费它，写前门删本地字面与那句「引擎没有导出标题谓词」的注释。
- 反例夹具：`# x` ∥ `#\tx` ∥ `## x` ∥ `#` ∥ `#x` ∥ `  # x` 六行，引擎与写前门**同判**（写前门正文行谓词非空 ⟺ `headingMark` 为 `null`）。
- 约束：谓词语义随现有段判据**逐字不动**（行首 1–6 个 `#` 后接空白）；本次只搬单源，不改判据松紧。

**E4′ —— `stripCanonOperands`（`thincoder-core/doc-check/anchors.mjs`）· 剥除面**

- 根因：剥除按**子串整串删除**（`out.split(s).join("")`），不看 token 边界——路径形操作数里的末段名被当独立操作数删掉，路径前缀留下来却不再构成档 token。判面边界算错 ⇒ **漏报**（与 E2 同族：一处是码段判面，一处是剥除判面）。
- 改法：剥除改**整 token 边界**——左右界与锚抽取的档 token 用**同一对**边界（左界不接 `[A-Za-z0-9_.\-\\/@<>]`、右界不接 `[\w]`），一处定义、两处消费；末段名不再单独被删。
- 反例夹具（提示词面档 · 系统临时域 · 零落仓）：一行「末段名属操作数表的路径形」⇒ `checkAnchors` **1 条 `档缺`**（改前 0 条）；同档一行「裸名操作数」⇒ 仍 **0 条**（照剥）。逐行读数见设计 §3.20「剥除面 = 整 token 边界」夹具块。
- 回归：`docs/` 面判定零变（剥除只作用提示词面）；J1 ∥ J3 面同域复算旧式 0 ∥ 新式 0。
- 消费面记账：`scripts/prompt-refs-check.mjs` 从本档 import 同一函数（定义单源、不复制）⇒ 改法随之生效，该档**零编辑**；其闸态读数 = 本批兼容判据（改前 / 改后各一读，记 §5）。
- 设计落点：设计 §3.20「抽取面三免」的「剥除面 = 整 token 边界」∥「③ 的作用面」∥「实现单源」。

## 关键决策（含被否）

1. **E1 只校验 `files` 不够**：静默路径正是判定集落空，故同时拒多余位置实参——把「位置传错」这一族一次拦死，而不是逐个猜调用形。

3. **E3 用「一次建索引」而不是「按 token 记忆」**：记忆只摊薄重复档名，悬空档名各不相同时仍一档一次全树走查；一次建成后成本与悬空 token 数脱钩（结构判据由此可判）。
4. **缓存口径要重述，不是推翻**：§3.20 原句「不设缓存」防的是 mtime 键算错即静默放行；E3 要的是同一次调用内同一档只读一次。两者不冲突——跨轮缓存照禁，同轮记忆放开，分界写进设计档。
5. **E5 导出而不是「两处注释互指同步」**：谓词面本就自称单源，缺的正是这个谓词；补进导出面后写前门零字面，漂无可漂。

6. **E4′ 只改剥除面，不动判据松紧**：维持操作数族、维持「只提示词面剥」。被否两条——① 改成「路径形一律照报 + 文档里写明别这么写」（处方式规避，判据的洞还在，§1 已把这种规避列为病）；② 顺手动 `scripts/prompt-refs-check.mjs`（§1 边界外：不新增工具、只改 `doc-check/` 与写前门；该档 import 同一函数即自动生效，复算差 0）。
