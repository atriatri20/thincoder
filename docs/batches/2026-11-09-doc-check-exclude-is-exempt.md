### 用户裁定：排除面 = 免检放行（2026-11-09 05:29）

**用户原话**：「我让你给doc_check做排除路径，目的就是不去检测，让他免检放行……你他妈个傻逼给我做成了：『不得读作已检』，操作加什么戏啊！」

**我把话听明白了**：排除路径的定义是**这些档不进判、等于通过**。做成了「排除了但你要知道它没被判」——那是把「免检」改写成「检不了的免责声明」，正好反了。

**盘上现状（实读，两条相反的话在同一个设计节里）**：

| 同节 · 报面 | 「全清单被排除（**唯一一处「错读会当成干净范围」的地方**）」⇒ `gate` 面 `ERROR（0 档受检——空范围不判 PASS）` ∥ `report` 面 `结论：0 档入判——清单 N 档全落在 manifest 排除面内，**不得读作已检**` |
| 同节 · AC-Ex6 | 把上面两个报面字串写成了验收项 |

**所以这不是实现跑偏，是设计里就写了两套**：一边说「不设提示」，一边把提示写进了验收。实施席照着第二套做的，它没错；**错在这一节自己没把口径统一**。

**本批口径（就一条）**：

- 被排除的档 **不进判集、不报错、不提示**——它们等于通过。
- **全清单被排除** 是合法状态，报面照常给 `PASS`；**不许**出 `ERROR`、**不许**出「不得读作已检」「没有可判档」一类免责句。
- 排除桶那一行（`排除 N 档（manifest 排除面命中，未判）：`）**保留**——它是「这批档被免检了」的如实记录，不是警告。**保留它 ≠ 保留那两句。**

**要改的面**（设计档 + 代码，两处同轮）：

1. `docs/core/design/DOC-CHECK.md` §2.6：删「全清单被排除」那一节的 ERROR 句与「不得读作已检」句；`AC-Ex6` 改成「全排除 ⇒ 两侧报面照常通过、零免责句」；用例表那两行同步。
2. `thincoder-core/doc-check/index.mjs`：`gateReport` 的 `excluded.length > 0 && !hasSkips` 分支、`report` 面那句、以及空范围判 `ERROR` 的那一支，按新口径收。

**一条要记**：这是「把用户要的『不做』做成『做了但声明没做』」——**免检就该像免检**，加免责句等于没免。

### 机制设计（实施契约 · 全在 `thincoder-core/doc-check/index.mjs`）

一句话：**免检的那几档根本不计入「判了 0 档」这一态**。派生的局部判据 = `exemptedAll`（`checkFiles` 空 ∧ `excluded` 非空 ∧ 两个跳过桶皆空），就地算、不新增导出、不进返回值。**它算一次、三处读、一处删支后不吃它**（见 1–4 条）。

**先后（评审 ③）**：可判性判定在前、排除过滤在后。

- 依据：`resolveRange` 先分出 `check` 与三个跳过桶，`splitExcluded(range.check, …)` 只吃 `check`——依据 `thincoder-core/doc-check/index.mjs`「const { checkFiles, excluded } = splitExcluded(range.check, base, readOf)」。
- 边界读数：排除前缀内写一档已不在盘 ⇒ 它落 `skipped.missing`、不进 `excluded` ⇒ 首行仍 `ERROR（0 档受检——空范围不判 PASS）`、跳过行点名该档、排除桶零出。
- 与需求 F3 同口径：「『另有档不在盘』不属此列，仍按空范围判 `ERROR`」。

1. **首行（`gateReport` 的 `verdict`）**：`total === 0` 那一支现在是 `checkFiles.length ? PASS : ERROR`；改成 `checkFiles.length ∥ exemptedAll ⇒ PASS`，其余仍 `ERROR（0 档受检——空范围不判 PASS）`。
2. **`范围` 行的 0 档支**：`exemptedAll` ⇒ `范围：${src} —— 0 档受检（清单 N 档全落在 manifest 排除面内）`——只写事实，**不写**「不得读作已检」那一类括注；其余空范围分支的括注不动。
3. **空范围说明行（抑制式，不为它拆四条入口）**：`if (checkFiles.length === 0)` 整块加 `!exemptedAll` 守卫；块内 `excluded.length > 0 && !hasSkips` 那一支**删除**（`checkFiles` 空时它与 `exemptedAll` 同值，已恒假）。四条空范围入口逐字不变——它们的 `excluded` 皆空 ⇒ 守卫为真 ⇒ 既有四句照出，`36-4` 不受影响。
4. **`report` 面末行**：删 `checkFiles.length === 0 && excluded.length > 0` 那一支，落既有 `结论：0 条命中（锚 ∥ 段 ∥ 行 均清）`。`report` 面另有档不在盘时先抛错（既有 fail-closed），故删支后该位置只剩「全排除」与「真干净」两读。
5. **注释面同轮收**：档头注释块里「全清单被排除时两面各有一句点名排除面：判了 0 档不得读成干净范」那一句、`gateReport` 内「全清单被排除（§2.6）：这是唯一一处错读会当成干净范围的地方」那一句、报面末行上方「全清单被排除时末行点名排除面（§2.6 AC-Ex6）」那一句，加上 `splitExcluded` 上方那句以 `PASS` 为红点的否证（「且全排除时 `checkFiles` 非空 ⇒ 首行落 `PASS`」），四句按新口径改写——留着就是把已废的规则写在代码里。
6. **不动**：`splitExcluded` 的判定 ∥ `excluded` 桶行形 ∥ `hits` 口径 ∥ 三条判据本体 ∥ `per-root.mjs`（已在盘，本批零改）。`excluded` 桶在两面照出、位置不变。
7. **接口契约（评审 ④）**：`checkFiles` ∥ `excluded` 都是既有返回值读数，`excluded` 与 `skipped` ∥ `unreadable` 各成一桶、三者不重叠；契约行见设计档 §3 引擎返回行，本批不改返回形状。

### 关键决策

| # | 决策 | 理由 |
|---|---|---|
| KD-1 | 全关即过：`checkFiles` 空 ∧ 全落在排除面 ⇒ 首行 `PASS`，零免责句 | 用户原话「排除路径，目的就是不去检测，让他免检放行」。排除面是调用方的声明——声明之外没有档要判，「判了 0 档」这一态在这里不成立；照旧判 `ERROR` 等于把免检改写成「检不了的声明」 |
| KD-2 | 混态不退让：清单里另有不在盘 ∥ 非 `.md` 的档 ⇒ 仍 `ERROR` | 那几档不是被排除的，是清单与盘不符——`ERROR` 由它们引起、不是由排除面引起。免检放宽的是「被排除的档」，不放宽这一签 |
| KD-3 | 排除桶那一行保留，但不当警告用 | 用户明说保留：「它是『这批档被免检了』的如实记录，不是警告。保留它 ≠ 保留那两句。」 |
| KD-4 | 不新增 `judgedFiles` 一类第二名字，靠 `exemptedAll` 一个局部常量收口 | 首行 ∥ `范围` 行 ∥ 说明行块三处读的是同一个事实，各算一遍必漂；`report` 末行改成删支后不吃它 |
