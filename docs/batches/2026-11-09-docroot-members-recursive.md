## 2.3 机制设计（要点，正文单源 = §2.12）

- **遍历**：`readdirSync(dir, { withFileTypes: true })`；只下潜 `ent.isDirectory()`，`ent.isSymbolicLink()` 跳过；`.md` 过滤按名字、大小写不敏（沿用现行「按名字认、不按 dirent 类型预筛」的取成员纪律）。
- **序**：成员**收完后对整集排一次**——声明序（目录序）→ 层根相对路径（`/` 归一）码点序；不是逐层下潜各按名序（T98 钉住两种读法的分界格）。递归后裸文件名不再唯一。
- **嵌套根**：一根在另一根之内 ⇒ 同一份档按解析后的绝对路径去重、保留首次出现（T99），去重键在 win32 折小写（AC-58⑧）；不去重就进两次正文、吃两份预算。
- **部分不可读**：任一目录（层根或下潜目录）`readdirSync` 抛 ⇒ 该目录进不可读集（`read failed: <code>`），其余照走 ⇒ 态 3 + 半读句逐项点名；不新增原因词、不新增句形。
- **态 2 `no .md file`**：语义 = 「整棵子树零 `.md`」且**没有任何目录列不出来**（任一目录 `readdirSync` 抛 ⇒ 子树内容未知，不追加该句；AC-58⑦），字面不动（零新增词表）。
- **预算**：整层成员共用一次注入的同一预算，按注入序拼接后一次截断——算式与截断句零改。
- **文案**：态 3 用途句不含排序短语（递归后「名序」不成立，评审也不需要知道序）；`24-1` 的逐字断言随新句同改，业务结果不变。
- **函数层**：遍历 / 排序 / 去重收进模块私有 `collectStandardDocs(dirs)`，`injectProjectStandards` 只留三态组装与预算（判据 = 源码面 AC-60③）。

## 2.7 关键决策

- KD-M1-63 就地改（递归 + 整集相对路径序 + 不跟链接）；拒掉两样：按目录枚举序（跨机器不可复述）· 跟链接 ∥ 加深度帽（前者成环跑不完，后者静默漏档）。理由与代价单源 = 该行。
- 排序只留**一种读法**（整集按层根相对路径码点序）：逐层下潜各按名序在「子目录名排序早于层根档」时给出相反顺序，两读法不能并存 ⇒ T98 钉住分界。
- 嵌套根按**绝对档路径**去重：递归把「一根本身在另一根之内」从罕见变成随手可得，不去重则同一份档进两次正文、吃两份预算。
- 不引「跳过表 / 条数帽」：`thincoder-core/memory/file-walk.mjs` 的 `SKIP_DIRS` / `MAX_WALK_FILES` 属索引面策略，搬进标准层会静默漏掉作者真放进层的档。
