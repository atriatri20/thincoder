## 范围裁定（父侧，2026-11-09 21:49）

**本批三件，全是「让已有数据说真话」，不动采集器：**

1. **回执按 `kind` 分类计数**：`cites` 与 `cites-symbol` 分开报，各自带「已验存在 N ∥ 判不了 N」；**不以一个混合总数作头行**。
2. **自环不入边**：`src === dst` 不生成边。
3. **回执自报时效**：回执写明图建于何时、此后 N 档变更（不用做增量扫描）。

**不入本批的（各有理由，不是漏了）：**

- **`cites-req` 的需求号登记表**：它要定「什么算一条需求的定义」（表格首格 ∥ 标题 ∥ 两者兼收），是**新判据 + 新解析器**，不是修回执——另起一批，行见 §1 末。
- **`cites-symbol` 的形状过滤**：现在没有驱动它的场景；分类计数之后噪音已可被读者自行排除，收窄采集面反而可能漏掉真引用。
- **裸名解析歧义**（`README.md` 解到仓根那份）：属解析策略，不在回执面。

## 实证（2026-11-09 实跑，本批动因）

对同一份设计档：`forward` 全 `kind` = **124 条**；`kind=cites` = **38 条**（38 条全 `ok`）。**八成出边是 `cites-symbol` 抓的反引号标识符**（`v2` / `docs` / `open` / `层与落点` 这类），全部落「判不了存在性」。全库 `scan` 47 档 → 5543 边，其中 4458「判不了存在性」。

**结论：总数这个数字现在没有信息量，而它恰好是回执的头行。**

### 机制设计（细则全在 design，此处只记落点）

1. **按类计数**（形与列序单源 = design §2.5.0，本节不复述）：四个回执各紧跟一行按类计数；`cites` 与 `cites-symbol` 不共格；`scan` ∥ `forward` ∥ `reverse` 首行不含任何混合边总数（`chain` 首行的「命中 E 条边 / V 个节点」是走查规模口径，不参与边类读数）。
2. **自环**（design §2.2）：`src` 与 `dst` 字符串等值 ⇒ 不产出边，拦在 `makeSink.push` 一处；`doc:P → doc:P#5` 是两个节点、**照常落边**；旧库里的自环边随下次 `scan` 整表重写消失，**不写迁移**。
3. **时效格**（形单源 = design §2.5.4，本节不复述）：来源 = `doc_edges.scanned_at`（每行都带，按 `scope` 一档一个时刻）；读面逐档比文件的 `mtime`（**严格大于**）得变更档数。**两形都印 `K`**——`K` 是「此后 N 档变更」的分母。一次目录走，不读全文、不解析、不落库，**不做增量扫描**。

### 关键决策（全文 design §4）

- **KD-10** 按类计数、混合总数不作首行 —— 被拒：留混合总数作头行、分类数另列。实测 124 条出边里 86 条是 `cites-symbol`（全「判不了」）、38 条是 `cites`（全 `ok`），混合总数的读法是反的。
- **KD-11** 自环拦在产出面 —— 被拒：靠 `UNIQUE` 顺带挡（它只挡同行同写法重复）、走查里跳过（表里坏边照旧被 `forward` 印出）。
- **KD-12** 时效复用 `scanned_at`，不建元数据表 —— 被拒：`doc_graph_meta` 存全图建标时刻（带 `scope` 扫一档就会洗掉其余各档的老化，且要连带升 schema 版本）。

### 上抛项

- **[上抛·知会]** 时效格量的是「已落边的档」：扫过但一条边也没产出的档没有行、没有时刻，它的变更不计入「此后 N 档变更」。要覆盖得给扫过的档单开一张清单表（连带 schema 版本号），本版不做，已记 design §7；`K` 印出来就是让读者知道这把尺量了多少档。若用户要覆盖零边档，另起一批。
- **[上抛·知会]** 需求 AC-9 写的是「`scan` 回执写明……」，而「刚扫完」这一刻 N 恒为 0。本设计把同一格同时放到三个读动作上（§2.5.4），这一格才有信息量——这是对需求的加强，不是改义；若父侧只要 `scan` 面，读动作那两处删一行即可。
