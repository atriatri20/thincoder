# 核心统一（CORE-UNIFICATION）· 设计

> 需求 = `docs/core/requirements/CORE-UNIFICATION.md`。
> 最近先例：`TWO-REPO-MERGE.md` 的产品边界与 `PORTABILITY.md` 的归属。对齐 = 包边界、显式注入、独立验证。
> 勘察证据：已读当前核包消费、提示词加载、兼容与测试章节。相关 = 包依赖、VSIX 内嵌和单副本。

## 1. 目标形态

```text
thincoder-core/       @thincoder/core，共享实现、prompts、tool-docs
thincoder-cli/        CLI/TUI/ACP 壳
thincoder-vscode/     宿主 API、面板、webview 壳
thincoder-desktop/    桌面宿主壳
thincoder-server/     服务端宿主与 WebUI
render-core/          共享渲染核
```

core 的内容只撰写一次。端侧不维护同语义副本。

## 2. 包与加载契约

1. 壳经 @thincoder/core 包名与子路径导出使用 core。
2. core 内 import 只指向 core 内模块、允许的共享核或 node: 内建，不指向端壳。
3. 开发期可使用本地链接；生产依赖使用真实 semver，不使用 file: 或 * 代替版本。
4. 核独立版本并先发布；CLI 等产品后发布。
5. VSIX 等无运行时依赖解析的产物必须内嵌核。
6. prompts 与 tool-docs 随核包进入所有产物。
7. 端差经参数、回调、ctx 或装配注入，不在 core 写产品名分支。

## 3. 提示词与资源

prompt-files.mjs 以 import.meta.url 定位核内资源，不依赖进程 cwd。

prompts/ 与 tool-docs/ 是唯一撰写面。缺档行为按各调用方的当前硬加载或可见降级契约，不因统一而改变。

端特有内容通过当前 overlay/decorate 装配进入，不建立第二份提示词文档。

## 4. 发布与版本

发布前检查：

- 产品声明的核版本与仓内核版本一致。
- 实际安装或打包的核版本一致。
- 核包、产品安装目录和 VSIX 内提示词/工具描述文件集合一致。
- 产物内对应文件与仓内核逐字节一致。
- 缺核、缺资源或错误依赖形态必须失败。

核包未发布时，依赖 registry 的产品发布应显式失败。

## 5. 兼容策略

| 面 | 规则 |
|---|---|
| 配置 | 旧键可读、未知用户键不静默丢弃、迁移有说明 |
| 文案 | 机器消费协议保持；人读文案变化同步字典和测试 |
| 命令 | 必要旧名保留别名；外部命令 id 不静默改 |
| 事件 | 事件名、状态值域、载荷语义变化有迁移与验证 |
| 数据 | 会话和记忆迁移由各自负责文档定义 |

无法兼容的变化必须单独提交用户，不用“核统一”作为默示授权。

## 6. 验证层次

- core：单元测试与语法/结构检查，独立于端壳。
- 产品：从真实入口运行集成场景。
- 发布：npm pack/安装与 VSIX 解包断言。
- 文档：当前 doc_check。
- 回归：未涉面保持，改行为的面按当前裁定验收。

不为文档治理新增业务集成用例。

## 7. 关键决策

| # | 决策 | 理由 |
|---|---|---|
| D-C3 | 真包 + 开发链接 + 生产发布包 | 两态都可验证 |
| D-C4 | 核不依赖壳 | 保持依赖方向 |
| D-C5 | 提示词与描述进核 | 消除副本漂移 |
| D-C9 | 使用标准依赖与打包机制 | 不增加垫片 |
| D-C11 | 版本和资源完备性断言 | 防止成功产生缺核产物 |
| D-C13 | import.meta.url 定位资源 | 与 cwd 解耦 |
| D-C16 | 行为与契约变化逐项裁定 | 统一不代替用户决策 |

## 8. 边界

本档不保存模块迁移表、历史相似度、旧端差清单或目录改名步骤。当前机制由各子系统设计档负责。
