# 台账自持（LEDGER-SELF-CONTAINED）· 设计

> 板块：工程模式 / 文档体系自持——项目归属、仓内文档、批次与台账写权。
> 需求层 = `docs/core/requirements/ENGINEERING-MODE-V2.md` §13.4（文档体系各仓自持）。
> 最近先例：`docs/core/design/LEDGER.md` 的项目根与 SQLite 存储、`docs/core/design/BATCH-RECORD.md` 的批次载体。对齐 = 同一项目根、同一批次指针和同一写权边界；偏离 = 本档只负责仓内归属与写权，不展开状态机或批次段契约。
> 勘察证据：已读当前 LEDGER、DOC-SYSTEM、BATCH-RECORD 及 `docs/core/requirements/ENGINEERING-MODE-V2.md` §13.4。相关 = 工作树外 SQLite、项目根推导、各仓自持和主 agent 写权；未使用外部公共源。

## 1. 定位

本档回答“工作项属于哪个项目、正文住在哪里、谁可以写”。它保证台账、批次与需求设计文档按同一项目归属，不另建存储或状态规则。

| 主题 | 权威文档 |
|---|---|
| SQLite schema、六态、证据、查询与批次结算 | `docs/core/design/LEDGER.md` |
| 批次段、生命周期与冻结 | `docs/core/design/BATCH-RECORD.md` |
| 文档层、目录和引用形态 | `docs/core/design/DOC-SYSTEM.md` |
| 跨仓写门 | `docs/core/design/CROSS-REPO-WRITE.md` |

## 2. 项目与存储归属

### 2.1 项目根

项目根由目标路径沿祖先链向上取得，最近一个携带 `PROJECT-MANIFEST.json` 的目录拥有该目标。库文件存在不构成项目标记，多项目工作区不得向下猜选子项目。

工具面的会话锚是上溯边界。目标越出边界或项目根有歧义时拒绝归属，不用进程工作目录代替。

### 2.2 本地台账

本地台账是工作树外的 SQLite 数据库，存于用户数据目录，并按规范化项目根生成库键。它保存条目、状态、证据和批次指针，不保存需求或设计长正文。

项目工作树内不保存本地台账镜像。删除或克隆工作树不复制其他项目的台账，数据库可读性也不得被伪装成空台账。

### 2.3 条目归属

一条本地台账行只登记其项目根内的工作。`task_book` 与实现落点指向同项目；证据需要引用公共来源时，另按第 5 节的声明边界。

团队台账是独立的服务端账本，不与本地台账同步，也不改变本地条目的项目归属。

## 3. 文档与批次自持

- 每个项目在自己的仓内维护需求、设计、批次和本地台账入口；本仓需求不得交由另一仓文档代管。
- 本仓缺少当前工作需要的文档层时，在本仓补建并登记归属；另一仓已有同主题文档不构成省略理由。
- 一个交付目标只开属于本仓的批次档。跨仓工作按仓拆批，各自记录受影响文件、验收和结算。
- 文档读取不受仓界限制；写入仍归目标项目及其批次规则。读取权限不构成写权。

## 4. 写权与批次绑定

本地台账的记录、状态推进、结算和物理写入只由主 agent 执行。子代理获得 `query` / `count` 只读面，新发现通过报告交回主代理，不直接写账。

开批时，批次档头记录真实台账行号，行的 `task_book` 指回该档。接手、新建、补挂、收口、重开和取代使用同一批次绑定链，具体写序与补偿归 `docs/core/design/BATCH-LEDGER-REVIEW-UNIFY.md` §2.20。

工程模式的适用写操作必须携带该项目的一条在途行。`project` 只声明归属，不改变命令执行目录；`writableRepos` 只按跨仓写门扩展目标范围，不转移条目或批次的归属。

## 5. 引用边界

仓内引用使用本项目可解析的文档、章节或符号坐标。引用外部公共源时，目标仓必须先由本项目的 `index.publicRepos` 声明；未声明的邻近仓不因路径可达而成为合法引用源。

声明公共源只开放读取与引用。它不等于本地条目可以登记他仓工作，也不等于可以创建跨仓批次档。

## 6. 一致性与恢复

批次与台账以双向指针和实际状态互核。`batch check` 只读报告指针、档头与行集的不一致，不自动改档或改账。

恢复由主 agent 按具体读数执行：修指针、补挂、重开、收口或取代。任何恢复不得补造未发生的评审、批准、实施或验证记录。

## 7. 验收

- 同一目标推导出的项目根、台账库键、批次归属和写门项目一致。
- 本地台账库位于工作树外，并按项目根隔离；项目不可判时明确拒绝。
- 子代理写账不可达，主 agent 的每笔写入能归因到当前项目与批次。
- 跨仓工作分别形成各仓批次，不产生归属混合的条目或文档。
- 未声明公共源不作为合法引用源；声明读取不附带写权。

## 8. 边界

本档不复制六态迁移、凭证、批次段写权、跨仓写门算法或文档机械检查判据。这些机制各由第 1 节列出的权威文档负责。
