# 文档检查（DOC-CHECK）· 设计

> 需求层 = `docs/core/requirements/DOC-CHECK.md`（F1–F21 / AC-1–AC-19；本批的判据条目 = **F18–F21** ∥ **AC-16–AC-19**）。本档只答「怎么建」，判据口径不重述（单源 = `docs/core/design/DOC-DISCIPLINE.md` §3.20）。
> 判据仍三条（锚 ∥ 段长 ∥ 行号坐标），判定逻辑、命中类与 verdict 串未动；本档的三处**收窄面** = 档名与扩展名的识别面（§2.6）· 逐条豁免登记 · 假阳第三档（§2.7）· **示例写进围栏块**（§8 的两条合法写法①，分界判据与逐块登记住 §2.6 末）。第三笔只换写法、不动任何判据。
> 判据口径单源 = `docs/core/design/DOC-DISCIPLINE.md` §3.20。

## 1. 模块目标与现状

`doc_check` 在三个强制面上判文档：设计轮交付（eng-designer）· 实施轮交付（eng-coder）· 父侧收口（`batch` 工具两机械点）。它收的清单可以跨项目，而它只拿得到一个根——那个根就成了整批的坐标系。

**定根（读码取证）**：`thincoder-core/doc-check/index.mjs` 的 `runDocCheck(root, opts)` 开头先定声明根 `const base = declaredRoot(root)`；相对条目由 `resolveRange(base, docs)` 按它解析，而每份档的判定根由 `rootOf` 单独求（§2.1）——`base` 不再是判定的坐标系，只是相对条目的解析基准与无 manifest 祖先档的落点。

一次调用横跨多个项目时，各组按自己的根判（§2.2）：一份档一个根，谁也不借谁的坐标系。声明根只在两处接手——相对条目的解析基准、祖先链至盘根无 manifest 的档的落点；缺声明根才整清单不判（§2.4）。

## 2. 判域：按档所属项目根解析

**目标态的三种入参形**（锚 = 工作区，自身无 manifest）：

| 入参 | 判据 |
|---|---|
| 缺 `target` | **拒**——报文点名 `target`，零判定 |
| `target: null` | **拒**（`null` 即缺，解析层把两者归一） |
| `target: ""` | **拒**（「给了」= 一个非空字符串） |

- **「缺 `target` ⇒ 拒」**：三形同一判（缺 ∥ `null` ∥ 空串），AC-11 上锁，零判定。
- **`null` 即缺的依据**：解析层把 `undefined` 与 `null` 当同一件事（`thincoder-core/path-resolve.mjs`「if (given === undefined || given === null) {」）——工具面不再为 `null` 单设一支（§5 KD-10）。
- **读数口径（知会，不设机制）**：判定行为以**新进程直调盘上模块**的读数为准——会话进程可能加载旧模块，在那里读到的「恒拒」是载体的事，不是判据。本档不设检测、不自愈：那会造出第二套判据。

### 2.1 根的定法

```text
rootOf(abs) = owningProject(abs, parse(abs).root) ?? declaredBase
```

- **取根判据本体** = `owningProject(target, boundary)`：`thincoder-core/manifest.mjs` 导出（实现在 `thincoder-core/manifest-discovery.mjs`）。全仓单源，台账库键、批档路径、评审受理同用它。
- **界 = 该档所在盘的盘根** `parse(abs).root`（F17 同条「界 = 该档所在盘的盘根（与项目根视图同一个界）」，与 `projectRootView` 里 `owningProject(target, parse(target).root)` 是同一个界）。
- **`declaredBase`** = 声明根（工具面收到的 `target` 解析后的绝对路径——`target` 必填；会话锚只作相对形 `target` 的基根）：它在「该档祖先链至盘根无 manifest」时接手。**判据只有一条**：有声明根 ⇒ 用它；没有声明根 ⇒ 显式报错。「声明根自身是不是项目」**不参与判断**。
- **不取「清单首档定根」**：一份档的根管不了另一份，跨项目清单必然错一半。**不拿会话锚当整批的公共坐标系**：拿它盖住整批才是要治的形——根由调用方指名（`target` 必填），或由档自身所属项目给出；一份档一个根才是本批要的形。声明根**可以**是会话锚（调用方显式把它当 `target` 传入，见上一条 `declaredBase`）；「拿它当声明根」与「拿它盖住整批」是两件事。

**为什么界不能填声明根**：`owningProject` 先判界，档在界外即判无归属——填声明根会把跨项目的档一律推出界。依据 `thincoder-core/manifest-discovery.mjs`「if (!isInsideOrEqual(dir, edge)) return null」。现场：`target = thincoder`、清单含 `thincoder.com` 的档 ⇒ 界外 ⇒ 落声明根 ⇒ 正是本批要修的 `档缺`。

| `rootOf` 的哪一支 | 依据（现场读数 ∥ 依据行） |
|---|---|
| `owningProject` 命中 | 先例：`thincoder-core/agent-tools/batch-gate.mjs` 的 `evaluate` 内 `const root = owningProject(selfAbs, base) ?? batchProjectRoot(base)`——批档门按档定根，已跑在生产 |
| 落 `declaredBase` | F17：依据 `docs/core/requirements/DOC-CHECK.md`「有声明根 ⇒ 用它（含夹具临时域，那是调用方声明的坐标系）；连声明根都没有 ⇒ 显式报错」。夹具面另有豁免通路：测试钩子顶在前面时，依据 `thincoder-core/manifest-discovery.mjs`「if (_projectRootOverride) return resolve(_projectRootOverride)」——一档一根退化为单根，与今日逐字同 |
| 无声明根 ⇒ 显式 `ERROR` | 依据 `docs/core/requirements/DOC-CHECK.md`「连声明根都没有 ⇒ 显式报错」——该式落在 `thincoder-core/doc-check/index.mjs` 的 `runDocCheck` 定根前置：`declaredRoot(root)` 取 `null` ⇒ 整清单走 §2.4，`gate` 面出一首行 `ERROR`、`report` 面抛可读错，两条都不静默跳过任何档 |

**数据事实核对**：本档唯一的数据断言 = 工作区锚下不止一个项目。取证 = 新进程直调 `projectRootView` 的读数（本档不预载候选数，读数随交付报出）。其余断言全部由读码得。

### 2.2 分组判（只换喂进去的根）

引擎在**分组之前**先定声明根：缺声明根 ⇒ 整清单走 §2.4 的 `ERROR`（不出现「部分组无根」）。声明根在 ⇒ 可判集 `checkFiles` 按 `rootOf` 分组，每组调一次既有 `checkAnchors(root_i, { files: group_i })`，命中按文件稳定序合并。

**另两条判据与根无关**：`checkParagraphs({ paragraphMax, lineMax, exemptZones, files: checkFiles })` 与 `collectLineRefs({ files: checkFiles })` 都不收根（读码取证）⇒ 全清单一次跑完，零改。

**为什么这样切**：分组只换喂进去的根，抽取式 ∥ 解析序 ∥ 面判这些判法内部不因分组而改（锚判据的跨仓三笔是另一笔改动）；跨项目清单在锚面等价于「两组各按自己的根判一遍」。

**弃案：把根做成 `checkAnchors` 的逐 token 参数**——那要改解析序内部（同轮记忆按根建、同名候选扫描根按根取），判法跟着动，与本档 §8 的边界相冲。

### 2.3 命中报面（跨项目清单怎么读）

- **verdict 只有一条**：一次调用一个答案。不按项目分 verdict——分节判 PASS 会让读者读到其中一节的 PASS，而另一节是 REFUSED。
- **单根清单**：**不附根行**；除本档头注列的两形（`未核 N 条` 与环引行）外，报面照旧（零回归的判据面见 §6 的 AC-2）。
- **≥2 根**：范围行追加根清单；每条命中 ∥ 跳过 ∥ 读不到行前置 `[<项目名>]`，行内路径**相对该档自身的根**显示。读回执的人据此分清是谁的账。
- **项目名 = 本次调用里能唯一定位该根的最短路径后缀**（段间以 `/` 分隔）：末尾一段在本次的根之间不重复 ⇒ 就是根目录名；重名（两个项目各有一个 `web`）⇒ 往前多取一段，直到各根互不相同，如 `[a/web]` ∥ `[b/web]`。**唯一定位的判据面 = 本次调用的根集**，不是全机路径——标签的职责是让读者分清是谁的账，两个同名根同时出现时必须分得开。

### 2.4 定不出根 ⇒ 显式 `ERROR`

- **触发条件只有一个**：调用方没有声明根（`root` 入参缺省 ∥ 空串 ∥ 非字符串）。**「声明根自身不是项目」不是触发条件**——普通目录、多项目工作区都能当声明根，照它判。
- **两层分界**：「调用方给了 `target`」（非空字符串，§5 KD-10）与「歧义」都判在**工具面入参**那一层；工具面交给引擎的 `root` 永远是**解析后的非空根**（`target` 缺 ∥ `null` ∥ 空串 ⇒ 工具面拒，见 §2 三种入参形；锚缺位 + 相对形 `target` ⇒ 拒、点名锚）。`§2.4` 只管**引擎入参**——直调引擎、`root` 给不出非空值才触发，两层不混。
- **报面形**（`gate` 面）：

```text
DOC-CHECK GATE: ERROR（无法定根 N 档）
本次没有声明根：声明根是这条判据的调用前置，缺它整清单不判（不出半份判定）
<档> —— 原因：<下表那一式>
```

- **逐档原因句：两式 + 相对条目一支**（按该档自己的读数取式，逐字照抄）：

| 该档的情形 | `<档>` 怎么显示 | 原因句（逐字） |
|---|---|---|
| 绝对路径条目，祖先链有 manifest | 条目原文 | `本次没有声明根，整清单不判——本档本可归 <该根>` |
| 绝对路径条目，祖先链至盘根无 manifest | 条目原文 | `祖先链至盘根无 PROJECT-MANIFEST.json，且本次没有声明根` |
| 相对路径条目（无根即无法定位） | 条目原文 | `本次没有声明根，整清单不判——本档是相对路径条目，无根无法定位` |

- **报文不得断言盘上为假的事**：只有该档祖先链**真的**没有 manifest，才许说「无 `PROJECT-MANIFEST.json`」；本可由 manifest 定根的档一律走第一式。三式都不提 `<base>`。
- **N 怎么数**：N = 清单独特条目数——去重键只认**可证明同一**的两类：绝对条目按归一后的绝对路径（Windows 大小写不敏感）、相对条目按原文。**相对条目与绝对条目之间不合并**：无声明根时没有基准能把两者归一到同一路径，拿 cwd 去归一就是本批禁的猜根。同一份档写成相对 ∥ 绝对两种形时至多数成 2——报面说的是「本次点名的条目数」，不冒充「实际档数」。
- 无声明根时**判不了「在盘 ∥ `.md`」**——这两个谓词要绝对路径，而相对条目的绝对路径正是声明根给的 ⇒ 报面不得写成「可判档数」。
- **行内路径**：无声明根 ⇒ 没有可相对的根，`<档>` 按**条目原文**显示，不套 `rel(base, …)`。
- `report` 面同样抛错（现状 report 面对不可判档就是抛错、整次零判定，同口径）。
- **不跳过、不出半份判定**：该面**零 `✗` 命中行**。判不了就是一次都没判，不得出成「有的判过了」。
- **为什么这是政策，不是公式的推论**：`rootOf` 的 `?? declaredBase` 只在「祖先链无 manifest」的档上落空——**一个有 manifest 祖先的档，没有声明根也本来就有根**（`owningProject` 沿祖先链取最近带 manifest 的目录，见 §2.1）。所以「整清单不判」不是公式算出来的结论，而是**刻意的一条政策**：声明根是调用的前置条件，缺它整清单不判，**即使部分档本可定根也不出半份判定**。理由两条：缺声明根时盘上的形是**整次不判**（`thincoder-core/doc-check/per-root.mjs` 的 `declaredRoot` 取 `null` ⇒ 整清单走本节），政策与它同向——把不可读的崩溃换成一个能读的拒绝；而半份判定在报面上分不出「这档干净」与「这档没判」。

### 2.5 域表：按各档所属项目根读

**判据**：一份档的指针按谁的项目声明判，它的域表就按谁的项目根读——域表与判定同一条规则、同一个根。

- **域表三项**：`docRoot` 各键（同名候选的扫描根）· `docRoot.batches`（批档基底根——决定「批档面互引」豁不豁免）· `index.publicRepos`（声明仓引用的**判据源**：那张表就是本仓出边，未声明即 `档缺`）。三项一律取自**该档所属项目根**的 `PROJECT-MANIFEST.json`。
- **`index.publicRepos` 的读取点**：值单源 = `thincoder-core/declaration.mjs` 的 `declaredPublicRoots`；解析层经 `thincoder-core/declared-repos.mjs` 的 `declaredOutEdges` 取三件（目录名 · 声明项原文 · 本机在盘）。判定面 `thincoder-core/doc-check/anchors.mjs` 不直读该键，只 import 解析层与出边投影。
- **第三项的按档根性（读码佐证）**：判法面的 `resolveDoc` 把**该档的判定根**当解析锚传进统一解析层；解析层以锚定 `start`，声明仓名集按 `start` 取；声明层的 `declaredPublicRoots` 再按入点取声明——三行盘上逐字见下方围栏。
- **声明源同时是环检的边集**：锚判据按被判档的组根走一遍出边图，每个节点读它**自己**的 manifest（兄弟仓各读各的，不借本根的声明）；无 manifest 的节点是叶仓，没有出边，走查在该节点止步。

```text
thincoder-core/doc-check/anchors.mjs · resolveDoc（base = checkAnchors 收到的判定根）
  return resolvePathTarget(base, token, { kind: "file", order: "root-first", referrer: refFile, declaredRepos: true, scanBases, session })
thincoder-core/path-resolve.mjs
  const start = resolve(anchor ?? ".")
  const declared = declaredOutEdges(start).find((e) => e.name === repo)
thincoder-core/declaration.mjs · declaredPublicRoots 的参数注
  @param {string} [cwd] 会话锚（项目根经 manifest.mjs 解析）
```

链上无声明根一环：分组后判定根 = 组根（§2.2）＝该档所属项目根，各档的 `publicRepos` 各读各的根，头句第三项由此成立；这条链原样保留。
- **落地形 = 组根**：`perRootGroups` 每组的 `root` 已经是该组各档的项目根，组内**只读一次** manifest（§3 的 `manifest` 注入），锚判与批档基底都吃这一份。
- **不并成并集**：各组各读各的，A 组的扫描根绝不进 B 组的候选集。并集只在「拿一个根盖整批」的旧形下才需要，而那个形本档已否（§2.1）。
- **无 manifest 的组**：该档祖先链无 manifest ⇒ 组根 = 声明根；声明根也没有 manifest（普通目录 ∥ 工作区）⇒ **域表为空集**。空集两向都是 fail-closed：批档面互引**不豁免**（token 照判，目标缺了就是 `档缺`）· 同名候选零提示（只影响提示，读数面）。**空集不会让门误判 `PASS`**——它只会让门更严。
- **不继承批档面的工作区并合**：`thincoder-core/agent-tools/batch-paths.mjs` 的 `batchDocBases` 在入参是工作区时会把下辖各项目的基底并起来；那一支服务批档自己的路径判定，本判据不吃它——传进去的根恒是组根。

**读数口径**：域表的读取必须能从报面上看出来——一个决定落地后看不出它做了什么，下次出问题就只能靠猜。

- 引擎返回 `domainTables: { root, manifest }[]`（每组一根、按路径升序；`manifest` = 该根读到了 manifest）。
- `report` 面出一块（位置 = 读面行之后、行数读数块之前；**不进 `hits`、不动 verdict、不改 `结论：` 行的位**）：

```text
域表读数：2 根（读 manifest 2 · 无 manifest 0）
  D:\teamcode\thincoder        读 manifest
  D:\teamcode\thincoder.com    读 manifest
```

- **出场条件**：只在「本次读到域表的根集 ≠ {声明根}」**或任一根无 manifest** 时出（7-13 的「无 manifest」行只有靠这半句才出得来）。单项目锚下根集恰是声明根且该根有 manifest ⇒ 两支皆假 ⇒ 零出，单项目零回归的判据面（AC-2）不破。
- 无 manifest 的根，该行写 `无 PROJECT-MANIFEST.json —— 域表为空（批档面互引照判 · 同名候选零提示）`：降级可见，不静默。
- `gate` 面不出域表读数：verdict 面只放判据。既有先例同向——`lines` 读数与批档面留痕行都只在报告态出。`gate` 面本批增的是 `未核 N 条` 列报（不进 `hits`、不动 verdict）与环引命中行；阈值与其余命中行形未动。

### 2.6 档名与扩展名识别面（F18 ∥ F19）

**机制的落点只有一处**：`thincoder-core/doc-check/anchors.mjs` 导出的一组常量与一个谓词。

- **常量**：`NAME_CH` · `EXT_PART` · `TOKEN_LEFT_GUARD` · `TOKEN_RIGHT_GUARD` · `DEFAULT_DOC_EXTS`。
- **谓词**：`isDocToken(token, exts)`——清单的判定落点（见下「清单落在哪一层」）。
- **四条抽取式由常量拼出**：锚 `ANCHOR_RE` ∥ 花括号组 `BRACE_GROUP_RE` ∥ 依据行 `CITE_RE_SRC`（三条同住该档）∥ 行号面 `NAME_RE`（住 `thincoder-core/doc-check/line-refs.mjs`，本批改吃这一组）。

**一个 token 要成为候选，两件同时成立：后缀落在生效清单内 ∧ 形分档（§2.10.3）**


```text
| 形 | 例 |
|---|---|
| 裸名 | `x.py` ∥ `JSON.parse` |
| 路径形 | `docs/x.py` ∥ `build/app.tar.gz` |
```

**判决依据两条，各管一条腿**：清单那条 = 用户 2026-11-09 裁定原话「统一一条腿，路径形也查清单；真文件名不在这条腿上，按真悬空处理」；形分档那条 = 用户 2026-11-11 00:09 裁向，判据句与代价单源 = §2.10.3。

**为什么清单两种形都要管**：先前那一版把路径形从清单里放出来，理由是「路径形本身就是最强证据」。实跑下来，那一支放进来的正是**版本区间与归档名**——`20.x/22.x` ∥ `tar.gz`，它们恰好都带路径分隔符。路径分隔符证明的是「这是一条路径」，不是「这是一份档」。

**为什么裸名还要再过一道形分档**：裸名是散文里最常见的一形，而代码表达式、字段访问、版本区间全落在这一形上。清单挡下末段不在清单里的那些（`parse` ∥ `env` ∥ `log` ∥ `map` ∥ `keys`）；末段在清单内的代码族裸名由形分档挡下（§2.10.3）。

两道任缺其一，这一族会**全部**成为候选并一律解不到 ⇒ `档缺`。现盘 `docs/core/design/CONFIG.md` 的「严格 `JSON.parse`」与 `docs/core/design/MCP.md` 的「其余 → `JSON.stringify`」就是活例子——这两处由清单挡下，形分档不看它们。

**清单 = 项目声明面；缺省值 = 引擎常量 `DEFAULT_DOC_EXTS`**：

- 键 = `index.docCheckExts`（数组，缺省 `[]` = 用引擎常量），按**该档所属项目根**读——与域表同一条规则、同一个根（§2.5）。
- **并集不替换**：项目写的项追加在缺省值之后（与 `codeExtensions` / `docExtensions` 同族语义）。拿它当「把判集收窄」用的路走不通，也不该通——窄判集是豁免面的事（§2.7）。
- 比较不折叠点、不分大小写：`JSON` 与 `json` 同项，`.md` 与 `md` 同项（书写面允许带前导点）。
- **报面读数一行，只在该仓写了这一项时出**：`扩展名清单：缺省 + 本仓 N 项`。不进 `hits`、不改 verdict；没写这一项的仓零出 ⇒ 单项目零回归面不破。

**`DEFAULT_DOC_EXTS` 的取形六条**：

- **F19 点名的必须在**：`py` ∥ `csv` ∥ `txt` ∥ `sql` ∥ `xml`——AC-17 的判据钉在这几个后缀上，缺一项该条当场红。
- **改前认得的 12 项全留**：`md` ∥ `mjs` ∥ `cjs` ∥ `js` ∥ `json` ∥ `css` ∥ `html` ∥ `svg` ∥ `yml` ∥ `yaml` ∥ `sh` ∥ `ps1`。退役闭集是把它换成可配清单，不是把已经认得的后缀扔掉（扔掉即零回归面破）。
- **真实文件类型补入**：`ts` ∥ `tsx` ∥ `jsx` ∥ `vue` ∥ `rb` ∥ `go` ∥ `rs` ∥ `java` ∥ `kt` ∥ `toml` ∥ `ini` ∥ `conf` ∥ `proto` ∥ `ico` ∥ `git` ∥ `db` ∥ `pem` ∥ `pub`。**完整清单只住 `DEFAULT_DOC_EXTS` 一处**，本档不复制第二份字面。
- **代码表达式 ∥ 字段访问的末段一律不进**：`parse` ∥ `stringify` ∥ `env` ∥ `log` ∥ `map` ∥ `lock` ∥ `keys` ∥ `filter` ∥ `join` ∥ `slice` ∥ `all` ∥ `set` ∥ `get` ∥ `has` ∥ `push` ∥ `then` ∥ `catch` ∥ `timer`。
- **单字符后缀不入**（用户 2026-11-09 裁定）：`.x` 正是 `20.x/22.x` 的来源。**代价如实**：真实单字符后缀 `.c` ∥ `.h` ∥ `.r` 从此永久不成候选，方向是漏报；要判这类路径，出口是 §8 的两条既有写法（围栏块 ∥ 目录形），不是把单字符后缀请回清单。
- **归档内层不入**：`tar` ∥ `gz` ∥ `zip` ∥ `bz2` ∥ `xz` ∥ `7z` ∥ `tgz` ∥ `rar` 不单列；末段后缀取法 ⇒ `build/app.tar.gz` 的末段是 `gz`，不在清单 ⇒ **整串不当档名**。

**生效清单怎么拼 · 这两条坐在哪**：`生效清单 = DEFAULT_DOC_EXTS ∪ 该档所属项目根的 index.docCheckExts`，并集之后过一次取形过滤（单字符后缀 ∥ 归档内层一律剔除）。

- **过滤坐在清单装配处**（`runDocCheck` 拼出本次调用的清单那一步），不在谓词里：谓词 `isDocToken` 只按字面查这张已过滤的表，不另设第二支。
- **项目自己写进去的项同样被剔**：写 `x` ∥ `tar` 与不写，读数逐字相同。不另设报面句、不逐条点名。

**划界 = 「认错了东西」与「认对了、盘上没有」**：

- **不进清单的** = 认错了东西：`JSON.parse` 是代码表达式、`arr.map` 是字段访问、`20.x` 是版本号、`build/app.tar.gz` 是归档名。它们不是文档名，认了就是误报。

- **进清单的** = 认对了而盘上没有：它们**真的指向了盘上没有的路径**。工具把这件事说出来是它的职责，说不出才是失职。报告面因此判 `档缺`，文档侧的出口是 §8 的两条合法写法。这一族的举例（真悬空，写进正文会判 `档缺`）：

```text
build/icon.ico   cert.pem   memory.db   org/repo.git   兄弟仓源码路径
```

**形护（`EXT_PART`）与清单各管一段**：形护判「这个后缀长得像不像后缀」——`1.5` ∥ `v2.0` ∥ `192.168.1.1` 的扩展名首字符是数字，抽都抽不出来；清单判「这个后缀算不算本项目的档」。两道都过才是候选：缺形护则数字形进候选，缺清单则代码表达式进候选。

```text
NAME_CH    = \p{L}\p{N}_.\-               名字字符类：Unicode 字母与数字（含中日韩）+ 原 ASCII 符号集
EXT_PART   = \.[A-Za-z][A-Za-z0-9]{0,9}   ASCII 点 + 首字符字母 + 长度 1–10
左界       = (?<![\p{L}\p{N}_.\-\\/@<>])   不得从更长的名字 ∥ 路径中间起抽（四条同取一份定义）
右界       = (?![\p{L}\p{N}_])             扩展名后紧邻字母数字 ⇒ 不是完整 token（四条同取一份定义）
构造       = new RegExp(<式>, "gu")        \p{…} 只在 u 标志下成立；四条抽取式同加
```

**清单落在哪一层（形护进正则，清单进谓词——两条各坐一处）**：

- **形护进正则**：它是**形**，对所有 token 一个标准、可写成一条式。且抽出再丢会动归属窗——`1.5` 先被抽出再被丢掉，那一行里其余 token 的行号坐标归属跟着变。
- **清单进谓词**：它是**项目声明**，随根变、读不到写不进一条全局式；生效面也在报面可见（该仓写了清单就有那行读数）。被挡下的 token 不逐条列——数量大，列出来正是真命中被淹没的成因。
- **落点 = `isDocToken(token, exts)`**，与 `docNameExemption` **同一批调用点**：锚 ∥ 花括号 ∥ 依据行 ∥ 行号面四处，各加一次同形判断。
- **谓词里两条腿同坐一处**：清单这条腿只看 token 末段最后一个点之后的那一段，**不分**有没有目录段；形分档那条腿恰好就按有没有目录段分两族（判据 = 本档 §2.10.3）。两条都落在 `isDocToken` 里，不存在绕过形分档的第二条判路。

**为什么边界对也进导出面**：今天 `ANCHOR_RE` 与 `NAME_RE` 是两条各自写的正则——名字字符类两处各一份字面，左界也各一份，且两处已经不同（`TOKEN_LEFT_GUARD` 含 `<>`，`NAME_RE` 那条不含）。真正共用住的只有扩展名枚举一项。

本批把常量与边界对一并导出，四条抽取式从此只有一个定义处。依赖方向不变：`line-refs.mjs` → `anchors.mjs`，它本就 import `docNameExemption`。

**收敛带来的一处行为差（如实）**：`NAME_RE` 的左界改用 `TOKEN_LEFT_GUARD` ⇒ 名字前紧贴 `<` ∥ `>` 的 token 不再被抽。方向是漏报，且只是把两处既有写法并成一处——留两处则两处迟早各改各的。

**为什么中文句读吞不进来**（三条，逐条可判）：

- **句读不在名字字符类内**：`。，、；：？！「」『』（）《》【】` 属 `\p{P}`，不在 `\p{L}\p{N}` 之内 ⇒ 一律截断名字，既做不成名字的一段，也做不成扩展名的首字符。
- **扩展名分隔符只认 ASCII 点**：全角 `。` 与 `．` 都不是分隔符 ⇒「需求档。」「设计档，」没有扩展名 ⇒ 不构成候选（F18「裸词不得被当成档名」）。
- **左界挡住「从中间起抽」，挡不住「从头起抽一条更长的」**：名字串从中间截断那种抽法不会发生；但一段中文散文后面紧贴的档名，会**连前面那段汉字一起**成一个候选 ⇒ 解不到 ⇒ `档缺` 一条。这是**多报**，不是漏报；出口在写法面（下「紧贴中文的档名」块）。

**`u` 标志的两条附带后果（写清，不留给实现席猜）**：`\p{…}` 不带 `u` 是字面量 `p{…}`，整条抽取式会静默变成另一种式——四条必须同加 `u`；`u` 下过度的转义会在模块求值时抛错（fail-loud 在载入面，比抽出错字好）。

**紧贴中文的档名：多报一条整段 token（实测）**。散文里紧贴的档名若前面没有分隔（空白 ∥ 标点 ∥ 反引号 ∥ 行首）⇒ 该档名与前面那段汉字**一起**成一个候选，解不到 ⇒ `档缺` 一条。**方向是多报**，不是漏报——左界挡的是「从更长的串中间起抽」，挡不住「从串头起抽一条更长的」。

实测三读（夹具全程在系统临时域，零落仓；示例住围栏块，判据整块跳过）：

```text
详见在盘档.md。       候选 = 详见在盘档.md（整串，连前面的汉字）  ⇒ 档缺 1 条
详见 `见在盘档.md` 。  两侧有反引号 ⇒ 候选 = 见在盘档.md 在盘     ⇒ 零命中
详见 见在盘档.md 。    两侧有空格   ⇒ 候选 = 见在盘档.md 在盘     ⇒ 零命中
```

**写法出口（给出怎么写，不只是记一条缺陷）**：提到档名时**用反引号包住**，或**与前后汉字留一个空格**；行首起写的档名本来就零命中。

**为什么不设回退支**：本档**不猜名字从哪个汉字开始**——词法上分不开「真中文档名」与「汉字紧贴档名」，回退支一开，任何真悬空都有了一条洗白的路（与 §2.2 弃案同形）。


**仓外路径族：真悬空，照报（不是误报）**。清单把「认错了东西」那一族挡住之后，剩下一批**真的指向盘上没有的路径**的写法：构建产物 · 运行时数据 · 凭据 · 兄弟仓源码 · 外部仓库。工具把「指了、盘上没有」说出来正是它的职责。这一族的举例（真悬空，写进正文会判 `档缺`）：

```text
build/icon.ico · memory.db · cert.pem · MiMo-Code/packages/opencode/src/acp/agent.ts · org/repo.git
```

文档侧的出口是**两条既有写法**（§8）：写进围栏块（逐字证据，判据整块跳过）∥ 写成目录形（`build/`，不带后缀、不成候选）。两条都不新增机制，也不是豁免——是同一个事实换一种写得对的形。

**豁免谓词的词干判定 = `isExtension`**：末段算不算扩展名由扩展名定义判（`isExtension(ext)`），扩展名定义只此一处——豁免谓词与抽取面不得各持一份（F12 单源）。

**「词 + 点 + 字母」这一族按清单分流（如实）**：

```text
e.g ∥ i.e          .g ∥ .e 不在清单 ⇒ 本批起不再是候选（改前也不是——闭集本就不含）⇒ 零新增
Node.js ∥ Mr.Smith  Node.js 的 .js 在清单内 ⇒ 候选（改前也是候选）；Mr.Smith 的 .Smith 不在清单 ⇒ 不再是候选
```

**最近先例（对齐 ∥ 偏离）**：

- **对齐 `thincoder-core/doc-check/anchors.mjs` 的边界对**（既有私有件 `TOKEN_LEFT_GUARD` ∥ `TOKEN_RIGHT_GUARD`，现由锚抽取式消费）：本批把同一对边界转导出面、四条抽取式同吃一份——照既有写法，不新造第二个定义处。
- **对齐 `index` 族的扩展名键**（`index.codeExtensions` ∥ `index.docExtensions`）：`index.docCheckExts` 照抄同族三件事——`index` 子键 ∥ 数组 ∥ 与缺省并集只增不减。
- **偏离：扩展名定义从闭集改成「清单 + 谓词」两段**。偏离理由 = 能力面失败，不是口味——闭集认不出 `.py` 一类真后缀（F19 要的正是这一类），而放开成「任意点 + 字母」会把 `JSON.parse` ∥ `20.x` 淹进候选（F18 的误报为零当场破）；闭集与全放开之间，只剩「可配清单 + 形护」这一条能同时满足两条需求。

**扩展名枚举退役的 D14 清扫**（口径 = `docs/core/design/DOC-DISCIPLINE.md` §1 D14）：

- **族怎么认**：这一族 = doc-check 的扩展名枚举——**无前导点、数组形**（`["md", "mjs", …]`），消费面 = 抽取面四条 + 豁免谓词的词干判定。
- **域**：跟踪面的 `*.md` 与 `*.mjs`，扣 `docs/batches/**`（一次性记录面，随批删）与 `_archive/**`。
- **同名不同族，域内排除**：`thincoder-core/index-discover.mjs`（带点 `Set`，索引面档发现）· `thincoder-core/memory/schema.mjs` 与其再出口 `thincoder-core/memory.mjs`（带点 `Set`，记忆面）。它们与退役件只是同名，扫进去就是误伤。
- **逐处三类处置**：`delete`（句已读不成）∥ `re-point`（改指 `DEFAULT_DOC_EXTS` ∥ `isExtension`）∥ `转台账`（写权不在本批的档，登记一行并把到期条件写进证据）。
- **预期残留数住批档 §2**（D12：规范面不载绝对读数）；收口判据 = 实测命中 = 批档 §2 预先写下的那个数，差一条即未闭。

**先例三问**：

- **在哪**：`thincoder-core/doc-check/anchors.mjs` 的 `TOKEN_LEFT_GUARD` ∥ `TOKEN_RIGHT_GUARD` ∥ `ANCHOR_RE`（三个既有件，本批改值不改位）。

**数据事实核对**：本面**有数据断言要读盘**——「新式在现盘 `docs/**` 上新增多少候选、其中多少解不到」只能实跑得出，读码得不出。取法 = 对 `docs/**` 逐行按新抽取式抽 token（围栏块整块跳过）并与旧式 token 集作差，再逐条判存在性。本档只留关系句：清单把代码表达式族清零 ∥ 路径形留下的散文路径族清单收不窄；读数随交付报出。

**示例与判据的分界（围栏块准入判据 · 本档这一笔的凭据）**：

- **准入四类**：围栏块里只放 ① 示例枚举（路径 ∥ 名字 ∥ 命令）· ② 读数与实测结果 · ③ 逐字证据（拒文 ∥ 日志 ∥ diff ∥ 前后对照）· ④ **用例表**（夹具枚举 + 逐例的期望读数）。
- **用例表为什么算准入**：它的「输入」列就是夹具枚举、「期望」列就是逐例期望读数——两类合一。**移出围栏不可行**：夹具路径本就不在盘上，落回正文当场判 `档缺`（本节两条「真悬空」族已把这件写明），而围栏存在的理由正是这个。
- **不准入一类**：任何一句**判据**——「什么算命中 ∥ 什么不判 ∥ 出口是什么」。判据句一律住正文，示例住围栏。
- **判法（逐块一条）**：读该块第一句——它在说「什么必须 ∥ 什么不许 ∥ 因此照报」，那是判据句 ⇒ 移出围栏；它在列举或记录一次读数 ⇒ 留在块里。
- **本档围栏块共 15 块，逐块判过（清单如下）**：块内只放准入四类的内容；判据句（「进清单的」∥「仓外路径族」∥ §5 的「独立参考系结论」三句）住正文，块内只余举例。

### 2.7 逐条豁免登记与假阳第三档（F20 ∥ F21）

**声明面**：`PROJECT-MANIFEST.json` 的 `index.docCheckExemptions`（数组，缺省 `[]`）。**按档所属项目根读**——与域表同一条规则、同一个根、同一次 `readManifest`（§2.5），所以一个仓的登记不会替另一个仓放行。键位与名先例 = `index.excludePaths`（`docs/core/design/MANIFEST.md` §2.2）：同 `index` 族、同一份归一，差别只在谁吃这张表。

**一个条目长什么样**（写法例）：

```json
{ "index": { "docCheckExemptions": [
  { "file": "docs/core/design/X.md",
    "kind": "锚·档缺",
    "text": "docs/planned/NEW.md",
    "why": "规则要求计划新建件先写路径（裁定依据 = 用户 2026-11-09 15:15）",
    "review": "2027-01-31" }
] } }
```

**五个字段，缺一无效应**：`file`（项目根相对路径）∥ `kind`（判据类，闭集见下表）∥ `text`（命中文本，见下表）∥ `why`（为什么不算违规——裁定依据）∥ `review`（何时复审）。

- **缺一个 ∥ 形态不对 ⇒ 该条不生效**（命中照拦），并在报面点名。
- **条目形态在消费点判，不进 `validateManifest` 的 `errors`**：一个写坏的条目不该把整份 manifest 打掉——manifest 不可用 ⇒ 域表空集 ⇒ 批档面互引不豁免，代价见本节末第三弃案。

**命中怎么被稳定识别**（本节判据）：**`file` + `kind` + `text` 三合一全等**。不用行号——插一行整片失效，豁免就成了一次性的。

| `kind` | 命中来源 | `text` 取什么 |
|---|---|---|
| `锚·档缺` | 锚面解不到 | 被抽出的那个 token 原文（含目录段，逐字） |
| `锚·节缺` | 目标档无该节 | `<token>§<节号>` |
| `锚·引缺` | 引文不是目标档里的连续子串 | `<token>「<引文>」`（引文逐字，不折叠空白） |
| `段·文字太长，难于阅读` | 段长判据 | 该段整段原文（首尾去空白，内部逐字） |
| `行·行太长` | 行长判据 | 该行整行原文（首尾去空白） |
| `行号坐标` | 行号坐标判据 | 该处所在行的整行原文（首尾去空白） |

- **`file` 比法**走 `pathKey`（与 §2.6 的 `pathKey` 同一条平台规则）；`kind` ∥ `text` 逐字比，**零折算**——不折空白、不换全半角、不换算大小写。折算一次，`text` 就只须「大致对」，判据随之失效（口径同 F13 的引文面）。
- **命中文本被改过 ⇒ 登记失配 ⇒ 照拦**（fail-closed）：裁定是对那一段文字的裁定，原文一变，被裁定过的那处就不存在了。
- **`环引` 不可登记**：它是仓级命中（无行号、无档内文本），假环意味着 `index.publicRepos` 的声明本身错了——那是改声明，不是登记一个假阳。

**三条判据同判，判法本体零改**：`exempted` 的分类在**装配处**做（`thincoder-core/doc-check/index.mjs` 的 `runDocCheck`），在 `perRootGroups` ∥ 三条判据都跑完之后。`thincoder-core/doc-check/anchors.mjs` ∥ `paragraph.mjs` ∥ `line-refs.mjs` 三档因此**不认登记**——它们只产命中，分类在装配处做。本批在这三档的改动只有抽取面（§2.6）与 `paragraph.mjs` 的载荷字段 `text`（§4），判据本体零改。

- **为什么不在判法里做**：段长 ∥ 行号坐标两条也产命中，登记面必须对三条同判；放进锚判法就只覆盖一条。
- **怎么找自己那根的表**：逐条命中按该条自己的 `file` 求 `rootOf(该档, 声明根)`，取该根的登记表——`readOf` 的记忆体，与域表**同一次读**（§2.5 KD-7）。
- **verdict 只吃未豁免的那批**：`hits` 三数（锚 ∥ 段 ∥ 行号坐标）与 `hits.total` 只数未登记的条目；`exempted` 另成一桶（与 `unverified` ∥ `unreadable` 同层：读数，不进 `hits`、不改 verdict）。
- **写前门同吃，这不是新机制**：`thincoder-core/tools/doc-write-gate.mjs` 走同一个引擎 ⇒ 引擎返回什么它就认什么。效果 = 一段正文若必须写一个尚不存在的路径，登记后仍可编辑；不登记则每一笔写都拒（F14 的死锁面）。

**报面（两问法同出 · 不进 `hits`、不改 verdict）**：

```text
豁免 3 条（已裁定假阳，不阻断交付）：
  [projA] ✗ 锚·档缺 docs/design/X.md:12 docs/planned/NEW.md —— 规则要求先写路径（复审 2027-01-31）
```

- **F21 的四项一个不少**：哪一条（`kind` + `text`）∥ 哪一份档（`file`）∥ 理由（`why`）∥ 复审（`review`）。
- **N = 0 时不出块**：未登记任何豁免的仓，两面报面与改动前逐字相等（零回归）。
- **失配登记照出**：`登记未命中 N 条（原文已变或已不在判集，复核后删）`——登记跟着一条消失的命中活下来，就是下一轮没人敢删的残骸。
- **`report` 末行的清句要带上它**：未登记的命中为 0 而 `exempted` 非 0 ⇒ `结论：0 条命中（… 均清）；已裁定假阳 N 条（见上，不阻断）`——「均清」旁边摆着一列已裁定条目，不读成「这里什么都没有」。

**三个声明面并存，各管一件事**（F3 · 2026-11-09 裁定）：

| 面 | 键 | 管什么 | 行为 |
|---|---|---|---|
| 扩展名面 | `index.docCheckExts` | **哪些 token 算档名候选** | 后缀在清单内才是候选；裸名另须后缀落在文档名族 `BARE_NAME_EXTS` 内，带目录段的一族同判（§2.6 ∥ §2.10.3） |
| 排除面 | `index.docCheckExcludePaths` | **入不入判** | 落进去的档不入判、不出命中；全落进去则 `PASS`（**本批不改**） |
| 豁免面 | `index.docCheckExemptions` | **拦不拦** | 档照判；已登记的命中照列、不阻断 |

- **一句话分清**：排除是「**不看**该档」，豁免是「**看了、已裁定、不拦**」。两者不能互相替代——排除把一片区域变盲区，登记是对一条已看过的命中下结论。
- **判决依据** = 用户 2026-11-09 15:36「维持免检放行不动」＋ 15:38「允许把一片故意变成盲区是我们提供的功能，用不用是他们的选择」。
- **这是明示的取舍**：把一片区域交给排除面，就是选择不去看那片区域；工具照做，**不替使用方决定该不该这么做**。
- **本批的引擎改动因此是加法**：判集过滤器 `splitExcluded` ∥ `excluded` 桶 ∥ `exemptedAll` 三处**一律保留**；新加的是装配处的豁免分类（本节上一段）与 `exempted` 桶。
- **排除面的报面形零改**：`排除 N 档（manifest 排除面命中，未判）` 行 ∥ 全排除时的首行 `PASS` ∥ `范围` 行括注——三处逐字保留。
- **一面不替另一面下结论**：全排除 ⇒ 0 档受检的 `PASS` 是排除面的正确行为；有档受检而另有登记 ⇒ 豁免块列出、首行按**未登记**那批定。

**先例三问**：

- **在哪**：`index` 族（`index.excludePaths` ∥ `index.publicRepos` 同族），读取点 = `thincoder-core/manifest.mjs` 的 `readManifest`。
- **叫什么**：`docCheckExemptions`（键名自带消费面，与旧排除键同式命名）。
- **谁在用**：装配处一处读（引擎）∥ `thincoder-core/tool-docs/manifest.md` 的键面说明 ∥ 报面豁免块。

**公共源勘查**：同 §2.6 那一次勘查（本仓相关 3 处、两个公共仓无一相关）——豁免登记的形在公开源里没有可对齐的先例，本面按 F20 ∥ F21 的字段自建。

**数据事实核对**：本面**无需读盘**——新键本批才设计，盘上不可能已有登记。旧键的现存值仍参与判定（首表的排除面），但它本批不改，也不进本节任何判据。

| # | 决策 | 弃案 | 理由 |
|---|---|---|---|
| KD-R1 | 名字字符类 = `\p{L}\p{N}_.\-`，扩展名式 = `\.[A-Za-z][A-Za-z0-9]{0,9}`，两条护栏都写进正则 | 抽出 token 再用谓词过滤 | 四条抽取式共用一份（写谓词要写四份）；且抽出再丢会动归属窗与区间占位，计数面跟着漂 |

- **AC-R1（非 ASCII 档名判得出 · F18 ∥ AC-16①）**：三例夹具——指向不存在的中文档 ∥ 中文目录下的档 ∥ 纯中文件——在 `report` 面各出一条 `档缺`。判法：把名字字符类换回 `[A-Za-z0-9_.\-]` ⇒ 三例全绿、本条红。
- **AC-R2（普通中文词误报为零 · F18 ∥ AC-16②）**：一份正常中文正文（含「需求档」「设计档」「依据设计档」一类普通词与中文标点）跑 `report` ⇒ 命中 0 条。判法：把扩展名式放宽成「任意点 + 任意字符」⇒ 该份正文出现命中、本条红——这条是「误报为零比判得出更难」的读面。
- **AC-R3（扩展名不闭集 · 数字不成候选 · 路径形照查清单 · F19 ∥ AC-17）**：带目录段、指向不存在的 `docs/<名>.py` ∥ `docs/<名>.csv` ∥ `docs/<名>.txt` 各一处 ⇒ 三例全红；同一份正文里 `1.5` ∥ `v2.0` ∥ `192.168.1.1` ⇒ 零候选；路径形而后缀不在清单（`docs/notes.xyz` ∥ `20.x/22.x` ∥ `build/app.tar.gz`）⇒ 同样零候选。判法：扩展名式去掉「首字符字母」那一半 ⇒ 数字形变候选、本条红；闭集写回 ⇒ `docs/<名>.py` 那例转绿、本条红；**把「路径形不看清单」写回** ⇒ 那三例成候选、本条红。
- **AC-R4（清单可配：按档根读 · 并集不替换 · 读数行 · F19）**：夹具两项目甲（`index.docCheckExts` 写一个缺省清单里没有的真后缀，如 `tsv`）与乙（不写该键）。甲档引不存在的 `docs/<名>.tsv` ⇒ `档缺`一条；乙档引同一 token ⇒ **零命中**（清单按档所属项目根读，甲写的不替乙生效）；同一夹具把甲的键改成 `["md"]` ⇒ 指向不存在的 `docs/<名>.py` 仍判 `档缺`（并集：缺省项照旧生效）；再把甲的键加上取形外的两项 `x` ∥ `tar` ⇒ 甲档引 `docs/<名>.x` ∥ `build/app.tar` 仍**零命中**（装配处剔掉，写了与不写同读数）。`report` 面：甲出`扩展名清单：缺省 + 本仓 N 项`一行，乙零出。判法：并集改成替换 ⇒ `docs/<名>.py` 那例转绿、本条红；清单按声明根读一次 ⇒ 乙档的 `docs/<名>.tsv` 成候选、本条红；把取形过滤挪进谓词之后（或整条不过滤）⇒ `docs/<名>.x` ∥ `build/app.tar` 成候选、本条红。

**AC-X1（登记后不阻断且仍列出 · F21 ∥ AC-19①）**：一条真悬空指针登记为假阳 ⇒ `gate` 首行 `PASS`，且回执出豁免块，四个字段齐全（`kind` + `text` ∥ `file` ∥ `why` ∥ `review`）。判法：把登记表读成空 ⇒ 首行变 `REFUSED`、豁免块零出、本条红。
- **AC-X2（撤销后重新计入 · F21 ∥ AC-19②）**：删掉那条登记再跑 ⇒ 同一处回到 `REFUSED（锚 1 条）`，豁免块零出。判法：把登记做成「一经命中永久放行」的缓存 ⇒ 本条红。
- **AC-X3（两面并存，各管一件事 · F20 ∥ AC-18）**：三组夹具。① 某档被目录排除 ⇒ 不入判、零命中、回执出 `排除 N 档（manifest 排除面命中，未判）`；② 同一档不排除、某条命中已登记 ⇒ 该档照判、豁免块列出该条、首行 `PASS`；③ 两面对同一档同时作用 ⇒ **排除优先**，该档不出现在受检清单里、也不出现在豁免块里。判法：删掉 `splitExcluded` ⇒ ① 红（该档的命中冒出来）；删掉豁免分类 ⇒ ② 红（首行 `REFUSED`）。
- **AC-X4（识别键不用行号）**：同一登记，先把命中所在一行之上插入一行空行 ⇒ 仍豁免（首行 `PASS` + 豁免块在）；再把该段 ∥ 该行文字改一个字 ⇒ 转回 `REFUSED`，且回执出 `登记未命中 N 条`。**三类各跑一遍，`行号坐标` 这一类同判**（它的键 = 整行原文，改行内任一字符即失配）。判法：把识别键换成 `file` + 行号 ⇒ 前半变 `REFUSED`、本条红；`行号坐标` 那一类的键换成坐标串 ⇒ 该类的「改一个字」半红。
- **AC-X5（零登记零变化）**：manifest 无 `docCheckExemptions` 键 ⇒ 两面报面与改动前逐字相等，豁免块与失配行零出。

```text
| 边界 | 路径形且后缀不在清单：`docs/notes.xyz` ∥ `20.x/22.x` ∥ `build/app.tar.gz` | 不成候选、零命中——路径分隔符本身不是候选资格 |
| 边界 | 中文散文紧贴一个在盘的中文档名（前面无分隔） | 整串成一个候选（前面那段汉字 + 档名）⇒ 解不到 ⇒ **`档缺` 一条（多报整段 token）**；同例改成反引号包住 ∥ 与前后汉字留一个空格 ⇒ 各零命中（两种写法出口由此钉住） |
| 正常 | 一条真悬空登记为假阳，跑 `gate` | 首行 `PASS`；豁免块一行，`kind` ∥ `text` ∥ `file` ∥ `why` ∥ `review` 齐全（AC-X1） |
| 边界 | 同一夹具删掉登记再跑 | 首行 `REFUSED（锚 1 条）`；豁免块零出（AC-X2） |
| 边界 | 登记后在命中所在一行之上插一行空行 | 仍 `PASS` + 豁免块在（AC-X4 前半） |
| 错误 | 登记后把该档里那段文字改一个字 | 转 `REFUSED`，且出 `登记未命中 N 条`（AC-X4 后半） |
| 错误 | 登记条目缺 `why` ∥ `review`，或 `kind` 不在闭集 | 该条不生效、照拦，报面点名；manifest `ok` 仍为真（KD-X3） |
| 边界 | 同一档既落在排除目录内、又有一条命中被登记 | 排除优先：该档不入判、零命中，豁免块不出该条（AC-X3 ③） |
| 边界 | manifest 无 `docCheckExemptions` | 两面报面与改动前逐字相等，豁免块与失配行零出（AC-X5） |
```

#### 边界（本批不做）

- **不改三条判据本体**：阈值 ∥ 命中类 ∥ verdict 词 ∥ 抽取式的解析序一律不碰；本批动的是**抽取面的字符类与扩展名式**、以及**豁免面**。
- **不动 `doc_check` 的调用面**：batch 工具机械点 ∥ 收口面 ∥ 端壳用法零改；`exempted` 是引擎返回值多一桶，消费面读 `hits` 的口径不变。
- **不猜名字的起点**：中文散文紧贴的档名会连前面的汉字成一个 token、判一条 `档缺`（多报方向；写法出口 = 反引号 ∥ 空格）；不设「从哪个汉字开始」的回退支。
- **不给登记设机检权限面**：机检判不出「这个裁定是不是真的裁定过」，`why` 的真伪归评审；本批只保证「登记了就可见、撤销了就回来」。
- **不把豁免做成按类**：`kind` 是判据类、`text` 是逐处文本，两者都不接受通配 ∥ 前缀 ∥ 目录（F20 的立条边界）。
- **不加新工具、不引 SQLite**：登记住 manifest 一个数组，零新存储；端壳静态闭包零 `node:sqlite`（W8 契约②）因此不涉及。

### 2.8 `doc_check` 读 manifest 哪几处（单源）

**这是唯一清单**：另两处（`docs/core/design/DOC-DISCIPLINE.md` §3.20 ∥ `docs/core/design/MANIFEST.md` §2.2）只留指针，不重述条目。

**五处，都是声明面，都不是判据参数**：

| # | 键 | 改的是什么 | 读点 |
|---|---|---|---|
| 1 | `docRoot`（各文档根 + `batches`） | **域怎么定**——同名候选的扫描根 ∥ 批档基底根 | 按组根一次 `readManifest`，注入判法面与批档基底（§2.5） |
| 2 | `index.publicRepos` | **域怎么定**——声明仓 = 出边表 = 环检边集 | 同一份 manifest；解析层经 `thincoder-core/declared-repos.mjs` 的 `declaredOutEdges` 取三件（§2.5） |
| 3 | `index.docCheckExcludePaths` | **入不入判** | 判集过滤 `splitExcluded`（§2.7） |
| 4 | `index.docCheckExts` | **哪些 token 算档名候选** | 清单透传给判法面的 `isDocToken`（§2.6） |
| 5 | `index.docCheckExemptions` | **拦不拦** | 装配处分类：`hits` 与 `exempted` 两桶（§2.7） |

- **判据参数一处不读**：阈值与豁免谓词恒为内置常量 `DOC_CHECK_BUILTINS`——「不读 manifest」只对**参数面**成立，对上表五处不成立。

### 2.9 判域与判据本体：一条判据，判它该判的那段字节

这条链上有四个面读同一套判据：写盘门、批档 `edit`、批档收口、`doc_check` 本面。而「哪段字节算在判域里」四面各家一套 —— 本节的六项缺陷全部落在这一处，不是六个独立的错。

#### 2.9.1 统一判据（②③⑥ 三题共答）

**判域 = 本次写入所产出的那段文本，加上它落盘后读者所见的那个完整单元。**

三条推论：

1. **阻断集跟「本次写入」走，不跟「档」走。** 三个面各有自己的「本次」，阻断集就是那一段：写盘门 = 本次写入扩区后的片段区；批档 `edit` = 本次替换区；收口 = 本批改动区（取法见 §2.9.4）。批档 `edit` 与收口面的档内其余部分命中进读数桶（存量句形），照列、不阻断；写盘门只判本次改动区，不出存量读数。
2. **改动区的边界必须让判据本身成立。** 锚判要解析得到、段判要算得对，改动区就得落在完整段落 ∥ 完整围栏块 ∥ 完整表格行上。扩区表因此是判域的一部分，不是装饰（① 修的正是它）。
3. **与本次写入无关的事实不进判据输入。** 仓级声明事实（`环引`）只有在本次判集的解析路径经过它时才算本次命中；别的仓、别的批、别的档的存量债不进阻断集。

**② 的答** —— 一个仓的声明错误不该拒掉别的仓的写入。`环引` 是声明面的事实，今天在每组无条件产生并直接入 `hits`，不看本次判集有没有人指向那个环。判集里出现一个 `PROJECT-MANIFEST.json` 档名 token 就足以让环被算出来并被拦。

**③ 的答** —— 收口按本批改动区判，整档出读数。理由不是「宽松一点」，是**整档判对本批没写过的字节是第一遍、对本批写过的字节是第二遍**：每一次写入落盘时都已在自己的改动区判过，整档重判对本批产出零新增保护，对别人的存量债却是一张否决票。既有债的处置权在它作者手里、已由台账持有，收口人不是它的作者。

**⑥ 的答** —— 两段互引同一条失效引文时，**顺序自由**。本段的改动只判本段的区，另一段那条失效引文不进本次阻断集 ⇒ 任一段先落都成立。先落的那段若顺手修了那条引文，后落的那段自然更轻。这不是绕路：绕路把问题留在原地，判域收敛把问题留在它该在的地方。

#### 2.9.1.1 四个机制的先例 ∥ 命名 ∥ 公共源勘查

四个机制各带取证面写下来：先例（对齐哪件 ∥ 偏离哪件 ∥ 为什么）· 名字（在哪 ∥ 叫什么 ∥ 谁在用）· 公共源（查过哪几处、有没有相关）。「已查无」也写——留白会被读成「没查」。

**最近先例（对齐 ∥ 偏离）**：

- **对齐 `thincoder-core/agent-tools/batch-gate.mjs` 的触达账腿**（改动区取自 git 基线、四态判定、区外存量只出计数）：③ 的收口面照这一件写，不新造第二套「什么叫本次改动」的判法。
- **偏离 `thincoder-core/doc-check/paragraph.mjs` 的 `isExecutableLine`**（行谓词：行内任一码段像命令 ⇒ 整行算可执行）：⑤ 要的是段谓词。偏离理由 = 能力面失败，不是口味——行谓词当段谓词用，同一行另一处反引号路径被整行连坐，漏报方向当场成立。
- **`环引` 入闸挂判集指向：已查无先例**（检查面 = 本仓 `thincoder-core/**` 与 `docs/core/design/**` 的「环引」族）——既有写法是「算出来就入 `hits`」，没有「先问本次判集指不指向」的一支，本批首建。
- **偏离既有存量句**：既有句是「触达账存量命中 N 条——不属本次改动区，不阻本次写；收口面整档判」。③ 的存量读数取它前半句的形，砍掉后半句——收口面本批起也不再整档拦，留着后半句就是两句互相拆台。

**公共源勘查**（范围 = 本仓 + manifest 声明的公共仓 `index.publicRepos`；检索面 = 判域 ∥ 改动区 ∥ 围栏配对 ∥ 码段豁免四串）：

- **本仓相关 5 处**：上面四条各是一处；另加 `docs/core/design/DOC-DISCIPLINE.md` §3.20 的「改动区取法（基线两级 · 四态判定）」——③ 的基线口径与它同源，本批不另立一套。
- **两个公共仓无一相关**：源码面零命中，没有「按写入区判、整档出读数」的现成做法可对齐。

**新名三问**（`none found` 的读法 = `grep` 于 `thincoder-core/**` 零命中）：

| 新名字 | 在哪 | 叫什么 | 谁在用 |
|---|---|---|---|
| `alignZonesToFences` | 本批**退役**（原住 `thincoder-core/tools/doc-write-gate.mjs`）；唯一的存在理由 = 「片段起于围栏内」，身份改成目标档后该前提消失（§2.10.2） | 退役名，不另命名 | 无调用点——本批退役；围栏对齐与其导出区间表一并退场，扩区要问的「区落在哪个块里」仍留在 `judgeZones` 内部的 `fenceSpans`（不另立导出面）；处置 = 随族退场、域内零命中（AC-G13） |

#### 2.9.2 ① 围栏状态没有随片段一起过去

**修法**：判域不切片 —— 见 §2.10。被判的是目标档的**整份文本**，围栏状态因此取自整份文本本身（§2.10.1 的 `texts`），「片段起于块内」这个前提不再存在。随之一并退场的两件（围栏对齐与其不变式）见 §2.10.2 的 D14 条：它们的全部理由都是「片段 ≠ 档」。

**判它修好了**：造一份含围栏块的档，块内放一条不解析的路径，改动只有块内一个空行的增删。
- 改前读数：该笔被拒，命中落在块内示例行（作者没动的那一行）。
- 改后：放行。
- 反面（同一用例在改前代码上）：把实现回退到本批改前，复跑该用例必须红。红不起来 = 用例没断住东西。

**A-3 那一格不丢**：实施轮原样复跑——红不起来就把结论记在批档 §5，**不得反过来放宽判据**（拿判据去迎合事故叙述，与 §2.9.8 否掉的「改判法让它容忍不齐」同形）。

#### 2.9.3 ② 环引被无条件压进每一组的命中集

**根因**：`declaredCycles` 按组根走一遍声明出边图，走回组根成环 ⇒ 一条 `环引` **无条件**入 `hits`。它不问本次判集里有没有人指向那个环。于是判集里一个档名 token 就够：组根一定，环被算出来，环就拦。

**修法**：`环引` 的入闸条件改成「本次判集里存在**归一化后首段** = 环上任一仓名的 token」。归一化只在入闸谓词内做：反斜杠换 `/`，按 POSIX 路径段归一，剥去归一后仍留在开头的 `./` ∥ `../`，再取首段。`../<仓>/PROJECT-MANIFEST.json` 因而与 `<仓>/PROJECT-MANIFEST.json` 同判，不需要另一套解析机器。

**实跑判定**：`checkAnchors` 的 `onEdge` 回传原始 token，不先做上述归一化。实跑输入：

```text
../V2-MDSnPermission/PROJECT-MANIFEST.json
../api/PROJECT-MANIFEST.json
```

两形回传的 token 都与输入逐字相同，首段为 `..`。因此入闸谓词必须自己归一化；直接拿原 token 首段比仓名，会让 B-2 的反向控制转绿。

不进闸的那些出**环引读数行**（字面单源 = §2.9.4，与三面存量句同处），两问法同出。判据类数、verdict 词、命中类闭集三样零改 —— 这是入闸条件的作用面收敛，不是新判据。

**判它修好了**：仓的声明里造两仓互引成环，判集放两份文档 —— 一份不指向这两仓，一份写 `../<环上仓>/PROJECT-MANIFEST.json`（B-2 的真实事故形）。
- 改前：两份都 `REFUSED`，命中数相同。
- 改后：不指向的那份 `PASS` + 一行读数；指向的那份照旧 `REFUSED`（环 2 条）。
- **上一条是反向控制**：它证明放宽只在「无关」时成立，指向环的写入一分没松。

#### 2.9.4 ③ 同一条判据在四个面上四个判域

**根因**：判域今天有四个 —— 本次写作文本（段 ∥ 行类）、本次改动区片段（写盘门的锚类）、整档（批档 `edit` 的锚类）、整档（收口）。同一条判据换面换判域，宽严因此差一个量级。

**修法**：按 2.9.1 统一为「改动区阻断 + 存量读数」，三面各写清自己那一段怎么取。

- **写盘门**：判域 = 本笔各 hunk 经扩区表后的区间（§2.10.4）；身份 = 目标档、判定输入 = 本次改后内容（§2.10.1 ∥ §2.10.2）。
- **批档 `edit`**：锚类从整档判改成**本次替换区**判。替换区 = 改动后整档视图里 `newText` 所占的行区间（`edit` 的锚必须唯一命中，行区间因此可定）；区外锚类命中出存量读数、不阻断（⑥ 一并兑现）。
- **收口门**：阻断集 = **本批改动区**，整档出存量读数。取法如下，与触达账腿同一张扩区表：
  - **基线由工具自动记，作者不用写**：`batch create` 的 `createBatchRecord` 在建档前取该批所属仓的 `HEAD`，传给 `thincoder-core/agent-tools/batch-skeleton.mjs` 的 `batchSkeleton`；后者在 §1 自动落 `批起 sha = <sha>`。写入面就在这条建档路径上，不开人工补行这条支。
  - **HEAD 取不到** ⇒ 自动行写 `批起 sha = 未取到（<原因>）`，不伪造提交；收口按「区未定」整档判并点名原因。
  - **基线** = 上述自动行所记的那个提交（`baseShaOf`）；区 = `git diff -U0 <该 sha> -- <该档>` 的 `+` 侧区间，经扩区表扩成片段区。
  - **纯删段**（`+` 侧宽度为零）⇒ 零宽定位点仍扩出完整相邻单元供判定，但**扩进判域不等于邻段全进阻断集**：
    - **行映射**：按 diff 的前后端行序号映射存活行，不按相同文本猜对应关系。邻段存活行因此都能对应到基线行。
    - **逐行文本判据**：锚 ∥ 行号坐标 ∥ 行长在映射存活行上的既有命中 = 存量，只读数、不阻断。
    - **组合单元判据**：基线与落盘各跑一次同一判据，再按行映射比较段落 ∥ 围栏 ∥ 表格单元的成员行。落盘单元的成员映射后不等于任何一个基线单元 ⇒ 它是删除造成的新单元；只有它新产生的命中进阻断集，例如两段合并后段长跨线。基线已有的命中仍是存量。
    - **单元类型改变**：删除定界行使单元类型改变时，只有因新类型才进入判面的命中算新命中；原类型下已存在且相同的命中仍算存量。
    - **基线怎么判**：基线那份字节走引擎的 `texts`（键 = 该档，`docs` 里仍是该档本身），身份因此是**目标档**——命中天然带基线行号，`file` ∥ `root` ∥ 豁免识别键全按目标档取（§2.10.2）。**不落临时档、不写盘**：基线副本一份不留，进程被杀也不再可能留下残档。判整份基线（不交 `zones`）：这一跑不划分本次与存量，只产出完整基线命中供行映射与单元比较；`zones` 只在落盘那一跑把命中分进阻断集与 `stockHits`（§2.10.1）。
  - **该档在那个基线提交里没有**（本批新建 ∥ 改名进来的那一侧）⇒ 整档判：路径在基线里不存在，整份就是本批的笔。
- **写盘面区未定**（非 git 仓 ∥ 基线不可解析）⇒ 零强制 + 明示，因为收口面兜底。
- **收口面区未定**（§1 无 `批起 sha` 记入行 ∥ 非 git 仓 ∥ git 跑不出）⇒ **整档判**（fail-closed）+ 回执点名未定原因。收口是最后一道，它倒向宽等于收口门什么都不挡。
- **批档 `edit` ∥ 收口两面共用一句存量读数**（字面单源 = 本节，常量名 `STOCK_LINE`）：

```text
存量命中 N 条（不属本次改动区，不阻断交付；整档读数）
```

- **`环引` 的读数行**（不进阻断集时出；字面单源 = 本节，消费面 §2.9.3）：

```text
环引 N 条（本次判集未指向成环仓，不阻断交付）
```

**判它修好了**：C-1–C-3 共用下述夹具，C-4–C-6 的夹具各见用例表。一份档里先放若干条既有命中的存量（一条都不动），再往里加两行干净内容，然后走写盘门、批档 `edit`、收口三面。
- 改前：写盘放行，批档 `edit` 被别段的失效引文挡，收口 `REFUSED`，命中全是该档既有债。
- 改后：三面都放行；批档 `edit` ∥ 收口各带一行 `STOCK_LINE`，写盘面只判本次改动区，不出存量读数。
- **C-2 反面**：同一份档里再加一条**落在本次写入区内**的死引文 ⇒ 三面都必须拒。
- **C-3 反面（区未定的倒向）**：同一夹具删掉批档 §1 的 `批起 sha` 记入行 ⇒ 收口面区未定 ⇒ 整档判 ⇒ 照拒 + 点名未定原因；同夹具的写盘面照放行。倒向反了这条当场红。

#### 2.9.5 ④ 行号坐标类的豁免识别键取了一个没人写的载荷字段

**根因**：`exemptionKeyOf` 取命中对象的 `text` 当识别键的文本，而这一类的 `text` 该是什么，本档两处各说各的（§2.7 的类型表要**整行原文**，本节早先那版要「写出来的那串坐标」）。照任一侧登记都与另一侧对不上，回执固定报「登记未命中」。

**修法（键文本一处定死）**：`行号坐标` 的识别键文本 = **该处所在行的整行原文（首尾去空白）**。单源 = §2.7 的类型表，本节不另立第二个定义。

载荷已在盘：`thincoder-core/doc-check/line-refs.mjs` 的 `collectLineRefs` 逐处产出 `text: l.trim()`（该档首注也写明「豁免登记的识别键取它」），`exemptionKeyOf` 对这一类取 `hit.text` 即可。

**报面命中行不动**（形别 + 片段两格照旧）——键是给登记表用的，不是给报面用的，交付门那个坐标类用例因此不必改。判据类闭集、verdict 词、命中计数零改。

为什么取整行、不取坐标串：§2.7 的另两类（段 ∥ 行）取的也是原文的整段整行，一条判据一个取法；换成坐标串，同一行两处坐标就分不开了，登记一处会把另一处一起免掉——那正是识别键要防的事。

**判它修好了**（D-1）：造一条正文面坐标命中，manifest 登记 `kind` = 行号坐标、`text` = **那一行的整行原文**。
- 改前（键取坐标串）：`登记未命中 1 条`，`hits.lineRefs` 不变。
- 改后：`豁免 1 条`，`hits.lineRefs` 减一，`exempted` 新增一格。
- **端到端那一次跑就是 D-1 本身**：载荷在盘已验（上面那条 `text: l.trim()`）；登记这条链整条通没通，本席未实跑——不以读码替代那一次跑。

#### 2.9.6 ⑤ 可执行行的判据是行级的，消费却是段级的

**根因**：`isExecutableLine` 是**行**谓词 —— 行内任意一个码段含命令词、命令链符或搜索模式串片段，整行就叫可执行行。消费面却拿它当**段**谓词：`codeSpans` 返回该行**全部**码段，`inSpan` 对这些段一律不抽。

于是同一行里另一处反引号路径一并被越过 —— 既不判 `档缺`、也不进判集。它是被「同行的命令段」连坐掉的。

**修法**：把「命令形」从行级降到段级。`paragraph.mjs` 出一个**段**谓词（一个码段的文本本身像不像命令 ∥ 模式串），`isExecutableLine` 保留为「任一段满足」的既有语义（它别处还有消费面）；`checkAnchors` 的 `inSpan` 改吃**过滤后的段**（只含满足段谓词的码段）。

这是抽取面的 carve-out：判据类数、解析序、豁免谓词、阈值四样零改。

**判它修好了**：一行散文里两个码段，一个是命令、一个是路径。
- 改前：0 条命中（路径被连坐）。
- 改后：1 条 `档缺`，落在那个路径上。
- 反面：把路径单独放一行、同行无命令段 ⇒ 改前改后都是 1 条 —— 证明放宽只留给真命令段，散文里的路径一分没松。

### 2.10 判域三义：一个判定、三处调用、两个入参

三条缺陷同源：**「判什么」被写成了另一样东西**。写前门把改动区切片落成一份临时档，「判什么」于是成了那份临时档；改动区被写成首末包络，「判什么区间」于是成了「从第一处到最后一处」；锚抽取式只按清单收 token、连代码族裸名一起收，「哪些 token 算指针」于是在代码族裸名上多判了一整族散文提及。

本节的机制 = **一处判定 + 两个入参**（`texts` ∥ `zones`），三处调用各只说自己要判哪份档、哪些区间。

#### 2.10.1 单源机制：`runDocCheck` 的 `texts` ∥ `zones`

引擎入口加两个**可选**入参（`thincoder-core/doc-check/index.mjs` 的 `runDocCheck`）：

- **`texts`**：键 = 档的绝对路径，值 = 该档本次判定所用的完整文本。给了它，该档的判定输入就是这份文本，不再读盘。
- **`zones`**：键 = 档的绝对路径，值 = 区间表（按**改后档**行号，闭区间）。它的判定是**逐档**的：某档有键 ⇒ 该档阻断集 = **命中行落在任一区内的那些**，区外的命中进 `stockHits` 读数桶，照列、不阻断（字面单源 = `STOCK_LINE`，§2.9.4）；**某档在 `docs` 里而 `zones` 里没有它的键 ⇒ 该档整份进阻断集**，不是「区外」。所以「交了 `zones`」不等于「每档都有区」——append 腿把批档本体的键留空，正是用这一条让候选整份即本次（反读成「无区 ⇒ 全存量」会让候选文本里的悬空锚当场放行，AC-P7 钉住）。

三条语义：

1. **`texts` 只换输入，不换判定**：三条判据、四条抽取式、解析序、面判、豁免谓词一字不动 —— 它替换的是「读哪份字节」，不是「怎么判」。
2. **`zones` 只改阻断集**：它决定一条已有命中算「本笔的」还是「存量的」，不决定什么算命中。
3. **两个入参都缺席 ⇒ 与今日逐字相同**：交付面（`report` ∥ `gate`）零回归。

**为什么是这个形**：判定输入本来就不是「盘上那份」，而是「本次要判的那份」。写前门有改后整份内容、批档 `edit` 有改后整档视图、收口面有落盘后的档，纯删比较还持有基线全文。给一个替换输入 + 一个归属区间的入参，正是把调用方手里已有的东西交出去，而不是让每个调用面各造一份临时档来假装它就是那份档。

**与既有注入形同族**：`checkAnchors` 的 `manifest` ∥ `exts` 两个入参已是这一形 —— 注入换来源、判定零改、缺省自读（§2.5 KD-7 ∥ §2.6）。本批把同一处置上提一层到 `runDocCheck`，不新造第二套形。

**各次调用各交什么**（调用方只说自己要判哪份档、哪些区间；收门口的纯删基线另跑一遍）：

| 调用点 | `docs` | `texts` | `zones` |
|---|---|---|---|
| 交付面（`doc_check` 两问法） | 调用方给的清单 | 不给（读盘） | 不给（整档即判域） |
| 写前门（`thincoder-core/tools/doc-write-gate.mjs`） | 目标档一份 | 目标档 → 本次改后内容 | 目标档 → 各 hunk 经扩区表后的区 |
| 批档 `edit`（`thincoder-core/agent-tools/batch-gate.mjs`） | 触达账各档 + 批档本体 | 批档 → 改后整档视图 | 批档 → `newText` 所占行区间经扩区表后的区 **∪ 触达账各档的改动区**（与 `append` 行同一个 `zoneTablesOf`；只收 `kind:"region"` 的档，未定 ∥ 未跟踪态不交、由 `blocks` 另判） |
| 批档 `append`（同档的候选文本腿） | 触达账各档 + 批档本体（身份 ∥ 豁免登记按它取） | 批档本体 → 候选全文 | 触达账各档的改动区；批档本体的键**不进** `zones`（候选整份即本次） |
| 收口门（同档的 `close` 腿） | 本批笔域集 | 不给（已落盘） | 逐档 → `git diff -U0` 的 `+` 侧区间经扩区表后的区 |
| 收门口的纯删基线那一跑 | 纯删目标档一份 | 目标档 → 基线全文 | 不给（整份基线都产出命中，供行映射与单元比较） |

- **代价（用户 2026-11-11 裁定：接受）**：append 面不再对批档已落段出存量读数。`append` 只在段尾追加、改不动既有行，那里本来也只能明示、不阻写；可见性由 `edit` ∥ 收口两面承担，不为它多跑一次引擎——那一跑会把成本摊到每一次 append。
- **代价谁兜底**：批档自身的存量债由 `edit`（替换区外的存量读数）与收口面（本批改动区外的存量读数）两面接住，两面出同一句 `STOCK_LINE` ⇒ 没有哪条存量只能靠 append 才看得见。

**判定只有一处**：上表各次调用的三条判据、抽取面、解析序全走同一个 `runDocCheck`。调用方不再各有判法，只各有「要判什么区间」。这也是 §2.9.1 的统一判据第一次真正落到一个入口上 —— 那一轮把**判域口径**统一了，入口仍是四处；本节把入口收成一。

#### 2.10.2 身份 = 目标档：豁免面三处同判

**根因（读码，不是推断）**：写前门把改动区切出来落成一份**临时片段档**再交引擎判。于是每条命中的 `file` 是那个片段档，而豁免登记的识别键要求 `file` = 登记时写的**项目根相对路径**。两者永不相等。

依据 `thincoder-core/doc-check/index.mjs`（豁免分类的识别键）：

```text
const t = tableOf(rootOf(h.file, base))
const own = pathKey(rel(t.root, h.file))
const matched = t.items.find((it) => it.problem === undefined && it.fileKey === own && it.kind === k.kind && it.text === k.text)
```

**为什么身份取目标档**：登记要求的 `file` 是**项目根相对路径**，而片段档时代每条命中的 `file` 是那串临时名，两者永不相等。身份一改，豁免分类不必加第二个分支：它本来就按 `file` 找表，只是过去那份 `file` 是个临时名。

⇒ **「豁免在写前门不生效」不是一个漏调的函数**：写前门调的就是同一个 `runDocCheck`，豁免分类也在跑；错的是**被判那份档的身份**。逐条登记这条机制本身没有问题 —— 它在写前门面没有可匹配的身份。

**修法**：`texts` 的**键 = 目标档绝对路径**（§2.10.1）。判定读「本次要落的那份文本」，而每条命中带出来的 `file` ∥ `root` ∥ 豁免识别键 ∥ 面判（§3.29）∥ 报面坐标全部是**目标档**的。豁免分类因此**不需要新分支** —— 它从来就是按 `file` 找表，只是过去那份 `file` 是个临时名。

**三处同判的判据句**：同一条命中在同一份档上，交付面判「豁免 1 条」⇒ 写前门与收口面也判「豁免 1 条」。三处读同一张表、同一个键、同一个分类点（§2.7 的装配处）。

**片段档一族整族退役（D14）**：前缀常量 ∥ 落片段档的函数 ∥ 命中行回目标档的映射表 ∥ 围栏对齐不变式 —— 这四件的存在理由都是「片段 ≠ 档」：映射表为把片段行号译回目标档，围栏对齐为防片段起于围栏内。身份改成目标档后，行号本就是目标档行号、围栏状态本就取自整份文本，**两个前提同时消失**。

- **扩区表照旧保留**：产出区间的那三件（段落区间表 ∥ 区间合并 ∥ 扩区表本体）仍产出区间，只是不再切片 —— 收口腿（`thincoder-core/agent-tools/batch-regions.mjs`）照旧消费它们，那一面本来只要区间。
- **围栏对齐的抛错句退役**：它的抛错句说的是「片段区起于围栏内」—— 判整份文本后，区起于围栏内是**合法**的（作者就在块里改了一行），前提不存在，留着只会误抛。
- **围栏块区间表随之退役**：它唯一的消费者是围栏对齐（实读：域内只见本档内部消费）。
- **族外的两腿同轮闭口**：纯删面的「基线副本」（`thincoder-core/agent-tools/batch-regions.mjs` 的 `pureDeleteStockEntries`）与批档 append 面的「候选文本片段档」（`thincoder-core/agent-tools/batch-gate.mjs` 的 append 装配）过去各落一份同目录临时档，同属「拿临时档假装它是那份文本」。改法同一条：字节走 `texts`，身份 = 交出的那份档——纯删基线取目标档、append 取批档本体（§2.10.1 的表）。
- **两腿闭口后符号不留**：`FRAGMENT_PREFIX` ∥ `fragmentPathOf` 没有任何使用者 ⇒ 随本族整族退场；`thincoder-core/agent-tools/batch-lifecycle.mjs` 的在飞扫描不再按片段前缀排除，改按**两条**判：扩展名不是 `.md` 的不算批档 ∥ 点开头的不算批档。两条都要——`docs/batches/` 下与批档同目录并存的同名单测档（`<批档名>.test.mjs`）以日期开头，只按「点开头」一条挡不住它，挡住它的是扩展名那一条。这条判据不为任何残档设支：盘上没有旧实现留下的片段档，按残档写的支是自造夹具。
- **族怎么认**：七个符号名 —— `DOCGATE_PREFIX`（字面 `.docgate-`）∥ `writeFragment` ∥ `alignZonesToFences` ∥ `fenceBlocks` ∥ `zoneOf`（`refusalMessage` 内把片段档行号译回目标档的那条查表支的局部名）∥ `FRAGMENT_PREFIX`（字面 `.gate-`）∥ `fragmentPathOf`。域 = 跟踪面的 `*.mjs` ∥ `*.md`，扣 `docs/batches/**`。**预期残留数住批档 §2**（D12：规范面不载绝对读数）。

#### 2.10.3 锚抽取式的形分档：裸名按扩展名族分两类

**判据句**：一个 token 要成为候选，除后缀落在生效清单内（§2.6 的清单谓词）之外，再加一条**形判**——

> **带目录段（含 `/`）⇒ 候选，一族同判。不带目录段（裸名）⇒ 后缀须落在文档名族 `BARE_NAME_EXTS` 内才是候选；后缀只在代码族里 ⇒ 不是候选，按散文提及处置，不解析、不判。**

`BARE_NAME_EXTS` 的取值 = `md` ∥ `markdown`（一处定义，导出面 = `thincoder-core/doc-check/anchors.mjs`）。

**为什么按形分、不按语义猜**：代码族名字**天生歧义** —— 一句散文里裸写的代码档名，读者知道那是个概念或约定名，机器只知道它可能指仓里任意一份同名档（实读：六个包各有一份同名的依赖清单档，依赖树内还有数十份）。而裸名这一形在代码族上占压倒多数的是散文提及、示例、否定句与约定名，在文档名族上占压倒多数的是真指针。同一个判据对两族给出相反的最优解 ⇒ 分档，不是放宽。

**为什么文档名族裸名照判**：文档指针最自然的写法就是裸名（「见设计档 §2.6」），而它可解 —— 解析序第 6′ 步的唯一后缀兜底正是为这一形开的（§2.8 ∥ F3 的同一条）。**唯一即过、歧义即红**：唯一后缀 ⇒ 解析到那一处；多候选 ∥ 零命中 ⇒ 照判 `档缺`。

**落点 = 谓词，不是五条消费面各写一遍**：`isDocToken` 是清单的判定落点（§2.6「清单落在哪一层」），形分档与它同坐一处、同一个调用点 —— 锚 ∥ 花括号组 ∥ 依据行 ∥ 行号面 ∥ 档图面五条消费面因此自动同判，不新增判断点。**同判的代价如实写**：行号面（`thincoder-core/doc-check/line-refs.mjs` 的 `NAME_RE`）同吃这个谓词 ⇒ 裸写的代码族档名其后跟冒号加数字时不再计一条行号坐标（带目录段的照计）。这是候选集随锚面一同窄化，不是判据本体放宽；验收 = AC-G14 那一对。

- **第五个消费面 = 档图面**：`thincoder-core/doc-check/graph-tokens.mjs` 的两处 `isDocToken` 调用随同判——裸写的代码族档名不再作边，两张图形的边集因此变更、不入 verdict。代价与行号面同向，调用点已注明。

- **带目录段的 token 一族同判**：路径本身给出了定位，代码族与文档名族在这里没有差别。下面两形同一把尺（示例住围栏块）：

```text
docs/<名>.py    docs/<名>.md
```

- **项目追加项一律按代码族处置**：`index.docCheckExts` 是**后缀清单**，不是族划分面；它加进来的后缀在裸名位不成为候选。要让它按文档名族判，改 `BARE_NAME_EXTS`（走评审），不新增第二个可配面（F3「判据不分适用面」）。
- **代价如实（两个方向都写）**：
  - **漏报方向**：散文里裸写的代码族文件名若真的指向一件在盘档，本批起不再判。出口 = 写成带目录段的形。
  - **多报方向不变**：文档名族裸名的歧义与零命中照判 `档缺`（这一点本批一个字没松）。
- **不设第三族**：`.txt` ∥ `.csv` 一类不进文档名族。理由是可判性 —— 散文里裸写的 `.txt` 绝大多数是样例输入名（冻结题面表的夹具即此形），不是「去读这份档」；认它当指针，一整张样例表就把档判红，而那张表的每个名字都不该在盘上。代价与上一条同向：写成带目录段的形，或登记一条逐条豁免（§2.7）。

**本批修好的是哪一半（照实写）**：清掉的是**裸名代码族**那一族。**带目录段的样例路径不在本批射程内** —— 下面这类仍判 `档缺`，它们是**真悬空**（认对了、盘上没有），出口仍是 §8 的两条既有写法（围栏块 ∥ 目录形）或 §2.7 的逐条登记：

```text
docs/<样例>.txt   tmp/<样例>.txt
```

把它们一并放过就是把这条判据拿掉一半，那是本批明令不做的方向。

#### 2.10.4 改动区 = hunk 并集，不是首末包络

**判据句**：改动区 = **本次每一处替换各自的区间**，各带 ±2 行上下文，相邻 ∥ 重叠者并成一段；**判据 = 命中行落在任一区内**。

**退回形（判据的一部分，不是实现的私活）**：hunk 由行级 LCS 切出；格数（旧中段行数 × 新中段行数）超过 `LCS_CELL_CAP` 时**退回改前的首末包络**——中段整段算一区，再照常加 ±2 行上下文与扩区。常量住 `thincoder-core/tools/doc-write-gate.mjs`，量级读数住批档（D12）。

**退回的代价如实写**：那一形下包络病会复现——首末两处之间夹一处存量锚即整笔被拒，正是本节修掉的那一形；方向落在从严一侧（只多认存量、不少报本次），不是放宽。

**根因（读码）**：`thincoder-core/tools/doc-write-gate.mjs` 的 `changeRegion` 剥公共前 ∥ 后缀，返回**一段**连续区间：

```text
let head = 0
while (head < min && oldLines[head] === newLines[head]) head++
let tail = 0
while (tail < min - head && oldLines[oldLines.length - 1 - tail] === newLines[newLines.length - 1 - tail]) tail++
return { start: head + 1, end: newLines.length - tail }
```

首处差异到末处差异之间的**全部未改行**因此都落进这一区。一份档改 20 处、每处都干净，只要首末两处之间夹着一处存量锚，整笔就死 —— 而调用方手里本来就有每处替换的确切行区间。

**修法两条，各坐一处**：

- **区间表代替单区间**：剥公共前 ∥ 后之后，对剩下的中段再剥**内部公共段** —— 逐段找出改后文本与旧文本相同的极大行段，它们把中段切成若干 hunk，返回区间表（改后档行号）；宽度为零的 hunk（纯删行）保留为定位点。
- **上下文两行在 hunk 之上加，不在包络之外加**：各 hunk 两侧各取 2 行并入区间，再合并，再经扩区表（整段 ∥ 整表格单元）对齐成 §2.10.1 的 `zones`。

**为什么留两行上下文**：一笔插入若落在两段之间，邻接段的**段落长度**可能因这一笔变；两行是判定「这笔有没有把邻段推过线」的最小窗口。方向从严（多认两条存量），与 AC-12 ⑦「被碰段落里的旧悬空指针照拒」同向，不制造新的放宽面。

**存量与本次的分界由此可读**：`zones` 之外的命中 = 存量（读数行，不阻断）；`zones` 之内的命中 = 本次（照拦）。**存量判别不再依赖距离猜测**，也不再依赖包络 —— 它就是区间成员关系。

**判面行跟着改**：写前门拒文里那行 `判面：改动区 M 区 · 片段区 N 区 · …` 的 M 从结构常量 1 变成**实际 hunk 数**（读数，按本笔实算）；片段区那一段随片段档退役（§2.10.2），改成「判定区 N 区」。

#### 2.10.5 四个机制的先例 ∥ 公共源勘查 ∥ 数据事实核对

- **对齐 `thincoder-core/agent-tools/batch-gate.mjs` 的触达账腿**（改动区取自 diff、区外存量只出计数）：§2.10.4 的区间成员关系照这一件写。

- **两个公共仓无一相关**：源码面零命中 —— 没有「注入文本判据」或「裸名按扩展名族分档」的现成做法可对齐。

**新名三问**（`none found` 的读法 = `grep` 于 `thincoder-core/**` 零命中）：

| 新名字 | 在哪 | 叫什么 | 谁在用 |
|---|---|---|---|
| `texts` | `none found: thincoder-core/**`；本批新建于 `runDocCheck` 入参 | 本档命名（判定输入替换） | 写前门 ∥ 批档 `edit` 两处调用（§2.10.1 的表） |
| `zones` | `none found: thincoder-core/**`（既有同名量只是写前门的内部值，不上引擎入参） | 本档命名（归属区间） | 写前门 ∥ 批档 `edit` ∥ 收口门三处 |

**数据事实核对**：本节**有三条断言要读盘**，全部实读得出、不留推断。

- **断言一**：散文裸名被误判那一族确实落在代码族上，且文档名族裸名一条不在其中。取证 = 对被拒的那两份设计档抽 token 并按形分档，读数随交付报出。
- **断言二**：豁免在写前门面失配的根因是片段档名与登记 `file` 不等，不是豁免分类没跑。取证 = 上面那三行读码 + 一次写前门拒文与 `doc_check` 回执的对照（同一命中、两处判决不同）。
- **断言三**：多 hunk 被包络绑架的现场可复现 —— 一份档两处改动、首末之间夹一处存量锚 ⇒ 改前拒写。取证 = 夹具实跑，读数与命令随交付报出（D12：本档不载绝对读数）。

#### 2.10.6 验收（回指本批条目）

单元用例住 `docs/batches/<本批批档同名>.test.mjs`，逐条核法 = `node --test <该档>`（用毕即删）。**每条单元用例都带红侧** —— 一条只能变绿的用例没断住东西。AC-P4 是父侧收口的集成复核，单列核法，不混进本批单元测试档。

**第一组 · 形分档**：

- **AC-G1（裸名代码族不判）**：一份正文写一句否定句，其中含一个裸写的代码族文件名，同行再无别的指针 ⇒ 零命中。**红侧**：把形分档判据去掉（只查清单）⇒ 该例出 `档缺` 一条。
- **AC-G2（带目录段的代码族照判）**：同一份正文写一处带目录段、后缀是代码族的路径，且不在盘 ⇒ `档缺` 一条。**红侧**：形分档写成「代码族一律不判」⇒ 本例零命中。与 AC-G1 一组，缺一条就把「按形分」读成「按族免」。
- **AC-G3（文档名族裸名照判 · 唯一即过）**：正文裸写一份在盘 `.md` 档名 ⇒ 零命中（唯一后缀兜底）。**红侧**：把 `md` 从 `BARE_NAME_EXTS` 去掉 ⇒ 本例出 `档缺`。
- **AC-G4（真歧义裸名照红）**：夹具造两份同末段名的 `.md`，正文裸写该名 ⇒ `档缺` 一条（多候选）。**红侧**：把文档名族的裸名也一并放过 ⇒ 本例零命中。**这条是本批「没把判据改宽」的正面证据。**

**第二组 · 豁免三处同判**：

- **AC-G5（写前门认登记）**：夹具档含一处已裁定的假阳命中，登记四字段齐全 ⇒ 写前门放行、字节落盘；同一命中在 `doc_check` 面判「豁免 1 条」。**红侧**：恢复旧实现的整条调用——改动区切片落临时片段档、`docs` 改交该片段档且不交 `texts` ⇒ 写前门照拒、零字节。
- **AC-G6（撤销即回拦）**：删掉那条登记 ⇒ 写前门与 `doc_check` 面**同时**回到拒 ∥ `REFUSED`。**红侧**：把豁免做成写前门面的缓存 ⇒ 本例前半仍放行。
- **AC-G7（三处一个键）**：同一条命中在交付面 ∥ 写前门 ∥ 收口面各判一次，三处判决词逐字相同。**红侧**：三处各取一份登记表（而非同一个 `file` 键）⇒ 三处判决分叉。

**第三组 · 改动区并集**：

- **AC-G8（多点写入不被包络绑架）**：一份档改三处、三处都干净，首末两处之间夹一处存量锚，且存量距最近改动 > 2 行 ⇒ 放行、字节落盘。**红侧**：区间表退回单区间 ⇒ 本例被拒，命中落在存量那一行。
- **AC-G9（区间内的存量照拦）**：同上夹具，把存量锚移进某处改动的 ±2 行内 ⇒ 拒写、零字节。**红侧**：把成员判据写成「只要有一条区外命中就整笔放行」⇒ 本例放行。**这条是「该拒的仍拒」那一拍。**
- **AC-G10（纯删行）**：删掉一段中间的行（改后侧宽度为零）⇒ 零宽定位点仍归本笔；邻段存量不因此被算成本次。**红侧**：把纯删支写成整档判 ⇒ 邻段存量把整笔拒掉。

**第四组 · 单源与零回归**：

- **AC-G11（判定一处实现）**：`grep` 于 `thincoder-core/**`，锚判的实现点只有一处；三个调用面各自的入参只含清单 ∥ 输入文本 ∥ 区间与模式。**红侧**：任一面自带一份锚判（哪怕只判「解析得到与否」）⇒ 该面出现第二个实现点。
- **AC-G12（交付面零回归）**：同一份档清单跑 `report` ∥ `gate`，不带 `texts` ∥ `zones` ⇒ 报面与改前逐字相等。**红侧**：把 `texts` 缺省写成空串（而非「不覆盖」）⇒ 该档被判成空档、报面漂。
- **AC-G13（片段档退役不留残）**：§2.10.2 那七个符号名与两个字面 `.docgate-` ∥ `.gate-` 在域内零命中（域 = §2.10.2 写的那一个）。**判罚面只有一类**：把退役角色当权威 ∥ 判据来源 ∥ 验收命令 ∥ 手跑面用的处；判据规格面与用例面的提及（§2.10.2 的族清单本身、§2.9.1.1 新名三问行的退役登记、本条）算**射程外**——逐档点名、零处置，不计命中。**红侧两拍**：① 留一个未接线的围栏块区间表导出（把退役符号当权威用）⇒ 命中 +1，本条红；② 把族清单自身的提及计成命中 ⇒ 本条同样红——射程外被计成红与射程内漏记是两种错，两拍各断一边。
- **AC-G14（形分档落到行号面 · 一对）**：正例 = 正文写带目录段的代码族路径、紧跟冒号加数字 ⇒ 行号坐标照计一条；反例 = 同一份正文裸写同一文件名再跟冒号加数字 ⇒ 零条（代码族裸名在形分档挡下，两条判据同吃一个谓词）。**红侧**：行号面不再过 `isDocToken`（只看清单）⇒ 反例计一条、本条红；形分档写成「代码族一律不判」⇒ 正例零条、本条红。

**第五组 · 判定输入：纯删基线 ∥ append 候选文本**：

- **AC-P1（基线身份 = 目标档）**：夹具档在基线含一处已登记假阳，本笔只删其邻段 ⇒ 该命中按目标档身份对上登记，进 `exempted`、不进 `hits`。**红侧**：恢复旧实现的整条调用——基线字节落同目录临时档、`docs` 改交该临时档且不交 `texts` ⇒ 同一命中进 `hits`，且命中的 `file` 是那串临时名。
- **AC-P2（行号对得上）**：同一夹具（删除点上方留两段、邻段各带既有死引文）⇒ 邻段存量退场、只出存量读数；基线两段各自不超长、删段间空行使两段合并后段长跨线 ⇒ 拒。**红侧**：把段类的基线识别换成「只比命中行号」——不比映射后单元的端点 ⇒ 合并那一格判成存量、放行，本条红。
- **AC-P3（零临时档 / 零残留）**：结构机检读 `pureDeleteStockEntries` 函数体 ⇒ 零 `writeFileSync` ∥ `unlinkSync`，基线判定调用不含临时档路径；再跑一次含纯删的收口判，结束后目标档同目录零 `.gate-*` 基线副本。**红侧**：恢复旧实现的 `writeFileSync` 或 `unlinkSync` 任一处 ⇒ 结构断言当场红，不依赖进程恰好死在 `finally` 之前。
- **AC-P4（父侧收口集成复核，非单元用例）**：`node --test test/integration/batch-close-gate.test.mjs test/integration/batch-touched-region-gate.test.mjs` 全绿，结果记批档 §6。纯删两场景的红侧由 AC-P2 承担，本条只读父侧收口回归结果。
- **AC-P5（纯删调用点退场 · 结构机检）**：`grep` 的 `fragmentPathOf\(` 于 `thincoder-core/agent-tools/**` ⇒ **零命中**（定义点与调用点同退，§2.10.2）。**红侧**：恢复纯删函数里的 `fragmentPathOf(file)` ⇒ 命中 +1，本条红。
- **AC-P6（append 候选文本走 `texts` · 结构机检 + 身份读数）**：`thincoder-core/agent-tools/batch-gate.mjs` 的 append 装配 ⇒ 候选全文经 `texts`（键 = 批档本体）、零 `writeFileSync` ∥ `unlinkSync` ∥ `fragmentPathOf(`；同一笔的命中行渲染成「候选文本第 N 行」，N = 候选文本里的行号。**红侧**：恢复临时档形（候选字节落 `.gate-` 临时档、`docs` 交该临时档、不交 `texts`）⇒ 同一命中的 `file` 是那串临时名，且行号与候选文本对不上，本条红。
- **AC-P7（`zones` 缺键 = 该档整份本次 · 逐档语义）**：一笔 append，候选文本里写一条解不到的路径（带目录段、落点不在任何批档基底根下——裸名在批档面内不入判，面判判据单源 = `docs/core/design/DOC-DISCIPLINE.md` §3.29 条目 AC）；`zones` 只含触达账各档的键，批档本体的键不在其中 ⇒ 首行 `REFUSED（命中 1 条——候选文本（锚 1 条））`、命中行点名「候选文本第 N 行」。**红侧**：把「缺键」读成「无区 ⇒ 全存量」⇒ 同一笔放行、命中落进 `stockHits`，本条红。
- **AC-P8（在飞扫描不把批档同名单测档当批档 · 结构机检）**：`thincoder-core/agent-tools/batch-lifecycle.mjs` 的排除支读两条（扩展名不是 `.md` ∥ 点开头），不含任何片段前缀字面。**红侧**：改回「点开头」单条 ⇒ 同目录并存的 `<批档名>.test.mjs` 被当成第二本在飞批，本条红。

#### 2.10.7 上抛项（需求面口径，本席不改）

**写前门的 `hits` 读法。** 写前门今天读的是锚类与段类两数之和（不读行号类）。`zones` 落地后，区外命中进 `stockHits`、不进 `hits`，该读法**语义不变**（照旧只取两类）；但拒文要新增一行存量读数，而 F14 的字面是「判集 = 本笔触碰的段落」—— 它没说拒文能不能带存量读数行。本设计按「带一行读数、不进 `hits`」写（与 §2.9.4 的存量句同处置），请评审确认这不是新的口径。

#### 2.10.8 边界（本节不做）

- **不改三条判据本体**：阈值 ∥ 命中类闭集 ∥ verdict 词 ∥ 抽取式内部解析序一字不动。本节改的是**判定输入从哪来**、**哪些命中算本次**、**哪些 token 算候选**。候选集窄化连带行号面的计数（裸写的代码族档名此后不成候选，代价段见 §2.10.3 ∥ 验收见 AC-G14）——那是同一个谓词的后果，不是第二笔改判据。
- **不取消锚判**：文档名族裸名照判、带目录段的代码族照判、真歧义照红、死指针照拒 —— 四条都是本批的验收条目（AC-G2 ∥ AC-G4 ∥ AC-G9）。
- **不给样例路径开口子**：冻结题面表那类带目录段的样例输入仍判 `档缺`（真悬空），出口是 §8 的两条既有写法或 §2.7 的逐条登记。
- **不动 §2.9 的判域口径**：本节只把 §2.9.1 的四入口收成一入口，判域规则本身（跟写入走 ∥ 存量只读数）不变。
- **不拆档**：`thincoder-core/doc-check/index.mjs` 越 800 硬限的拆分仍归另批（§2.9.7），本节只加两个入参与一个桶。
- **不动收口的基线取法**：`批起 sha` 自动行零改；本节只规定「区怎么从 diff 变成区间表」。

## 3. 接口契约

| 面 | 形状 | 变 ∥ 不变 |
|---|---|---|
| 引擎入口 | `runDocCheck(root, { docs, mode, docsSource, lines })` | **签名不变**；`root` 语义 = 声明根，不再是整批坐标系；缺省 ∥ 空串 ∥ 非字符串 ⇒ §2.4 的 `ERROR` |
| 引擎内部 | `perRootGroups(files, declaredBase)` → `{ root, files }[]`；每组一次 `readManifest(root)` | 取根 = `owningProject(abs, parse(abs).root) ?? declaredBase`；**每根一次读**（§2.5、§5 KD-7） |
| 判法入口 | `checkAnchors(root, { files, manifest? })` | 新增可选 `manifest`：给了就吃它（引擎已读的那份），缺省仍自读——直调判法本体的夹具（AC-5 的对照面）零改 |
| 基底根 | `batchDocBases(cwd, { manifest? })`（`thincoder-core/agent-tools/batch-paths.mjs`） | 同上注入形；批档工具面既有调用零改 |
| 引擎返回 | `projectRoots: string[]`（参与判定的根，升序）＋ `domainTables: { root, manifest }[]` ＋ 锚面的 `unverified` 桶 ＋ 判集一个名字 `checkFiles: string[]`（= 本次判集，仍等于 `range.check` 去掉排除面命中的那批）＋ 豁免桶 `exempted: []`（已裁定假阳，与 `skipped` ∥ `unreadable` ∥ `hits` 各自一桶；消费者 = 两面豁免块与 AC-X1 ∥ AC-X4）＋ 清单透传（该根的 `index.docCheckExts` 交给判法面） | `projectRoots` 的消费者 = 报面根清单行（§2.3）与用例断言；`domainTables` 的消费者 = §2.5 的域表读数块与用例断言；`unverified` 的消费者 = `未核 N 条` 列报（不进 `hits`、不动 verdict）。`hits` 三数口径、`anchorHits` ∥ `paragraphHits` ∥ `lineRefHits` 形状不变 |
| 工具面 | `thincoder-core/agent-tools/doc-check.mjs` | **改两处**：① `target` 必填——缺 ∥ `null` ∥ 空串 ⇒ 拒、报文点名 `target`、零判定（schema 加 `required: ["target"]`）；② `ambiguous` 那处守卫的「给了」判据 = **一个非空字符串**（§5 KD-10），该守卫必须与解析层同一条线——依据 `thincoder-core/path-resolve.mjs`「if (given === undefined || given === null) {」。`view.state === "workspace"` 提前返回**已不在盘上**（盘上照判），不重建。锚只作相对形 `target` 的基根 |
| 判定面 | `thincoder-core/doc-check/anchors.mjs` | 域表吃注入的 `manifest`（读取来源一处）；锚判据另有跨仓三笔——`resolveDoc` 传 `declaredRepos` · 走查声明出边图出 `锚·环引`（仓级命中、无行号）· 两处收集点收 `未核` 且不入 `hits`；判据口径单源 = `docs/core/design/DOC-DISCIPLINE.md` §3.20 |
| 判定面 | `thincoder-core/doc-check/paragraph.mjs` ∥ `line-refs.mjs` | `paragraph.mjs` **只加载荷字段 `text`**（段 = 该段整段原文 ∥ 行 = 该行整行原文）：§2.7 的 kind 表要求这两类命中的 `text` 是原文，不给就登记不了（F20）；判据与命中类零改。`line-refs.mjs` 不在此列：`NAME_RE` 的字符类、扩展名式与边界对随 §2.6 同轮换——本档自写的第二份字面整条删除（判据本体零改） |

数据流：`docs` 条目 →（**无声明根 ⇒ 停在这里，走 §2.4 的 `ERROR`**）→ `resolve(declaredBase, d)` 得绝对路径（路径解析基准**不变**，相对条目仍按声明根解析）→ 可判性判定（在盘 ∥ `.md`，**不变**）→ 按 `rootOf` 分组 → 逐组 `checkAnchors` → 合并命中 → 报面（单根无标 ∥ 多根打标）。

**判据句合规**：分组与定根住在 `thincoder-core/doc-check/per-root.mjs`；锚判据的跨仓三笔只沿 `index.publicRepos` 给出的边读（`thincoder-core/declared-repos.mjs` 的 `declaredCycles` 不遍走目录）⇒ `anchors.domain` ∥ `anchors.roots` 仍零存在，「不做全仓扫描」那条判据句照旧成立（回指 `docs/core/requirements/DOC-CHECK.md` 的边界段判据句）。

## 8. 边界（本批不做）

- **不改既有判据正文与阈值**：段长 ∥ 行号坐标两条判据、引文判法、三条判据的阈值均未动。**锚面本批动的是抽取面**：名字字符类 ∥ 扩展名式 ∥ 清单谓词（§2.6），四条抽取式（含行号面 `NAME_RE`）同源换一次；解析序 ∥ 命中类 ∥ verdict 串 ∥ 豁免谓词的判定逻辑零改。
- **仓外路径族 = 真悬空，照报**：清单把「认错了东西」那一族（代码表达式 ∥ 版本区间 ∥ 归档名）挡住之后，散文里指向**仓外产物**的路径仍会判 `档缺`——那是**真阳**（认对了、盘上没有），不是误报（§2.6）。
- **文档侧的两条合法写法（既有，不新增机制）**：① **写进围栏块**——围栏是逐字证据，锚 ∥ 引文 ∥ 行号 ∥ 段长四类判据整块跳过；② **写成目录形**（`build/`，不带后缀）——后缀不在清单，不成候选。两条都不是豁免：换的是写法，不是判据。
- **不替现盘文档改字**：本批交付的是能力；现盘那批真悬空按清账处置——台账登记（哪些族 ∥ 怎么清），另轮清。
- **不放松错判**：没有声明根就是 `ERROR`，不跳过该档、不出半份判定。
- **不做全仓扫描**：清单仍是唯一范围来源；按档定根不等于按目录找档。
- **不按项目分 verdict**：一次调用一个答案。
- **不合并各组扫描根**：每组只吃自己那根的域表（§2.5 KD-9）；域表为空集时向严判，不向宽判。
- **四态的判据不归本档**：`thincoder-core/path-resolve.mjs` 的四态（`ambiguous` 与第四态 `unverified`）归 `docs/core/design/PATH-RESOLUTION.md`；本档只规定工具面**何时拒**（`target` 缺 ∥ `null` ∥ 空串 ⇒ 拒；非空 `target` 解析为多项目工作区 ⇒ 另拒）。
- **`gate` 面只增列报与环引行**：域表读数不进 verdict、不改首行；`gate` 面增的是 `未核 N 条` 列报（不入 `hits`）与环引命中行。
- **需求档本批不再改（判域面）**：`docs/core/requirements/DOC-CHECK.md` 已含 F17 ∥ AC-15。
- **豁免只能逐条具名**：目录 ∥ 路径前缀 ∥ 通配不进**豁免面**的登记（§2.7）；判集的收窄由排除面管（`index.docCheckExcludePaths`，本批不改）。
