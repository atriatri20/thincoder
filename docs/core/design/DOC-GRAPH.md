# 文档锚点图（DOC-GRAPH）· 设计

> 需求单源 = `docs/core/requirements/DOC-GRAPH.md`（F1–F5 ∥ F7 ∥ 边界七条）。**本档覆盖 AC-1–AC-9**；AC-10（子代理可用文档工具面）是另一条活需求，设计落点 = `docs/core/design/AGENT-LOOP-SUBAGENT.md` §6.60，本档只写它的变体契约（§2.5.5）。本档只答「怎么建」，不重述需求口径。

## 1. 方案与理由

**一句话方案**：把 `doc_check` 锚判据那一次逐行遍历**顺手产出的边**收集起来，写进台账同一个 SQLite 文件的一张 `doc_edges` 表；查询面是一个新工具 `doc_graph`，四种问法（扫 ∥ 正向 ∥ 反向 ∥ 链路）。**不新写文档解析器，不新开库。**

### 最近先例

- **台账（`thincoder-core/ledger-db.mjs` ∥ `thincoder-core/ledger-tools.mjs`；设计档 `docs/core/design/LEDGER.md` §2.1 根解析面 ∥ §2.2 建表 DDL）——对齐**：同一 `node:sqlite` 句柄、同一「按项目根开库」、同一「单工具 + `action` 枚举」的交互形状、同一中文枚举进 `CHECK` 的写法。本面照抄这四样，不另立风格。先例批次坐标逐字在库头注：`2026-10-03 read-data-interface 批`（版本号落标）∥ `2026-10-07 批 ledger-tool`（枚举常量档单源）。
- **`doc_check`（`thincoder-core/agent-tools/doc-check.mjs`；抽取引擎 `thincoder-core/doc-check/anchors.mjs`；设计档 `docs/core/design/DOC-CHECK.md` §2.6 扩展名清单 ∥ §3.20 判据 ①）——对齐抽取面、偏离查询面**：抽取面直接复用；查询不并进 `doc_check`，理由见 §4 KD-2。
- **偏离台账的一处**：台账的写面是「用户点一下、工具改一行」；边表的写面是「扫一次、整档重写」。故边表按 `scope`（引用方那一档）整档替换，不做逐边增删——文档改了，它那一档的边全换，没有「旧边留一半」的中间态。

### 数据事实检查

**需要读数据的断言 = 三条**，都在盘上读实（引文逐字在下；绝对读数住批档的实施记录；读法 = 对这三档跑一次带 `onEdge` 的 `checkAnchors`，看载荷里的节号字段）：

- **`F16` 那一行指向的是整档，不是 `§5` 那一节。** `依据 docs/core/requirements/TOOLS.md「判据 = 设计档 `docs/core/design/EDIT.md` §5」`——路径裹在反引号里，反引号之后才是空格与 `§5`，而 `ANCHOR_RE` 的节指示组只跨空白，**不吃反引号** ⇒ 抽出来的节号为空，dst 落在整档。
- **批档 §2 的 B1–B8 八行指向的是节，不是整档。** 那八行的档名**不带**反引号、`§5` ∥ `§6` 紧随其后 ⇒ 节号接得上：B1–B7 落 `doc:…EDIT.md#5`，B8 落 `#6`（B8 那一行还另带一个独立 `§5`——没有档就没有节，它不成指针）。
- **同一份批档另有几处把档名裹进了反引号**（如「`EDIT.md` §5 说『`rename` 串是唯一残留的非原子窗口』」、「`EDIT.md` §6 五处『未落』判词」）⇒ 那几处节号断开，dst 落在整档。这几处的 token 是**裸名**（`EDIT.md`，不带目录段）：`docNameExemption("EDIT.md")` 判 `null`（既不是类名、词干也不是占位）⇒ **不被豁免**，照锚面正常解析（裸名由解析会话按名索引解到仓内唯一同名档，`doc_check` 报告面「后缀兜底读数」记的就是这条腿）⇒ **成边、`dst` 落整档**，不是「被豁免成零边」。§2.5.1 的折叠依据不依赖这几处：需求档那一处（整档）与批档那八处（按节）是两条各自成立的读数。

三条同时成立 ⇒ 同一份设计档上**整档与按节两种 dst 并存**，而且两种都在同一份引用方档里出现。§2.5 的**档级邻接折叠**就是为这件事定的，不是为方便。

## 2. 接口契约

### 2.1 节点身份（闭集八种）

```
req:<编号>              例 req:F16 ∥ req:AC-1
doc:<仓相对路径>        例 doc:docs/core/design/EDIT.md
doc:<仓相对路径>#<节号> 例 doc:docs/core/design/EDIT.md#5
case:<用例编号>         例 case:CLI 41-1
symbol:<符号名>         例 symbol:editTool
ledger:#<行号>          例 ledger:#2236
board:<板块名>          例 board:core
session:<会话 id>       例 session:<会话标识>
```

**身份按目标算，不按字面算**（F6）：同一种说法指同一目标才同节点。盘上已有的一个实例：RTM 行写 `41-1`、族号只在节标题 `## CLI 41.` 里、散文写 `CLI 41-1`——**三种写法，一个节点** `case:CLI 41-1`（拼法见 §2.2 的 `case-file`）。

**整档与它的各节是两个节点，不是同一个。** 节号等值即身份（KD-7）：`doc:P` 与 `doc:P#5` 是两个节点，因为写的人确实指名了不同的落点；把两者归一会让「这一处究竟指的哪一节」这个事实消失。**它们之间怎么连**由 §2.5 的查询规则回答（档级邻接折叠），不由身份面回答。AC-5「换说法的引用仍连得上」靠那条查询规则满足，不靠把两个身份并成一个。

**已知限度**：`req:` 的身份就是编号本身（全仓唯一假设）。两个需求档出现同一个编号会并成一个节点——本版不解（§7）。

### 2.2 边的形状与来源

边 = `(src, kind, dst, evidence, state)`。**存储六类** `kind`，每一类只有一个产出面：

| kind | src → dst | 产出面 | 依据（盘上实例） |
|---|---|---|---|
| `cites` | `doc:` → `doc:` / `doc:#N` | 锚抽取（档 token ± 节指示）∥ `依据` 行 | 抽取面现成；`依据` 行的 token 今天已判引文（`CITE_RE_SRC`），同一 token 已占区间，顺手成边不重抽 |
| `cites-req` | `doc:` → `req:` | 需求编号形（`F` + 数字 ∥ `AC-` + 数字），字符类取 `NAME_CH` 与那对边界 | AC-1 第一段：需求档 F16 那一行 |
| `mentions-case` | `doc:` → `case:` | 用例编号形（族名 + 空格 + `数字-数字`） | AC-1 第三段：批档写着 `CLI 41-1` |
| `case-file` | `case:` → `doc:` | **RTM 行配对**：行首格 `41-1` → 向上取最近的 `## CLI 41.` 标题得族号 → `case:CLI 41-1`；行末格的档 token 是 dst | 第四跳的桥：`依据 test/rtm/tooling.md「## CLI 41. 批量改多档」` |
| `cites-symbol` | `doc:` → `symbol:` | 反引号内的标识符（`NAME_CH` 字符类，且不是档 token、不是路径） | F2 列的锚形状之一；今天的码段扫描只跳不取 |
| `imports` | `doc:`（代码档）→ `symbol:` | `import … from "<说明符>"` 语句扫描；说明符解析到仓内档后取**具名导入** | 第五跳：`依据 test/integration/edit-batch-entry-outcome.test.mjs「import { editTool } from」` |

**`case:` 的拼法**：族号（节标题 `## CLI 41.` 里的 `CLI 41`）与行首格的用例号（`41-1`）**并成一个编号** `case:CLI 41-1`，两段数字不是串接。串接会得到 `case:CLI 41 41-1`，与散文里写的 `case:CLI 41-1` 裂成两个节点，第四跳（用例号 → 用例档）因此无出边。三处写法（RTM 行首格 ∥ 节标题的族号 ∥ 散文里的全名）合起来才是一个身份（§2.1）。

**只有一条方向**（KD-3）。反向查是索引查，不存 `imported-by` 这类镜像边——存两行就是两处记账。

**自环不入边**（AC-8）：**自环 = `src` 与 `dst` 逐字相同的边**——本档全文只用这一个定义（「自发边」∥「自指边」都是它，别处不再另给意思，需求档 AC-8 用的是同一个意思）。`src === dst` ⇒ 不产出边。拦截点只在产出面**一处**（`thincoder-core/doc-graph.mjs` 的 `makeSink.push`），六个 `kind` 共用——不进表、不进回执、不进走查；由写入侧产出的 `case-file` ∥ `imports` 两类同样经该点落边（§2.6 末段），故「一处」是字面的一处。

- **整档与它的节不算自环**：`doc:P` → `doc:P#5` 是两个节点（KD-7），照常落边。写的人指名了那一节，与「引自己这一整档」不是一回事。
- **为什么在产出面拦、不靠走查**：走查的「每节点只入队一次」只把环截短，拦不住坏边进表；而 `forward(P)` 上的自环字样会把「这一档引了谁」这条答案的第一行变成它自己。
- **旧库里的自环边不写迁移**：下次 `scan` 整表重写时自然消失（§2.3「整档替换，没有旧边留一半的中间态」）。

**`src` 不带节号。** `doc:#N` 只出现在 `dst`：引用处的节号既不进身份、也不进回调载荷（§2.6 载荷里的节号是**目标侧**解析出来的那一个）；引用方落在哪一档由 `src` 给，落在该档的哪一处由 `evidence` 的行号与行首片段给。理由：边回答「谁引了谁」，引用方是一份档，不是它的某一节——把引用处的节号写进 `src`，同一份档的出边会按节碎开，而读者要问的是「这份档引了哪些目标」。

**`case-file` 的行级上下文由谁持有**（三样：行首格、行末格、上方最近的节标题）：

- 行首格与行末格 —— `thincoder-core/doc-check/graph-tokens.mjs` 的 `rtmRowOf`（吃一行原文，吐 `{num, fileToken}`）；族号 + 行首格编号合成身份 —— 同档的 `caseNumberOf`；节标题取族号 —— 同档的 `rtmFamilyOf`。
- 「上方最近的节标题」是**跨行状态**，纯函数拿不到：它由**编排档**（`thincoder-core/doc-graph.mjs` 的 RTM 面对）持有——那一面对 RTM 档读一次、逐行过一遍，见节标题就更新族号游标，见用例行就配对产边。
- 故 `case-file` **不吃 `onEdge` 回调**：回调交的是「这一条 token 的只读副本」（§2.6 回调契约），里面既没有节标题也没有整行缓存。它与 `imports` 同属写入侧产物，同样经 `makeSink.push` 落边。

**`case:` 既入也出**：`mentions-case` 给它入边（谁提到这个用例），`case-file` 给它出边（这个用例的文件在哪）。少了后者，用例号就是死胡同——用例号到它那一份用例档没有任何边，AC-1 走查表第 4 跳（`case:` → 用例档）也无路可走。

**`state` 三值，判哪些身份写明**：

| 值 | 含义 | 适用身份 |
|---|---|---|
| `ok` | 判过存在性，且目标在盘 | 仅 `doc:` 族（整档 ∥ 带节） |
| `目标不在盘` | 判过存在性，目标不在盘 | 仅 `doc:` 族 |
| `判不了存在性` | 本面不判，或判不了 | `req:` ∥ `case:` ∥ `symbol:` ∥ `board:` ∥ `session:` 一律此值；`doc:` 族的「声明仓根不在本机」同此值 |

映射（一套东西两处说法，映射写死、第三套不许有）：`目标不在盘` ≡ `doc_check` 的判决词 `档缺`；`判不了存在性` ≡ `doc_check` 的 `unverified`（零命中、不入闸的那一格）。

`symbol:` 与 `case:` 一律「判不了存在性」是**如实**：符号不是档，判它在盘要读全部代码；用例号的存在性要另建一张用例清单。不判就说不判，不冒充 `ok`。

### 2.3 表结构（同库，不第二库）

```sql
CREATE TABLE IF NOT EXISTS doc_edges (
  id         INTEGER PRIMARY KEY,
  src        TEXT NOT NULL,
  src_label  TEXT,
  kind       TEXT NOT NULL CHECK(kind IN ('cites','cites-req','mentions-case','case-file','cites-symbol','imports')),
  dst        TEXT NOT NULL,
  dst_label  TEXT,
  evidence   TEXT NOT NULL,
  state      TEXT NOT NULL CHECK(state IN ('ok','目标不在盘','判不了存在性')),
  scope      TEXT NOT NULL,
  scanned_at TEXT NOT NULL,
  UNIQUE(src, kind, dst, evidence)
);
CREATE INDEX IF NOT EXISTS doc_edges_dst ON doc_edges(dst);
CREATE INDEX IF NOT EXISTS doc_edges_scope ON doc_edges(scope);
```

- 落点 = `thincoder-core/ledger-db.mjs` 的 `DDL` 串里加这一段（与 `items` 同一个 `db.exec`、同一个文件）；新表是结构变更 ⇒ `LEDGER_SCHEMA_VERSION` 升一号。**升号口径单源 = 本条**，本档其余各处回指本条，不各写一份。
- `evidence` 的形固定（读者据此自己点开那一处）：

```text
<引用方档的仓相对路径> @ <行号> 「<该行从行首起的 ≤ 80 字符原文；不足取全行；超出以 … 收尾>」
```

- **片段恒从行首切，不从被引 token 处切**：token 在一行里可能远在行末（`docs/core/requirements/TOOLS.md` 的 `F16` 行有数百字符，设计档那句在行末），从 token 切会把「这一行说的是谁」丢掉。行首是表格行的第一格（这一行关于谁）∥ 散文行的主句起点；行号 + 行首片段合起来才是读者认得出的那一处。代价如实：片段不保证含被引 token 原文——`dst` 已指明目标，片段回答的是「在哪一行」。
- **行号只作边的产地读数，不作节点身份**：节点指档案与符号，档里插一行不会让任何边失效。
- `scope` = 引用方那一档的仓相对路径。重扫一档 = 先按 `scope` 删、再插，别档的边零动。
- `scanned_at` = 这一行的产出时刻，**按 `scope` 一档一个值**：全仓扫时各档同值，带 `scope` 扫时只有那几档翻新。它是时效格（§2.5.4）的**唯一来源**——不另建元数据表、不加列、不做增量扫描。
- `dst_label` 存目标侧的标签原文：`doc:` 族存节标题原文（节号漂了还认得出），`case:` ∥ `symbol:` 存渲染出来的名字。`src_label` 同理存引用方的档名——这就是批档 §1 记的「节号 + 节标题双锚」，表里两列都存。

### 2.4 台账号不复制进边表（四列投影）

台账 `items` 的 `req_doc` ∥ `task_book` ∥ `board` ∥ `executor` 是四条现成的边（需求档 §1「这不是新系统」）。**查询面在内存里把它们投影成边读，不落进 `doc_edges`**（KD-4）：

```
task_book → ledger:#N --task_book--> doc:<指针的档部分>
req_doc   → ledger:#N --req_doc-->   doc:<档部分>
board     → ledger:#N --board-->     board:<名>
executor  → ledger:#N --executor-->  session:<会话标识>
```

`board:` 与 `session:` 是**身份闭集里的两格**（§2.1），不是闭集外的临时造物：它们只在投影面出现，`doc_edges` 里永不落这两类 dst。`session:` 是叶子——本版不给它出入别的边，它只回答「这一行是哪台会话动过的」，走查不会穿过它。

**投影边同样带 `evidence` 与 `state`**（边是四元 + `state`，投影面不缺这两样，§8「每条边后面必须跟 `evidence`」在投影面上才立得住）：

- `evidence` = `台账行 #<N> · <列名> = <dst>`——台账行没有行号，出处就是**行号 + 列名**；值原样印，不解析、不拼接。
- `state` 恒 `判不了存在性`：投影面不判存在性（`task_book` 的指针可以指到仓外档），不冒充 `ok`——与 §2.2 三态表的「本面不判」同一格。

链路查询因此是「`doc_edges` ∪ `items` 投影」的一次图走查，不是两套数据对账。

### 2.5 工具面：`doc_graph`，一个工具四种问法

| action | 参数 | 输出 |
|---|---|---|
| `scan` | `target`（项目根，必填）∥ `scope`（可选：只重扫这些档） | 首行 `全仓 · 扫 N 档`——**不带任何混合边总数**；紧跟按类计数行（§2.5.0）；时效格收尾（§2.5.4） |
| `forward` | `target` + `node`（+ 可选 `kind`） | 首行 `doc_graph(forward) · 起点 <node> · kind = …（按档折叠）`——不带混合条数；紧跟按类计数行；再逐条边 `kind → dst`，后随 `evidence` |
| `reverse` | `target` + `node`（+ 可选 `kind`） | 同上形，逐条边为 `src --kind-->`，后随 `evidence` |
| `chain` | `target` + `node` + `depth`（+ 可选 `kind`） | 首行口径（起点 / 深度 / 命中边数 / 节点数 / 生效 kind 集合）；紧跟按类计数行；再按边数分层的逐条边（下详） |

**参数零默认**：`node` ∥ `target` ∥ `chain` 的 `depth` 缺任何一个 ⇒ 边界拒，报文明点缺的那个参数名。两个可选参数（`scan` 的 `scope` ∥ 读动作的 `kind`）是**可选但缺席有明说的读法**——输出首格恒写 `全仓` 或 `范围 K 档`，`kind` 缺席时首行印本次生效的整集，缺席的含义被印出来，不靠记。

**回执行序（单源 = 本条）**：① 降级读数（无需求层时两行，§8）→ ② 首行口径 → ③ 按类计数行（§2.5.0）→ ④ 回调异常行（有则，仅 `scan`，§2.6）→ ⑤ 边行（三个读动作；`scan` 无此段）→ ⑥ 时效格（§2.5.4，**恒为末行**）。以下各节只写各行自己的形，位置只在本条定。

#### 2.5.0 按类计数（四个回执共用的形）

**四个回执各自紧跟一行按类计数**，形固定（只列**本次有边的类**，列序 = 闭集序：存储六类在前 ∥ 台账投影四类在后；每个列出的类后面跟三格状态格；整份回执一条边也没有 ⇒ `按类：（本次无边）`）：

```text
按类：cites 3 条（已验存在 3 ∥ 目标不在盘 0 ∥ 判不了存在性 0） · cites-symbol 11 条（已验存在 0 ∥ 目标不在盘 0 ∥ 判不了存在性 11）
```

- **三格恒印，零也印**：恒印的是**所列每一类的三格**（零边的类不列一行，见上），格内不按状态省格——省成两格就要读者记住「哪几类能判存在性」（§2.2 的三态表），而「这一类从来判不了」正是零格要传达的信息。
- **`cites` 与 `cites-symbol` 永不共格**（AC-7）：同一份设计档上 `cites-symbol` 的条数比 `cites` 多出量级（前者是反引号标识符、一律判不了存在性；后者是档引用、多数 `ok`）——合成一个总数，读者会把那一大堆反引号标识符当成验过的引用。
- **混合总数不作首行**：`scan` ∥ `forward` ∥ `reverse` 的首行不带任何混合边总数，**无例外**。`chain` 首行的「命中 E 条边 / V 个节点」保留，但那两格要说清是什么：**走查规模的口径**（走了多深、碰到多少），回答「这一跑展开到哪儿」，不是「各类边各有几条」。AC-7 禁的是**拿一个混合边总数替掉各类的分布**，而 `chain` 的类分布同样只在紧跟的按类行里给；首行那两格既不当边类读数用，也不进任何判据。
- **数的是「本次回执所依据的那批边」**：`scan` = 本次落库的边；`forward` ∥ `reverse` = 滤后全量（它们不截断）；`chain` = 走查命中且**已展开**的那批（被宽度截掉的层内边不在内，那一层的真实条数由该层自述行给）。数出来的数与下面印出的边是同一批。

#### 2.5.1 档级邻接折叠（查询面合并，身份面不合并）

**规则**：查询与走查把**同一档的各节视为共用同一批邻居**。查 `doc:P` 与查 `doc:P#N` 得到的是同一批邻边，逐条按**它真实的身份**打印（一条边的 dst 是 `#5` 就打成 `#5`，是整档就打成整档）。

**为什么必须有这条**：盘上同一份设计档被两处不同写法引用——需求档那一处是整档（反引号隔断了节号），批档那八处是 `§5`（§1「数据事实检查」）。若邻接也按身份隔开，`req:F16` 那条链走两跳就断在「整档 vs 节」这个纯书写差异上，而书写差异不是关系不存在。

**它不破坏 AC-5 的前提**：身份仍是两个节点，所以查 `doc:P#5` 时「谁按 §5 引的」与「谁按整档引的」在输出里是**两条不同的行**（`dst` 各自原样），读者分得清；AC-5 要的是「两条都在」，正是这个并集给的。

#### 2.5.2 `chain` 的走查规则（写全，不留「应该能连上」）

1. **一步 = 一条边**：正向边与反向索引都算一步，允许正反交替。交替是结构决定的，不是选择——`cites-req` 的 src 恒是 `doc:`，从一个 `req:` 节点出发，第一步**只能**反向走。
2. **分层**：按到起点的**边数**分层（第 1 跳 = 一步之邻，第 2 跳 = 两步之邻，以此类推）。输出逐条边，形为 `<第 n 跳> src --kind--> dst`（反向走的一步印 `src <--kind-- dst`），后随 `evidence`。**每一步都记「起点 → 落点」**：正向步起点 = `src`、落点 = `dst`；反向步起点 = `dst`、落点 = `src`，打印形不变。通路接不接得上按「上一步的落点 = 下一步的起点」读，**不按打印出来的列序读**——反向步把 `src` 印在左端，落点却在那条线的右端。
3. **每节点只入队一次**（按折叠后的档级格），走的是通路不是游走：同一个节点不会被同一条链踩两次，环自然截断。
4. **跳数按边数，不按节点数**，且这一口径在输出首行印出来：`走查起点 <node> · 深度 <depth> 跳 · 命中 E 条边 / V 个节点`。紧跟一行按类计数（§2.5.0）；时效格在回执末尾（§2.5.4），中间是分层的边行。
5. **截断要明说，分两种，各印各的**：
   - **宽度截断**：一层最多印 `LAYER_CAP = 200` 条边（`200` 是契约常量——改它就是改回执的可读性上限）。超了 ⇒ 该层照排序印**前 200 条**，紧跟一行 `本层并列 M 条，此处印前 200 条；收窄办法 = kind=<取值>（第 n 跳）`，`M` 是该层真实条数。**哪一层截了就在那一层说**，不许静默截，也不许只在末行总说一句。
   - **深度截断**：走满 `depth` 仍有未展开的邻边 ⇒ 在边行之后、时效格之前印一行 `已截断（depth = <depth>）：k 个节点未展开`，不静默交出一条看着完整的链。
   - 两种截断不合并成一行：一个是「这层还有多少没印」，一个是「再往下一跳没走」。
6. **不排相关度**（§7）：同一层内按 **`dst` → `kind` → `src` → `evidence`** 四键字典序，不分「哪条更重要」。后两键只在「同 dst 同 kind」时生效——只排前两键，前 200 条就落在库内行序上，「同一跑两次相同」只是碰巧成立。四键与输入顺序无关：同一跑两次取到的前 200 条逐字节相同，被截掉的那部分于是可复现、可用 `kind` 收窄取回（§2.5.3）。
7. **`chain` 不替读者挑路**：同一层并列的边在宽度上限之内全部打印；超上限的那部分由 §2.5.3 的收窄入口取回，不由本面替读者猜「哪一条重要」。要问「某一条特定通路连不连得上」，读者按 `evidence` 逐条点开看。

#### 2.5.3 收窄入口（`kind`）：被截掉的东西仍取得到

`kind` 是 `forward` ∥ `reverse` ∥ `chain` 三个读动作的**可选**入参：逗号分隔的 `kind` 子集，**可给的值 = 存储面的六类**（§2.2；取值单源 = `thincoder-core/ledger-db.mjs` 的 `DOC_EDGE_KINDS`，`doc_edges` 的 `CHECK` 由它生成——一份闭集，两个消费面）。它作用在**读出的那一批边**上——先滤、再排序、再分层、再按上限印。收窄之后的那一跑是完整的一跑，不是「大回执里抽了几行」。

- **缺席 = 不滤**（十类全收）：存储六类 + §2.4 台账投影的四类（`task_book` ∥ `req_doc` ∥ `board` ∥ `executor`）。投影是链路的那一半，滤掉它不是「收窄」，是把一半链路关掉——`forward(ledger:#N)` 会静默变空。首行恒印本次生效的集合，缺席的含义被印出来，不靠记。
- **收窄只收存储六类**：投影四类没有收窄入口（它们不落 `doc_edges`，见 §2.4），给了就拒，拒文里点名这四类并说明「不传 `kind` 即全收」。
- **可给范围外的值 ⇒ 拒并点名那个值**（如 `kind=mentions`）：静默当空集就是让「没这类边」冒充「没边」。
- **被宽度截掉的部分这样取回**（**只限「收窄压得进上限」的层**）：截断行点名了层与可用的 `kind`，按它收窄重跑，那一层就落在上限内——夹具层与中等层宽（构造出来的几百条、分属多类）属于这一类，§6 用例 11 押的就是它。**真实枢纽不在此列**：某一类 `kind` 自己就超上限时（如 `cites-req` 单类即超 `LAYER_CAP`），任何保住通路的收窄都压不进去（§7「已知限界」），那类「这条边在不在」的问题由无上限的 `forward` ∥ `reverse` 直查回答。故截断行必须写出收窄办法，而不只是报个数。
- **`forward` ∥ `reverse` 不设上限**：它们是单节点直查，读者问的就是「这个节点有什么邻边」，那个条数首行已印，截它等于不回答；真嫌多，用 `kind` 收窄。`chain` 需要上限，是因为层宽 = 前沿 × 邻接，是深度的乘积，不是任何一次直接提问。
- **收窄后的空集与空图分开说**：「该节点在本次收窄的 kind 集合里没有出边」不是「该节点没有出边」——后者会被读成降级。

#### 2.5.4 时效格：图建于何时、此后变了多少

**来源 = `doc_edges.scanned_at`**（每行都带，按 `scope` 一档一个时刻，§2.3）：全仓扫时各档同值，带 `scope` 扫时只有那几档翻新——不另建表、不加列、不做增量扫描（AC-9 明写不做增量）。四个回执**末尾各一行**：

```text
图建于 <T>（<K> 档同批） · 此后 <N> 档变更 · <D> 档已不在盘
图建于 <Tmin> … <Tmax>（各档时刻不一，<K> 档） · 此后 <N> 档变更 · <D> 档已不在盘
```

**上面两行是形，不是本仓读数**：`<…>` 是占位，本仓的实际读数住批档的实施记录。

- **怎么算**：读面按 `scope` 分组取每档的 `scanned_at`，比该档文件的 `mtime`；`mtime` **严格大于**该档时刻 ⇒ 计入「此后 N 档变更」；该档文件不在盘 ⇒ 计入「已不在盘」（那不是变更，是这档没了——AC-6 的信号在时效格上先露一次头）。一次目录走：不读全文、不解析、不落库。
- **`K` = 0（库里一条边行也没有）**：这一格印 `本仓尚无落边的档：时效不可算（先跑 scan）`，**不印**「此后 0 档变更」——零行时「0 档变更」是假话，它把「没东西可量」读成「什么都没变」。
- **扫描之后新增的档这一格看不见**：新增档没有行、没有时刻，因此不进「此后 N 档变更」。也不能靠同一趟目录走顺带报「新档 N」：盘上有、库里无行的那些档，既可能是扫后新增，也可能是扫过但零边，现有数据分不开，报出来就是猜（§7 已知限界）。
- **为什么不拿全图最大时刻一把比**：带 `scope` 扫过一档之后，`max(scanned_at)` 是刚翻新的那一档，其余各档的老化被这个新时刻一并洗掉——那正是「写着 0 档变更而盘上确有变」（AC-9 的失效面）。逐档比才如实。
- **严格大于**：等于不算变更——同一次落盘写出的档不会被算成「扫完又改过」。
- **`K` 恒印，两形都印**：同批那一形印「`<K>` 档同批」，各档时刻不一那一形印「各档时刻不一，`<K>` 档」——`K` 是「此后 N 档变更」的分母，两形缺了它，读者只知道变了几档、不知道共几档（§7 已知限界：零边档与扫后新增的档不在读数内；`K` = 0 印专句，见上）。
- **`chain` 也印**：走查跨的边越多，读者越需要知道这份图有多旧；回执里没有第二个地方回答它。

#### 2.5.5 两个变体：全量（depth-0）∥ 只读（子代理段）

**同一把工具两个装配形**，name 同为 `doc_graph`，互斥装配——depth-0 主 agent 段挂全量、全部 depth>0 角色段挂只读。装配矩阵单源 = `docs/core/design/AGENT-LOOP-SUBAGENT.md` §6.60.2；本节只写变体自身的契约。

| 面 | 全量 `docGraphTool` | 只读 `docGraphReadTool` |
|---|---|---|
| action 枚举 | `scan` ∥ `forward` ∥ `reverse` ∥ `chain` | `forward` ∥ `reverse` ∥ `chain` |
| `readonly` | `false`（写性按 action 判） | `true`（无写 action 可判，故工具级为真） |
| 调 `scan` | 照跑 | execute 拒，报文点名那个值、只印本变体的三值 |
| 描述面 | `DESC("doc_graph")` | 同 + 一句追加说明（逐字住 `docs/core/design/AGENT-LOOP-SUBAGENT.md` §6.60.2 ②） |

- **变体在 `execute` 再拒一次**：schema 的 action 枚举是**建议性**的（provider 不强制），枚举外的值必须由入口拒。这是 §2.5.3 同一条纪律落在同一把工具的另一形上。

- **不新增第二个工具名**：叫 `doc_query` 会让文档面与工具面对不上；同名窄化是本仓既有形（`ledger` ∥ `manifest` 的只读变体同律）。

### 2.6 抽取面怎么接（一次遍历，两个消费者）

`checkAnchors` 增一个可选入参 `onEdge`（回调）。**调用点钉在全部跳过谓词之后**，七处一律先过（`cites-symbol` 对其中 ② 是例外，见下方专段）：

① 围栏块（`fence !== null`）② 码段区间（`inSpan`）③ 花括号组区间（`inBrace`）④ 引文占位区间（`cited`）⑤ 档名豁免（`docNameExemption`）⑥ 扩展名清单（`isDocToken`）⑦ 面判（`isBatchFaceRef`——批档面互引照旧不产边，与它不产命中同一个理由）。

**`cites-symbol` 不吃码段区间谓词（②），另六处照过。** 区别不在「松一档」，在取形面在哪：

- `cites-req` ∥ `mentions-case` 与既有锚面一样从**行内文本**取形，码段是它们要绕开的「这里不是引用」的区域，所以 `inSpan` 必须先过。
- `cites-symbol` 的取形面**就是码段本身**，套上 `inSpan` 等于把这一支整个关掉。依据 thincoder-core/doc-check/graph-tokens.mjs「for (const span of codeSpans(line)) {」——候选逐段来自码段区间，没有码段就没有候选。

档 token 归锚面（那条已由 ② 管着），故本支另走「不是档 token、不是路径」两道守卫（§2.2 表），不在码段里把档名重抽一遍。

**回调契约三条**（写死，实现不得自行放宽）：

- 回调**不得抛**：`checkAnchors` 用 `try/catch` 包住每一次调用；抛了记一条 `回调异常` 读数（有则一行，仅 `scan` 印；位置 = 按类行之后、时效格之前，§2.5 回执行序），`hits` 与返回值零改。
- 回调**不得改**返回值：它拿到的是这条 token 的**只读副本**（档、行、token 原文、节号、解析态），拿不到 `hits` 数组。
- **回调缺席 ⇒ 行为逐字节不变**：判定面、命中面、读数面全零改。这是「零行为变更」的**确切范围**——本档新增的调用与三支新家族**只喂回调、不进 `hits`**，故 `checkAnchors` 的返回值与今天逐字节相同。

三支新 token 家族的**取形**住 §3 列的新档（纯函数：吃一行文本与上下文，吐候选 token），由 `checkAnchors` 在**同一个 `forEach` 行体里**调用；它们的**解析**走同一个 `resolveToken`（同一个解析会话），不新开解析器、不回头重读档。

**码段谓词照旧先过，但码段区间只在可执行行上切**：`依据 thincoder-core/doc-check/anchors.mjs「可执行行**只跳码段区间**」`——表格行 ∥ 散文行里裹在反引号中的 `F16` ∥ `CLI 41-1` 照抽。三支新家族与既有锚面同吃这一条，不改它。

代码档的 `imports` 边不吃这个回调（它要读的是 import 语句，不是文档锚），由边表的写入侧扫一遍——同一档读一次，不回头重读。**RTM 面的 `case-file` 同理**（它要的是跨行的节标题游标，见 §2.2「`case-file` 的行级上下文由谁持有」）。**这两类同样经 `makeSink.push` 落边**：六个 `kind` 一个落点，自环拦截与去重因此对全部六类一律生效——「产出面一处」这句话把写入侧那两类也算在内，不是只给回调那一半说的。

- 成功解析的那一支今天**什么也不产出**，正是要接的位置；
- 失败的那一支已经在 `hits` 里，回调拿同一条记录，`state` 记 `目标不在盘`——**边照落**（AC-6：不静默丢弃、不猜替代目标）；
- `unverified` 那一支（声明仓根不在本机）⇒ 回调拿 `state` = `判不了存在性`，同样落边、不入闸。

### 行数档位口径

**来源（用户原话，逐字）**：「500行其实也不应该再叫软线了，对于设计器来说，它就是硬线，只有设计器拿他做硬线。其他检查都是以800行为硬线。这样也就不用纠结该拆不该拆了。」

**要的就是机械化**：两条都是硬线，不留「审视后自行判断」的余地，也不留第三个判断点。

**同口径的另一处**：工作区根的 `AGENTS` 档（Coding Conventions · File size）写同一件事，逐字如下。

```text
File size (source and unit-test files only): two hard lines, no advisory tier.
500 lines = the designer's hard line — at design time, measured on the file before this batch's changes
800 lines = every other check's hard line — implementation, closeout and review judge only this one
There is no third line and no "looked at it, decided not to split" verdict.
```

两处互指，不是一处说了算：任一处改动，须同轮改另一处；两处措辞打架时先停下对齐，不各写各的。

**对象**：代码档（源文件 ∥ 测试文件）。文档面（设计 ∥ 需求 ∥ 批次 ∥ 台账）不受行数限制——依据 `docs/core/requirements/ENGINEERING-MODE-V2.md`「文档（设计 / 需求 / 批次 / 台账）不受行数限制——无任何行数义务」。

**① 设计器硬线 = 500（只有设计轮用这一条）**

- **过 500（> 500）⇒ 必须给分拆方案**：拆哪几族、切在哪、为什么切在那里。硬性义务，没有裁量空间——「接受本次载荷、拆分另批」不能替方案。
- **未过 500（≤ 500）⇒ 不提分拆**：不进分拆讨论，不写方案，也不写「故不拆」一类判断。

## 4. 关键决策记录

**KD-1 · 边从 `doc_check` 的遍历里旁挂产出，不新写解析器**（F2）。被拒：另写一个独立的边抽取器去读同样的文档。同一份文档被两套解析器读，两边迟早给出不同答案，而边与判定一旦分叉，「这条边为什么 `doc_check` 没报」就没有答案。

**KD-2 · 新工具 `doc_graph`，不并进 `doc_check`**。被拒：给 `doc_check` 加一个图查询的 action。`doc_check` 的返回面是**判决**（首行 `DOC-CHECK GATE: PASS/REFUSED`，有 verdict 词、有闸门语义）；塞进查询面，读者与脚本都会把非判决输出按判决解析，而需求档 §3 明写两者「判的东西不同，不合并」。代价是多一个工具描述档与那个计数常量——已列进受影响文件。

**KD-3 · 只存一条边，反向靠索引**。被拒：`imports` 与 `imported-by` 各存一行。同一事实两行，删一处漏一处。

**KD-4 · 台账号不复制，查询面投影**。被拒：扫台账时把 `task_book` 等四列灌进 `doc_edges`。理由同上，且台账行会变（状态迁移、`task_book` 改指针），复制出来的边立刻过期。

**KD-5 · 边落库带三种 `state`，失败也落**。被拒：只落解析成功的边。AC-6 要求端点不在盘时明说，而反向查恰恰最需要看见「这档已经没了但还有三处在引它」；只落成功的边正好把这个信号丢掉。

**KD-6 · 用例到代码只认 import 边，不做断言字面量近似匹配**。被拒：用断言里的字符串去猜它指的是哪个符号。需求档 §3 第一行已裁定；近似匹配是语义反推，与本档「不引大模型抽边」的边界相冲，且会让「链断没断」这个判定失真（一条要标「弱」才敢用的边，不如没有）。

**KD-7 · `doc:<path>#N` 的 `N` 按字符串等值判，不做数值比较，也不与整档归一**。理由：`§5` 与 `§05` 是两处写法，把节号归一化会顺手把「标题里恰好有别的数字」也归进来；`doc_check` 判节在盘今天就是字符串等值，本面同一把尺。节标题的容错走 `dst_label`，不走数字。**与整档不归一**：写的人指名了不同落点，归一会让这个事实消失；两者怎么连是查询规则的事（KD-8）。

**KD-8 · 查询面按档折叠邻接，身份面不折叠**。被拒：只做单向并入（查 `doc:P#5` 时并入整档引用，查 `doc:P` 时不向各节展开）。理由 = §1「数据事实检查」的两条读数：需求档那一处是整档、批档那八处是 `§5`，单向并入会让 `req:F16` 那条链断在一个纯书写差异上。代价 = 查整档时结果集变大；收益 = 「一处写整档、一处写节」不再被当成两条无关的边。身份不折叠这一半保住了 AC-5 的分辨力。

**KD-9 · `case:` → 用例档的边来自 RTM 行配对，不来自猜**。被拒：拿 `mentions-case` 的 dst 去仓里按文件名猜用例档（把 `CLI 41-1` 猜成某个测试档名）。猜法是语义反推，与 KD-6 同一条边界；RTM 行本来就是「一行一个用例 + 末列写它的档」这个事实的登记处，照登记处连，那是读出来的关系，不是猜出来的。

**KD-10 · 按类计数，混合总数不作首行**（AC-7）。被拒：保留混合总数作头行、把分类数另列一行。同一份设计档上 `cites-symbol` 的条数比 `cites` 多出量级（前者是反引号标识符、全落「判不了存在性」；后者是档引用、多数 `ok`）——混合总数不仅没信息量，读法还是反的（读者会以为那一大堆都验过了）。代价：回执多一行；收益：读者一眼分得清「验过的引用」与「被抽出来的标识符」。

**KD-11 · 自环在产出面拦，不在走查或判据里拦**（AC-8）。被拒：① 落表时靠 `UNIQUE` 去重顺带挡掉（它只挡「同行同写法」的重复，不挡自环）；② 走查里碰见 `src === dst` 就跳过（表里已有的坏边照旧会被 `forward` 印出来，而 `forward` 恰是最先被问的那一面）。拦在 `makeSink.push` 一处，六个 `kind` 共用。

**KD-12 · 时效格复用 `doc_edges.scanned_at`，不另建元数据表**（AC-9）。被拒：新建 `doc_graph_meta(k, v)` 存一个全图建标时刻。理由：① 带 `scope` 扫一档后，全图单值要么洗掉其余各档的老化、要么反过来高估，而「一档一个时刻」本来就在每行上；② 为一行读数加一张表要连带改 `LEDGER_SCHEMA_VERSION`（又一轮版本硬断测试跟改），换来的只是同一个数。代价：零边档不在读数内（§7 已记）。

## 7. 边界（本设计不做的事）

- **不做运行时覆盖**，不问「哪个用例真跑到了这个符号」。那要插桩跑测试，需求档 §3 已划到本版之外。
- **不做断言字面量的近似匹配**（KD-6）。
- **不做语义相似度**：`dst` 按目标身份连。同一概念换两个名字认不出——需求档 §1 已把这一条作为取舍写明，本版不管。
- **不做降级的第二级（代码 ↔ 会话记录）**：F5 的第二级要一个「会话记录」面，而会话记录的存储面住用户数据目录、不在 `docRoot` 任何一层里；要它就得开第二个抽取面，与 F2「一套解析器」相冲。本版落到第一级（无需求层 ⇒ 仍出 `case-file` ∥ `imports` ∥ `cites-symbol` 这些不依赖 `docRoot.requirements` 的边）。**本版不建第二级**：需求档 F5 那一句同轮标为过期——同一件事只能有一处要求，需求面留着它就与本节相反。
- **不治「目标档删掉后裸名身份漂移」**（本版已知代价，交父侧知会）：
  - **行为**：目标档被删后重扫，裸名 token 的 `dst` 印**写出来的那个 token**，不再印删档前解析出的仓相对路径。
  - **为什么**：「扫一次、整档重写」不留旧边；要治它得引入跨轮记忆（沿用上一次解析结果），本设计里没这个机制。
  - **后果**：反向查原先那个已解析身份不再命中；「这档没了但还有人在引它」只在**按 token 查**时可见。AC-6 仍成立（`state` = `目标不在盘`、`dst` 不替换）。
- **不解编号撞号**：`req:` 身份就是编号（§2.1 已知限度）。
- **不做常驻索引**：`scan` 是一次性动作，没有 watch、没有后台进程。
- **时效格量的是「已落边的档」**：两类档没有行、没有时刻，因而都不计入「此后 N 档变更」——① 扫过但一条边也没产出的档；② 扫描之后**新增**的档（§2.5.4）。回执也不报「新档 N」：盘上有、库里无行的档，两类都符合这个描述，现有数据分不开，报出来就是猜。要覆盖得给扫过的档单开一张清单表（连带 schema 版本号），为一行读数加一张表不划算，本版不做；`K` 印出来就是为了让读者知道这把尺量了多少档，`K` = 0 另有专句（§2.5.4）。
- **不判内容质量**：边只记「谁引了谁」与「目标在不在盘」。
- **不给搜索结果排序**：`forward` / `reverse` 按 `kind` → `src` → `dst` → `evidence` 四键字典序（键集与 §2.3 的 `UNIQUE(src, kind, dst, evidence)` 同一份，故行序确定）；`chain` 的层内按 `dst` → `kind` → `src` → `evidence` 四键（§2.5.2 第 6 条）。两者都不分相关度——本面没有「相关度」这个概念。
- **已知限界（限「每类 `kind` 自己就超上限」的真实枢纽）：`chain` 在枢纽节点上收敛不到上限，远端节点看不进一条回执。** 层宽 = 前沿 × 邻接，在枢纽上是指数级的乘积：从 `req:` 出发第一步**只能**反向走 `cites-req`（§2.5.2 第 1 条），滤掉它链就断在起点；留着它，下一层就是「所有写过这个编号的档」的全部邻边——两边都不落在上限内。层内又按 `dst` 排序，`symbol:` 一类目标恒排层末，故凡落进超限层的符号目标必被截。**放大上限不是答案**（那只是把一份读者看不完的回执换回来，换回的仍是同一批边）：将来要用的是 **`path` 式直查（给定源与宿，问一条单路径）**，而「这条边在不在」由无上限的 `forward` ∥ `reverse` 回答。本版不做 `path`。**夹具层与中等层宽不在此列**——那里按 `kind` 收窄能把被截的边取回（§2.5.3 ∥ §6 用例 11）。

## 8. 交互决策（查询面读什么、怎么读）

- **输出是文字，不是图**（需求档 §3 已定）。一行为一条边，形状沿用 `ledger` 查询面的「一行一条 + 读数行」。
- **每条边后面必须跟 `evidence`**：读者看的是「它长在 `docs/core/design/EDIT.md` 第 5 节那一条里」，不是一个孤零零的节点名。
- **三态显式**：`目标不在盘` 与 `判不了存在性` 在输出里各是一格，不用颜色、不用省略号表达。
- **空结果的形状与降级分开**：「本仓无需求层」是降级读数，「该节点没有出边」是空结果；两者文案不同，否则用户第一次问就得到空白会认为功能坏了（F5 的原话）。收窄后的空集是第三句（「在本次收窄的 kind 集合里没有出边」）——收窄后的空集不是这个节点没邻居。
- **按类计数，混合总数不作头行**：`cites` 与 `cites-symbol` 分格报，各带「已验存在 ∥ 目标不在盘 ∥ 判不了存在性」（§2.5.0）。为什么：`cites-symbol` 在一份设计档上往往比 `cites` 多出量级且一条也验不了，一个混合总数会让「几十条验过」读成「上百条都验过」。数与边表实际行数对得上；回调异常有则另占一行。
- **每个回执末尾带时效格**（图建于何时 ∥ 此后几档变更 ∥ 几档已不在盘，§2.5.4）：读者常在扫完很久之后才来查，这一格是他判断「这份图还能不能信」的唯一读数。
- **自环不入回执**（§2.2）：`forward` 里不出现 `src` 与 `dst` 逐字相同的行。引自身某一节的行照常出现——`doc:P → doc:P#5` 是两个节点（KD-7），§2.5.1 把整档与各节折进同一批邻居，故那一行会印在 `forward(P)` 里；它说的是「这一档按 `#5` 引了自己那一节」，与「它自己」不是一件事。
- **`chain` 的首行写清口径**：起点、深度、命中几条边、几个节点（§2.5.2 第 4 条）——「五跳还是六条边」这种数，读者一眼能对上。
