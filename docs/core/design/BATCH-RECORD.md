# 批次档与段写入（BATCH-RECORD）· 设计

> 需求 = `docs/core/requirements/ENGINEERING-MODE-V2-SPEC-BATCH-SEGMENT.md`。
> 最近先例：`docs/core/design/LEDGER.md` 的逐行写核和 `PATH-RESOLUTION.md` 的统一解析。对齐 = 写前校验、失败零假成功；偏离 = 本档负责六段与生命周期。
> 勘察证据：已读当前 batch 工具契约、批次需求与联动设计。相关 = 动作、段写权、状态行和收口。

## 1. 载体机制

批次档贯穿一轮工作的讨论、设计、评审、批准、实施和收口。路径由 docRoot.batches 与显式参数决定，不假定本仓布局。

批次档是过程记录，可清理；长期规则必须进入状态文档。

## 2. batchDoc 与 spawn 门

eng-coder 与 eng-designer 必须携带可读 batchDoc。普通模式 coder 可选绑定，绑定后获得自己 §5 的记录通道。

子代理 append/edit/status 不接受任意目标路径，目标来自绑定。depth-0 可显式 path；缺省时只有唯一在途批才可省略。

评审的 batchDoc 通过评审实例键传递，不使用全局“当前批次”状态。设计评审必须有当前账链；代码评审不强制设计凭证。

## 3. 交界面

- 任务、凭证和批次路径通过参数传递。
- 子代理写自己的段，父侧不代写为常态。
- 需要用户决定时上报主 agent。
- 写不进去时明确说哪段未写入。
- 多批并发不得串档。

## 4. batch 工具

### 4.1 动作与段写权

动作 = create、attach、append、edit、status、close、supersede、check。

| 身份 | 可写段 |
|---|---|
| 主 agent | 工程：§1/§4/§6；普通：§1/§2/§4/§5/§6 |
| eng-designer | §2 |
| advisor | §3 |
| eng-coder | §5 |
| 普通 coder，已绑定 | §5 |

create/attach/close/supersede 只由 depth-0 主 agent 执行。check 只读。

append/edit 使用同一身份段域。append 在段尾添加；edit 用 oldText/newText 精确替换自己段内区间，newText 空表示删除。

### 4.2 档绑定

| 调用方 | 绑定来源 |
|---|---|
| eng-designer / eng-coder | spawn batchDoc |
| 普通 coder | 可选 spawn batchDoc |
| advisor | 当前评审实例 batchDoc |
| 主 agent | 显式 path 或唯一在途批 |

绑定之外的批次档写入按跨批写门处理。批次自己的合法伴随件按当前规则处理，不借此扩大授权。

### 4.3 工具挂载

工程角色和绑定评审获得相应 batch 变体。未绑定的普通 coder 不获得 §5 写通道。工具是否存在与动作是否允许都要符合当前角色。

### 4.4 §3 评审记录

每轮由工具生成 `### 轮次 N（评审子代理）`。正文包含结论表、独立 VERDICT 行和计数。

证据格使用节名、符号名或原文指针，不写行号。评审全文不复制进档。

append §3 必须恰有一种裁定。pass 与 changes-required 同现时拒绝。工具根据裁定维护 §3 状态行。

### 4.5 提示词与工具描述

提示词说明各角色的写入手段、拒收、失败上报和当前记录形状。工具描述是参数与动作的即时使用契约。

### 4.6 文档与结构检查

append/edit 在写盘前执行当前文档检查。close/status→已收口检查本批变更区。

REFUSED 或无法形成有效通过结果时不得写成成功。检查范围按 DOC-CHECK，不另造规则。

### 4.7 不变量

- 段写权不削弱。
- 凭证不落档。
- 工具生成轮次。
- 状态行只有一个可读值。
- 失败明示。
- 并发批次隔离。
- 普通模式不获得工程机械门。

### 4.8 验证面

验证段域、绑定、骨架、路径、凭证剥除、轮次、裁定、状态行、冻结、重开、收口、补关、取代和 check。

### 4.9 状态读取与冻结

段头区内恰一条 `**状态行**：` 才可读。零条或多条均为不可判，不能取首条猜测。

已收口档冻结。状态不可判时写门 fail-closed；修复由主 agent 按当前文档写面执行。

### 4.10 骨架

create 一次写入六段标题、档头、台账与前情行、状态行和合法占位。死占位必须在正常写入前被真实值替换。

档头台账行支持单行多编号。占位只用于骨架，不能长期充当真实编号。

### 4.11 create

create 需要 path、topic、source，可带 ledger、board、prev、date 或预定指针认领。

它通过批次—台账事务创建或接手工作项，写骨架，再把真实行号与 task_book 绑定。目标已存在时拒绝，不覆盖。

### 4.12 status

status 只修改目标段受保护状态行。value 必须属于该段 STATUS_WORDS，note 只作为当前允许的附注。

append/edit 不得引入状态行。edit 可删除非受保护的冗余形态行，但不得让段头区状态行数量增加。

### 4.13 close

close 需要 path、completed、closeEvidence。它先检查链完整性、文档、凭证和工作项，再写已收口并结算。

close 不代写 §6。正常收口、补关和取代有不同前置，不能互相冒充。

### 4.14 路径归属

路径使用 PATH-RESOLUTION 与 batch-paths。读面要求可读，create 要求落在声明基底内并防止二次拼接。

工作区不向下猜项目。显式目标按目标所属项目处理。

### 4.15 引用

批次指针使用可解析文档路径与节名。引用长期规则时指向状态文档，不让状态文档引用批次作为规范来源。

### 4.16 普通模式

普通模式主 agent 折叠设计与实施管理席；绑定 coder 可写 §5。没有工程 designToken、强制 spawn batchDoc 或父侧写门。

评审工具的参数与账链契约仍按评审机制执行。

### 4.17 重开

status 将已收口 §1 改为进行中时必须带 note。工具追加重开记录，并回收允许回收的待核销行。

已核销和已废弃不因此复活。再次收口重新通过完整门。

### 4.18 收口分流

- 正常批：链完整、评审通过、用户批准、验证与完成证据齐全。
- 补关：行集全归档且唯一读数为 open-but-settled；不补造历史段。
- supersede：对象已消失或永不实施，并有真实 successor；结算已完成行，退回其他在途行。

### 4.19 edit

oldText 必须在作者段内精确命中一次。越段、触及受保护状态行、引入新状态行、超过当前大小限制或死占位均拒绝。

edit 改记录不等于追认实现；收口仍需对账 §2、§5 和当前设计。

### 4.20 指针形态

证据指针使用节号、符号名或逐字锚。行号不作为持久坐标。

### 4.21 状态行与 attach

状态行值由 status/close/reopen 等生命周期动作写入。其他文本通道只能减少冗余形态行，不能产生第二个可读值。

attach 给现有在途批次补挂新工作项。需要新 title，并更新档头编号列表。已收口档先合法重开或另起新批。

### 4.22 评审绑定

评审写面只获得当前评审绑定档的 §3 通道。评审在途冻结窗与 batch 段写是不同写路，按 ADVISOR-GUARDS 分别判断。

### 4.23 评审通过与凭证

设计评审结算判 pass 时，工具保证 §3 状态行与凭证签发一致。写档或凭证持久化失败时按当前补偿与回退规则处理，不留下假授权。

代码评审不签设计凭证。

## 5. 行为与生命周期

### 5.1 批次边界

交付目标、阶段或条目集变化时另起批次。单档过长是拆分信号，不在状态文档保存具体行数。

评审没有机械轮次上限；持续同一失败时停下上报。修复轮复用设计与凭证。

### 5.2 条目在别处完成

工作证据写进台账 evidence。锚批仍需收口；补关和取代不能伪造实施或评审记录。

### 5.3 §6 收口

§6 记录验证、文档对账、新债、用户确认和实际结算。没有文档改动时如实说明，不写虚假的 gate 通过。

### 5.4 落地核对

实施发现设计不成立时，修代码或走设计变更。不得把计划句留在状态文档后再以“陈旧”解释冲突。

## 6. 多端

core 提供同一工具与规则。端侧只负责宿主会话、权限和界面，不维护另一份批次状态机或段写权。

## 7. 关键决策

| # | 决策 | 理由 |
|---|---|---|
| D-BR1 | 路径由声明与参数决定 | 可移植 |
| D-BR2 | spawn 检查 batchDoc 存在与可读 | 内容质量由执行者与评审负责 |
| D-BR4 | 子代理路径来自绑定 | 语法上避免写别批 |
| D-BR7 | 工具剥凭证 | 不能依赖模型记得 |
| D-BR19 | 状态词分段单源 | 防止骨架与门漂移 |
| D-BR21 | depth-0 可显式 path | 多批在飞时需要定位 |
| D-BR26 | 段域模式感知 | 普通模式席位不同 |
| D-BR33 | 作者可 edit 自己段 | 修正引用和记录不能被迫只追加 |
| D-BR38 | 记结论与指针，不搬全文 | 减少重复与漂移 |
| D-BR41 | 状态行值只有一个写者 | 机器读取不能猜测 |
| D-BR42 | 现役档用 attach 接新事 | 不复活已核销行 |

## 8. 边界

不把批次当长期规范，不为普通模式添工程机械门，不做跨仓批档，不用 files 作为授权，不用语义猜测代替状态机。

已冻结档的变更通过重开或新批；需要长期保留的内容进入状态文档。
