# Advisor 评审链边缘守卫（ADVISOR-GUARDS）· 设计

> 需求 = `docs/core/requirements/ADVISOR-CONVERGENCE.md`。
> 收敛本体 = `ADVISOR-CONVERGENCE.md`；批次与凭证交界 = `BATCH-RECORD.md`、`DESIGN-TOKEN-SETTLEMENT.md`。
> 勘察证据：已读当前 advisor 工具描述、评审需求与路径规则。相关 = 启动顺序、受理面、凭证和失败回执。

## 1. 不完整判定族

### 1.1 单谓词

`advisorIncompleteMarker(text) → kind | null` 只读宿主生成的失败尾，不读模型自报。

| kind | 含义 |
|---|---|
| context_limit | 上下文预算耗尽 |
| turn_cap | 单场工具轮帽触发 |
| timeout | 墙钟预算耗尽 |
| empty | 无有效评审文本 |
| interrupted | 用户或系统中断 |
| review_failed | provider、transport 或执行失败 |

匹配块首行，避免把表格、引用或围栏中的相同文字当成失败尾。

三个消费点共用谓词：设计结算、代码覆盖记账和报告提示。

### 1.2 §3 记录与结算判据

设计评审的轮次块由结算写进批档 §3，这条只在工程模式的**设计轨**成立——代码轨没有结算进场，普通模式的结算整段跳过、不写 `§3`（判据是模式 × 评审轨，不是有没有设计凭证：设计凭证不分模式铸造），`§3` 仍由绑定评审席位写。设计轨的评审席在工程模式不写它，批工具的任何席位通道也不写它；块形单源 = `BATCH-RECORD.md` §4.4。

结算判据按序：

1. 批档可读——读不到 ⇒ `batch-unreadable`，零字节写。
2. 本轮块写进 §3 且回读见到它；pass 路径的段级状态行回读为「评审通过」，否则 ⇒ `status-not-passed`。

块与状态行进同一笔写，写不进即拒签——不留下有块无凭证的授权，也不留下凭证在而记录缺。

`changes-required`、无裁定行与未回显同样落块，结算头点名未签发：记录不拿凭证结果当过滤条件。被审档在结算前变了（封印算不出）或评审陈旧时不落块——它判的那份状态已不在。

`§3` 段头缺失属结构故障，写面 throw，不是给用户看的拒因。状态行由工具写，不由模型伪造。

设计实例没有 batchDoc 属于程序不变量违反；不得把它当作正常业务拒因后继续签发。

### 1.3 判定点

门位于凭证产生的 settle 点，因为这里能同时看到评审结果、批次记录和槽写。轮次块与状态行同在这一笔里，故不存在「块已落、字未到」的窗口。下游 §5 与核销仍保留独立校验。

判定点只在设计轨的结算。代码轨评审没有结算，记录落点与收口读数见 `BATCH-RECORD.md` §4.4——块由绑定评审自己写，收口门读 `§3` 段级状态行。

## 2. 启动与凭证守卫

### 2.1 构建与压缩

设计评审消息构建后若缺 Approval Signal，构建面补齐；启动前仍缺则拒绝。

上下文压缩后重新挂载对象声明、documents 清单和 Approval Signal。重型项目上下文可按预算丢弃，但必须按当前降级规则报告。

### 2.2 类型门

顶层 type 必须显式为 code 或 design。object.type 只声明对象，不选择轨道；两个不同合法值冲突时拒绝。

### 2.3 点火顺序

| 顺序 | 判定 |
|---|---|
| 1 | type 合法与一致 |
| 2 | design 的 batchDoc 非空 |
| 3 | batchDoc 可解析且可读 |
| 4 | design 有未决台账行指向该批 |
| 5 | documents 范围合法 |
| 6 | 实例绑定、凭证准备与模型调用 |

前提失败先报前提。拒绝启动不创建有效实例、不签发凭证、不消耗评审覆盖。

点火顺序第 2 项判的「批档缺失」是点火前可报的**前提失败**：拒绝启动，不进账链，不签凭证。§1.2 那句说的是已进结算的设计实例仍算出没有 batchDoc——那是**程序不变量违反**，throw，不当业务拒因放行签发。两处同一个条件、两个时点、两种结果，各管一面，不矛盾。

### 2.4 账链门

选行复用 resolveBatchRows，按解析后的同一批次地址判断，不比较指针字符串。

未决状态复用 PENDING_STATUSES。无项目根、库不可读或没有未决行都 fail-closed；不得因库不存在而放行。

该门只在点火判断。结算由 §1.2 的记录判据与当前批次状态保护。

## 3. 引文解析候选链

`verifyCitations` 使用当前 cwd 与评审对象声明派生候选根，不做全仓同名扫描。

命中需要：realpath 在允许围栏内、文件可读、当前行包含引文候选。

引文候选只剥离明确的外层引号与装饰，最终仍须是连续子串；不做模糊匹配或语义归一。

失败分类：

- file unreadable
- content mismatch
- path traversal
- not a contiguous citation (ellipsis)

候选已命中时不再判省略号失败。未通过校验的证据不能支撑打回，但条目仍须明确归宿。

## 4. 预算硬墙与提示

每次模型调用使用整场预算剩余时间构造中止信号。用户中止与预算中止分别处理；partial 结果也不能绕过超时判定。

接近预算耗尽时注入一次收敛提示。超时尾包含预算、轮次、工具调用、是否已有文本及恢复方向。

## 5. 冻结窗口

### 5.1 时点

机制窗口 = 点火受理到结算读取。父侧可观察下界 = 报告送达或取消/中止。子进程退出不是安全边界。

违规写入导致 stale 时，不签发凭证、不计评审覆盖。

### 5.2 写路

- documents 中的设计档：文件写工具命中即整档保护。
- 绑定批次路径：文件写工具命中即整档保护。
- batch 段写：不走文件路径冻结扫面；§1/§2 在评审期由流程纪律保护，其他段按业务需要记录。
- 不覆盖当前不可见的 bash/execute 等路径，不把它们宣称为已防护。

需要修改被审内容时先 cancel，再改，再重发。

### 5.3 判据同源

冻结和陈旧判定复用同一规范化路径与实例绑定。只处理仍在运行且未取消的设计评审。

## 6. 同步面记账

有效代码评审完成才置“评审已覆盖”。不完整代码评审不置位。

拒绝启动和异步 ack 都不是完成。类型不可判且出现不完整尾时按未覆盖处理。

设计凭证签发由设计结算独立完成，不能用代码覆盖位替代。

## 7. 失败结算结论

### 7.1 分类顺序

1. 启动拒绝：无尝试，不追加失败结论块。
2. stale。
3. no_report。
4. 非 interrupted 的宿主不完整 kind。
5. interrupted：按中断语义处理。
6. pass 但凭证未持久化：no_credential。
7. 其他有效 pass 或 changes-required：无失败结论块。

### 7.2 文案内容

失败结论包含实际类型、范围摘要、当前已结算轮次、criterion、当前尝试和恢复选项。

恢复选项是继续承担未完成状态、改变或缩小范围后重跑、停止并上报；机制不自动执行。

结论块不包含凭证值或 designId 值，也不封禁下一次发起。

## 8. 预算跟随模型窗口

`advisorContextBudget` 是纯函数：

```js
usable = max(0, context - outputReserve)
limit = floor(usable * 0.8)
compactAt = floor(limit * 0.8)
```

窗口取 providerSpec 与 provider.context 覆盖。outputReserve 取显式 provider.maxTokens、规格 maxOutput 或零。

未知模型回退默认规格并给可见告警。压缩与判死线使用同一可用窗口，不改变服务端协议。

token 估算复用主循环的加权估算，避免 CJK 被扁平 chars/4 低估；比例常量和失败族不变。

## 9. 验收

- 六类不完整尾与块首行匹配。
- 三消费点共用谓词。
- 启动顺序、账链失败和零假签发。
- 结算自写轮次块：块头点名凭证结局，正文为评审原文引用。
- 块与状态行同一次写、同一次回退；写不进 ⇒ 拒签且整笔回退。
- `changes-required`、无裁定行与未回显同样落块；封印算不出与陈旧评审不落块。
- 压缩定锚与 Approval Signal。
- 引文候选、围栏和四类失败。
- 硬墙、partial、超时统计和一次提示。
- 冻结窗两类文件路径与 batch 写路边界。
- 同步/异步覆盖一致。
- 失败分类、对象标识与无凭证泄漏。
- 窗口、预留、压缩和加权估算纯函数。
- 当前项目内 `.md` 受理与项目外拒绝。

## 10. 评审文档路径与受理

`resolveReviewDocPaths` 对相对路径使用会话项目根；绝对路径照用。

工作区锚没有唯一项目根时，相对路径拒绝并给候选；无项目根时拒绝并给期望形。`..` 越根和绝对路径出当前项目都拒绝。

最终只接受当前项目内现存普通 `.md` 文件。docRoot 树外但项目内的文档同样受理。

## 11. 边界

不修改轮次语义，不设置会话级评审封禁，不把冻结窗扩展到所有工具，不自动取消或重发。

不引入行号作为状态文档的长期引用，不把评审工具的行定位协议与文档写作规则混为一谈。
