# 引用修复（ANCHOR-DEBT-REPAIR）· 设计

> 当前判据 = `docs/core/design/DOC-CHECK.md`；写作规则 = `DOC-DISCIPLINE.md`。
> 本档只负责发现引用问题后的修复方法，不保存某一轮存量清单。

## 1. 修复原则

引用修复先确认语义目标，再改文本。doc_check 转绿只是结果之一，不能用占位、无关同名文件或删除必要含义制造假绿。

状态文档不保存历史命中数、某次扫描清单或旧档迁移过程。

## 2. 分类处置

| 情况 | 处置 |
|---|---|
| 目标仍在，路径不完整或已移动 | 阅读上下文后改到真实当前路径 |
| 同一文件名有多个候选 | 根据板块、章节和引用语义选定；不能判断时停下 |
| 目标已删除，规则仍有效 | 指向当前负责该规则的文档和章节 |
| 目标已删除，规则也失效 | 删除整句或整项，不留“已删除”尸体说明 |
| 引用的是历史过程 | 从状态文档删除；历史由 git 承担 |
| 引用只是示例占位 | 使用明确占位语法，不伪装成真实文件 |
| 行号被当长期锚 | 改用品节名、符号名或逐字锚 |
| 文档正确而检查器误判 | 报告检查器问题，不改坏正确文档 |

## 3. 操作纪律

1. 先读引用句、目标文档和所属章节。
2. 语义修改由作者使用文档写工具完成，不用脚本批量替换。
3. 同步检查反向引用和同一主题的其他现行文档。
4. 不通过新增无意义文件来填死指针。
5. 不让批次档或归档文档成为状态规则来源。

## 4. 验证

- 对修改档运行 doc_check report。
- 人工读修改句，确认目标与语义一致。
- 检查相同对象的其他引用没有形成另一版本。
- 若检查与真实句子冲突，修检查或其适用范围，不改记录迎合检查。

## 5. 边界

不保存清账排期，不设置历史豁免族，不为旧脚本保留写法，不处理未纳入当前任务的历史批档与归档正文。
