# 工程系统优化（ENGINEERING-SYSTEM-OPTIMIZATION）· 需求

> 本档规定工程体系优化的横向约束。具体机制由对应需求与设计档负责，不在此保留问题清单或分批计划。

## 1. 优化目标

工程机制应减少错误授权、账实不符、无效往返和重复文本，同时不削弱用户裁定、业务门与验证。

## 2. 当前约束

### 2.1 状态与账

- ledger 使用当前六态与合法迁移；未完成工作可退回等待池。
- batch close 同步结算本批工作项，不能只冻档不结帐。
- completed 显式列出完成行，不能默认全完成。
- 文件与 SQLite 无共同事务时，写序、回滚和 check 读数必须可见。
- 已核销与已废弃是终态，重开不得静默复活。

### 2.2 工具与角色

- 工具 schema、描述和执行门按角色一致收窄。
- 只读角色不能因工具只读旗标过粗而失去已设计的查询能力。
- 子代理只读变体不宣传其不可执行的写动作。
- tester 返回读数，不代下交付结论。
- 无界等待和反复机械失败必须有可见出口。

### 2.3 提示词与文档

- 规则在负责机制档一处详述，提示词只保留可执行语义。
- 状态文档只写当前态，过程进入当前执行记录，历史归 git。
- 规范引用与执行坐标必须区分。
- 设计档不保存本轮文件清单、瞬时计数和逐轮过程。
- 被长期否决的替代方案只保留仍有决策价值的理由。

### 2.4 流程成本

- 记录随当前批次结清，不制造同一事实的多次重复登记。
- 小批可以简化勘察与文书，但不能删除状态、凭证、业务门或验证。
- 评审冻结只保护实际被审对象和当前可见写路。
- 用户输入优先，异步结果自动送达，不靠轮询增加往返。

## 3. 验收原则

1. 每项优化说明解决的真实问题和可观察结果。
2. 有负例证明该拒绝的仍拒绝。
3. 文档与代码在同一变更中一致。
4. 不为“体系完整”新增无消费者的状态、表格或配置。
5. 不把工具数量、文本长度或台账行数下降当作业务成果。

## 4. 权威入口

- 生命周期：ENGINEERING-MODE-V2、BATCH-RECORD、LEDGER。
- 评审：ADVISOR-CONVERGENCE、ADVISOR-GUARDS。
- 角色与工具：AGENT-LOOP、TOOLS、PROMPT-SYSTEM。
- 文档：DOC-SYSTEM、DOC-DISCIPLINE、DOC-CHECK。
- 测试：TESTING。

## 5. 边界

本档不是评估报告或待办池。新缺陷必须在当前任务内处置或由主 agent 按范围入 ledger，不在本档追加问题清单。
