# Function Spec · M6 评审凭证

> 当前设计 = `docs/core/design/ENG-TOKEN-BINDING.md`、`DESIGN-TOKEN-SETTLEMENT.md`、`ADVISOR-CONVERGENCE.md`。

## ① 模块目标

设计评审通过后签发可在当前会话生命周期内使用的流程凭证， eng-coder 凭 designId 与 designToken 精确匹配进入实现；链终消费。

## ② 功能点

1. **签发**：有效回显、VERDICT pass、评审完整、§3 落地和封印可算共同成立才签发。
2. **生命周期**：默认七天，可配；跨模式与重启存活，过期不授权。
3. **多槽**：按 designId 隔离，支持只读清点和链终消费。
4. **评审对象**：当前项目内现存 `.md`；不硬编码本仓 docs 布局。
5. **批次绑定**：设计评审必须有可读 batchDoc 和未决台账行。
6. **批次与封印**：凭证记录批归属和评审版本；派单时复算。
7. **凭证卫生**：值不写进需求、设计或批次正文；工具按当前清点契约提供运行态取用。
8. **失败**：六类不完整、stale、落盘失败、缺裁定、批不符或封印不符均不授权。
9. **收敛**：轮次衰减、新会话与失败护栏按 ADVISOR-CONVERGENCE，不按轮次封禁。

## ③ 边界

- 不把流程凭证当密码学安全边界。
- 不自动用 designId 取 token 代替显式持凭证。
- 不让旧槽或过期槽继续放行。
- 不让批外设计评审产生无法归属的授权。

## ④ 验收

| # | 判据 |
|---|---|
| AC-M6-1 | 完整通过且记录合格才签发，TTL 与配置生效 |
| AC-M6-2 | 消费、过期、重启和模式切换的授权结果正确 |
| AC-M6-3 | 文档受理按当前项目与 .md 判断 |
| AC-M6-4 | 凭证值不落文档，运行日志按当前剥除规则处理 |
| AC-M6-5 | 不完整、打回、stale、读失败均无新授权 |
| AC-M6-6 | 无 batchDoc 或无未决账链时启动拒绝 |
| AC-M6-7 | 批不符、封印不符、封印不可读时派单拒绝 |

## ⑤ 依赖

MANIFEST、ADVISOR、BATCH、LEDGER、SESSION、WRITE-GATE。
