# 配置系统（CONFIG）· 需求

> 当前设计 = `docs/core/design/CONFIG.md`；settings 工具 = `docs/core/design/SETTINGS-TOOL.md`。

## 1. 总体定位

配置系统由 core 提供统一装载、默认值、迁移、持久化和运行期读取。CLI、VSC 与 Desktop 共享适用的配置文件和语义，端侧只实现宿主界面与特有适配。

## 2. 功能需求

| # | 需求 | 验收 |
|---|---|---|
| F1 | 单一装载器 | 配置经 core 装载器合并默认值、迁移和归一，不由端侧各建一套 |
| F2 | 严格格式 | 配置文件使用 JSON，不把 JSONC 当作受支持格式 |
| F3 | 默认值完整 | 用户可配键在默认值或明确的动态配置域中有归属 |
| F4 | 原子写入 | 并发修改使用新鲜读和原子写；冲突或畸形明确失败，不静默覆盖 |
| F5 | 迁移幂等 | 支持的旧字段可重复迁移，不产生重复数据或重复备份 |
| F6 | 路径可移植 | 家目录展开和相对路径按统一规则处理，配置原文不因读取被改写 |
| F7 | Provider 管理 | 预设、增删、key、默认模型使用 core 的同一条目和持久化语义 |
| F8 | settings 工具 | agent 可 list/get/set，写操作带形状校验、敏感遮罩和冲突检测 |
| F9 | 环境引用 | 敏感值可显式写 `${env:VAR}`，消费时解析，未设或为空明确报错 |
| F10 | 团队配置 | team 段只由团队登录与退出流程维护，不进入通用 settings 写面 |
| F11 | 并发池 | agent.poolLimits 提供 engCoder、other、advisor 的正整数配置和当前默认值 |
| F12 | 网络后端 | websearch.backend 与 fetch.backend 支持 auto / local，并使用当前消费规则 |
| **F13** | 互斥工作模式 | agent.mode 只接受 tiny / normal / engineering，缺省 normal；不存在独立的极简开关或第二枚可写 engineering 布尔状态 |

## 3. 非功能要求

| # | 维度 | 标准 |
|---|---|---|
| N1 | 单一来源 | 默认值、schema、预设和读取规则各有唯一归属 |
| N2 | 可移植 | 不写死本机用户目录或本仓路径 |
| N3 | 凭据保护 | 敏感值不明文回显；解析结果不回写 |
| N4 | 可恢复 | 写入冲突、迁移和原子写失败均不伪装成功 |
| N5 | 可验证 | 装载、迁移、写入、环境引用和热应用分别可用行为验证 |
| N6 | 依赖边界 | 优先标准库与第一方模块 |

## 4. 配置通道

自有行为输入使用明确通道：用户配置键、工具自身 CLI 参数、测试 setter seam、显式子进程参数。

环境变量不是隐式配置通道。外部工具、操作系统和 CI 已定义的环境变量仍按其外部契约使用；`${env:VAR}` 是用户在配置值中的显式凭据引用，不是另一套配置回退。

## 5. 边界

- 不引入第二份客户端配置存储。
- 不把团队登录 token 暴露给通用配置列表。
- 不把测试专用输入发布为普通用户配置。
- 不通过读取配置自动改写用户原文。
- 不在配置层校验所有外部模型、渠道和可执行文件的可达性。

## 6. 工作模式配置

agent.mode 是新会话默认工作模式的唯一配置来源。三个值分别对应极简、普通和工程，不由模型大小自动猜测切换。

旧配置只有 agent.engineering 时，装载器仅在读取兼容层迁移：true 对应 engineering，false 或缺省对应 normal。该旧字段不进入通用 settings 写面，不与 agent.mode 同时作为两份权威状态。

枚举值取名 tiny 之前写下的 `minimal` 是同一档的历史写法：装载器与各端读取口把它归一为 `tiny`，老配置与老会话打开后仍是极简档，不回落 normal。写入面只产 `tiny`，不再把 `minimal` 当合法值。

运行期旧消费者可读取由 mode 派生的 engineering 布尔事实，但它只服务于内部兼容。界面、settings 和新代码使用 mode。

CLI、VSC 与 Desktop 使用固定三选项。修改全局默认模式不改变既有会话槽中保存的模式；当前会话由命令或会话模式控件切换，并从下一轮生效。

### 验收

- 三个合法值均可保存和读取，非法值、空值和布尔值明确拒绝。
- 缺省为 normal；旧 engineering=true/false 配置分别恢复为 engineering/normal。
- 旧值 `minimal` 在配置文件与会话槽里都恢复为 `tiny`；写入面拒绝 `minimal`。
- settings 列表和界面不把派生 engineering 显示为第二个可写配置项。
- 新会话采用配置默认，既有会话采用槽内 mode，两者不会互相覆盖。
