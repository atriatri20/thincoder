# 轨迹存储（TRACES）· 需求

> 设计 = `docs/core/design/TRACES.md`；诊断骨架 = `LOGGING.md`。

## 1. 目标

traces.enabled 显式开启时，为模型调用保存可回放的输入、输出、推理、工具声明、usage 和错误，供本机诊断。默认关闭。

## 2. 功能需求

- chat() 是统一采集点，覆盖主会话、子代理、评审、压缩、蒸馏和会诊。
- 轨迹按本地日期和当前 sessionKey/seq 写入 ~/.thincoder/traces。
- 字段、脱敏、内容预算和在途上限由 core 统一。
- 写盘 fire-and-forget；失败或丢弃不改变模型业务结果，丢弃有可见计数。
- traces.retentionHours 控制清理，配置 UI 与 settings 可读写。
- 清理按日目录快速判定，每写 prune 节流，不在一次性信息命令启动面执行。

## 3. 安全与资源

- 复用日志脱敏，完整轨迹仍需按当前内容/记录预算限制。
- 在途写盘数量有界，超限丢弃并计数。
- 不做加密、跨端同步或把轨迹当会话权威。

## 4. 验收

验证默认关、采集字段、脱敏、超长标记、在途丢弃计数、序号、保留期、目录级清理、节流和启动解耦。
