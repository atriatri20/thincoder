# 可移植性（PORTABILITY）· 需求

> 本档规定 ThinCoder 在任意用户项目中的行为，不假定用户项目采用本仓的语言、目录或文档约定。
> 当前设计 = `docs/core/design/PORTABILITY.md`；项目声明 = `docs/core/design/MANIFEST.md`。

## 1. 总体定位

任意语言、目录布局、文档约定和有无 git 的项目都应可使用。需要项目约定时，由项目声明或项目自述提供。

缺失约定不得让评审、索引或检查静默失效。可以降级的能力继续工作，并明确说明局限；无法安全判断的写操作按当前写门规则处理。

## 2. 功能性需求

| # | 需求 | 验收 |
|---|---|---|
| F1 | 路径分类单一实现 | `classifyPath` 及相关谓词由 core 统一提供，各消费面不自建另一套分类 |
| F2 | 项目约定可声明 | `PROJECT-MANIFEST.json` 声明代码段、索引扩展名和索引范围；声明语义与校验一致 |
| F3 | 嵌套路径不漏判 | 路径段匹配支持任意深度、大小写和平台分隔符，并考虑项目根边界 |
| F4 | 评审降级可见 | 缺 AGENTS.md、文档地图、标准或 git 上下文时，评审消息明确说明缺失 |
| F5 | 索引可声明且可见 | 未列入扩展名出现在结果和相应提示中；索引范围使用声明 |
| F6 | 非 git 行为有定义 | 索引可回退到文件遍历；评审说明变更上下文缺失；checkpoint 明确报错 |
| F7 | 写门与分类分离 | 工程设计门使用 `faceOf`，不以文档扩展名或 `src` 名称自行放行 |
| F8 | 提示词适用于任意项目 | 不要求用户项目创建 ThinCoder 自研仓的目录、流程文件或脚本 |
| F9 | 产品面写入受当前模式约束 | 测试、脚本、临时产品文件和其他产品面不凭路径名称获得工程模式豁免 |
| F10 | 项目状态分类不扩大写权 | `state` 是分类读数；父侧写门只放行当前项目的 `PROJECT-MANIFEST.json` 本体 |
| F11 | 写门辖域按目标项目判定 | 目标沿祖先链归属最近 manifest 项目；无 manifest 的祖先链不进入该门 |
| F12 | 多项目并存 | 同一工作区的多个项目不视为错误，跨项目写入按目标所属项目判断 |
| F13 | 工程模式开启无自研仓前提 | 不要求事先存在本仓方法论、目录或脚本 |
| F14 | 推进档位有明确语义 | auto / manual 控制步骤间推进；整批指令不替代设计或用户批准门 |
| F15 | 旧声明不隐式生效 | `.thincoder/conventions.json` 不再读取；存在时可见告警并指向当前 manifest |

## 3. 非功能要求

| # | 维度 | 标准 |
|---|---|---|
| N1 | 不误判 | 已声明代码段内的文档后缀文件仍按产品代码处理 |
| N2 | 降级不崩溃 | 声明缺失或不可读时按当前规则回退并给可见提示；不静默吞掉能力缺失 |
| N3 | 全消费面一致 | 评审、写门、索引、验证和提示词各使用自己规定的判据，不混用分类与写权 |
| N4 | 可验证 | 分类、辖域、降级和索引行为有适用验证；不以历史测试文件名单作为当前通过证据 |

## 4. 推进交互

- `auto` 是当前默认推进方式；`manual` 在跨步动作前等待用户明确放行。
- 用户表达暂停或亲自把关意图时进入 manual，不依赖固定词表。
- manual 下仍可讨论和展示结果，但不自动发起下一实施或评审步骤。
- 用户明确继续或给出下一步指令后恢复推进。
- 一次性整批指令授权该批的评审、修正、实施和收口连续执行；范围改变、设计争议、实施偏离或用户叫停时停止。
- 整批授权不取消评审；没有整批授权时，批准与启动按工程模式当前规则执行。

## 5. 边界

- 不把工程模式机制绑定到 git。
- 不建立另一份项目约定文件。
- 不因用户项目没有本仓文档结构而拒绝基本使用。
- 不把文件系统安全沙箱与可移植性混为一谈。
- 不用分类结果扩大父侧写门的放行面。
