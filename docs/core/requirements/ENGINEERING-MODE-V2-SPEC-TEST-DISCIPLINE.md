# Function Spec · M10 测试纪律

> 当前权威 = `docs/core/requirements/TESTING.md` 与 `docs/core/design/TESTING.md`。

## ① 模块目标

测试按单元与集成分层，项目有明确验证入口。单元测试是批内开发工具，集成测试是真实业务或生产问题的永久回归资产。

## ② 功能点

1. 仓根 `node test/run.mjs` 是集成验证单入口；包级命令按项目约定用于开发反馈。
2. 单元测试随批次记录管理，不自动转集成测试。
3. 集成测试只从用户可见业务入口或真实生产问题产生。
4. 慢测仍属于应跑集合，不靠另建层级规避。
5. 空集不能冒充业务验证通过；验证报告说明实际运行对象。
6. 文档变化以阅读、引用核对和 doc_check 验证，不为它制造无关业务用例。

## ③ 边界

- 不新增测试框架或独立台账仪式。
- 不把 lint 当业务测试。
- 不用断言数量代替行为覆盖。
- 不为填 RTM 自动新增测试。

## ④ 验收

| # | 判据 |
|---|---|
| AC-M10-1 | 项目集成入口可运行并报告真实结果 |
| AC-M10-2 | 单元与集成的生命周期不混淆 |
| AC-M10-3 | 慢用例不通过另层归册逃逸 |
| AC-M10-4 | 空集、失败和未运行均可区分 |

## ⑤ 依赖

TESTING、BATCH、VERIFY。
