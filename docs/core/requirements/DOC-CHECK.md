# 文档检查（DOC-CHECK）· 需求

> 用户裁定（2026-10-18 16:17 / 16:24 / 16:25 逐轮定案）：「心目中的文档检查应该是在一轮设计或者开发这里的动作结束后，向以前的 verify 一样，对修改过的文档做一下即时的检查，发现问题以后直接打回让 agent 当场修改，不要把问题留到以后」∥「肯定不能是只查改动行啊！全文档都要检查的！」∥「这些悬空指针怎么留下来的？不就是因为你以前没有当场修吗！」
> 判据单源 = `docs/core/design/DOC-DISCIPLINE.md` §3.20（锚 ∥ 段长）及 §3.25 条目 Y（依据行逐字引文——挂在「锚」这条判据内部的第二个判法）及 §3.23 条目 W（行号坐标——2026-11-05 起为**第三条闸判据**）。

## 1. 模块目标

一轮设计或开发动作结束时，对**本轮改过的文档**当场做机器检查——发现问题**当场打回**，由发起该轮动作的 agent 在同轮内修正，不进入台账。

**治的病 = 挂账**：检查结果记一笔就走，等以后再处理时，当时的情境（这是举例？是类名？是真指针？）已经不在，问题从「一眼能改」变成「没人能判」。

**为什么必须是当场**：假阳（举错例子、类名当指针）在改动发生的当下一眼可辨；脱离上下文后无法判断该改文档还是改引擎。

**另有写盘前的一道（F14）**：每一笔对**文档面 `.md`** 的写，落盘前判**本次写入落进去的那个段落**，命中即拒写、零字节。它不替代上面这道轮末检查——轮末检查判整档、负责清历史遗留，写前门判本笔、负责不让坏字进盘。两者判集不同，缺一条就断：只有写前门则旧账没人清，只有轮末检查则问题攒到交付才炸。

## 2. 功能点

| # | 功能点 | 判据 |
|---|---|---|
| **F1** | **三个触发点** | 设计轮交付（eng-designer）· 实施轮交付（eng-coder）· 父侧收口前——各跑一次 |
| **F2** | **范围 = 调用方给的那几档，全文** | 清单两来源（**都不经声明域过滤——没有 `scanDirs` 这层**）：**子代理**（无 git）= 本会话触达记账（`_touchedFiles`）；**父侧** = 触达记账 ∪ 本批提交 diff（`git diff <批起 sha> --name-only -- docs`）。**每档全文检查**（不是只查改动行；不是全仓）。**为什么**：检查范围就是问题归属——判了本轮没碰过的档，别轮的存量问题会记到本轮头上，交付被档外债务拖住（这正是当年「技术待办爆炸」的成因）；范围由调用方说清，本轮判了什么才可复述、可复核 |

| **F10** | **可指定档集 = 唯一的取范围方式** | `report` 面**必须**给显式档清单（`docs`: array）：给了 ⇒ 只判这些档（每档全文，判据不变）；**未给 ⇒ 明确报错要求显式清单**——不存在「未给就查全域」的兜底支。清单内档须盘上存在；缺档 ⇒ 报错点名，不静默跳过、不降级为全域。空清单 ⇒ **`report` 面报错；`gate` 面不抛错**，照出「0 档受检」的实况，首行判 `DOC-CHECK GATE: ERROR（0 档受检——空范围不判 PASS）`——**判了 0 个对象不许报 `PASS`**：「全清」是一句关于对象的断言，没有对象就没有这句话可下。`gate` 面同样只判传入档。**为什么**：兜底支存在，调用方迟早依赖它（忘了传 `docs` 也能跑），全仓扫描便以「默认值」的形式悄悄回来——**有默认范围就等于有全仓扫描**，只是没人再看得见它。**来源**：用户 2026-10-19 11:14「不能指定检查哪些文件，这个有问题」+ 2026-10-22 10:27「只查指定文件…你还留着一个门？」 |
| **F11** | **行号坐标（`report` 清点 + `gate` 拦）** | `report` 面**逐处列出**文中的行号坐标形引用，`gate` 面把它计入判据。**形** = 一个名字后面跟 `:` 加数字，且那个数字是**行号而非节号**。**三种写法都要扫**：① 紧贴（档名紧跟 `:` 加数字）；② 承名（同行前文出现过档名，坐标本身只写 `:` 加数字）；③ 段落承名（档名在上一行、坐标在续行）。**它既清点也立闸**：`report` 面逐处列出（清存量用它），`gate` 面把它计入 `hits`、可判 `REFUSED`——2026-11-05 16:05 用户裁定「不过写门可以不挡，但是 doc_check 的时候你还是躲不过」，原先「清点不拦」的口径作废。**写门（F14）不加重这条**：写前门判本笔段落，拦行号会把每一笔正常写作都顶住（哪怕本笔一个字号都没写，只要那段里有存量就炸）。**围栏内不判**：围栏块是**逐字证据**（日志 ∥ 拒文 ∥ diff ∥ 前后对照）——它钉的是**被引的那份原文**，不随盘面漂，读者不拿它去今天的盘上找东西。**判面 = 正文面**：**围栏块整块免判**——锚 ∥ 引文 ∥ 行号坐标 ∥ 段长四类同免。为什么：围栏块放的是**被判那份原文**（日志 ∥ 拒文 ∥ diff ∥ 前后对照），钉的是被引的东西、不随盘面漂，读者不拿它去今天的盘上找东西。**围栏外四类照判**。用户裁定 2026-11-07 11:13「这条要改，围栏内要豁免行号坐标」——**该裁的本意是让行号坐标面跟上锚面（锚面一直整块跳过）**，不是反过来让锚面去判围栏内**为什么要它**：行号引用钉的是位置、不是内容——上面插一行，它以下整片引用同时失效，所以存量必须能被**清点**；而存量必须被清空——机制上立闸（`gate` 面判整档），排期与终点写在设计面 §3.23。**量法单源**：**清单块的首行**打印本次使用的抽取式与扫描域，别处不另写一套。**为什么是清单块内而不是报告页首**：读数会被整块复制走（贴进对话、贴进批档），量法得跟着读数一起走——放在页首，复制一半就散了。清存量期间同一件事被扫出过三个互不可比的读数（窄形 0 ∥ 承名形 119 ∥ 段落承名形 30），根因就是没有统一量法。**为什么三种写法算同一条而不是三条**：读者拿着 `:` 加数字去别处找，行为完全一样；换行不改变它是位置引用。**来源**：用户 2026-11-01 21:40 原话「开」 |
| **F12** | **豁免判定单一源：三处消费同一份定义** | 「一个档名是不是豁免」的判定，**闸判（锚）** ∥ **兄弟脚本 `scripts/prompt-refs-check.mjs`** ∥ **`report` 面的行号清单** 三处必须消费同一份定义，不得各自维护一张表。**现盘的病**：`thincoder-core/doc-check/anchors.mjs` 只导出了 `CANON_OPERANDS`（三张豁免表里的一张），`FILENAME_CLASSES` 与 `PLACEHOLDER_STEMS` 是私有的 ⇒ 兄弟脚本只拿到三分之一，把占位符干名与常规档名（`x.md` ∥ `file.md` ∥ `foo.md` ∥ `example.md` ∥ `todo.md` ∥ `NAME.md`）当成违规报了出来（实测 10 条命中里 6 条属于这一类）。**为什么它是 F11 的前提而不是另一件事**：行号清单若不知道哪些名字是占位，就会把占位档名（`x.md`）加坐标的示例也列进去——**一份自带假阳性的清单会连着闸一起错**，可信度就是它唯一的资产。**验收口径**：共用后 `node scripts/prompt-refs-check.mjs` 从 **10 条降到 4 条**，且那 4 条真违规（裸档名未写仓根路径）逐字不变；**那 4 条本批不修**（存量归清账），本批只让判定对起来。**来源**：父侧 2026-11-01 21:42 实读 |
| **F13** | **依据行逐字引文（命中类 = `引缺`）** | **形**：`依据` + **可选**分隔符（`:` ∥ `：` ∥ `=`）+ 档路径（可带反引号）+ `「` 逐字引文 `」`；档路径 token 与 `「` 之间只允许分隔符与反引号——中间夹进别的字符就不构成标记。**判**：引文必须是所指档里**一段连续子串**——不改写、不省字、不拼接，且**不做**空白折叠 / 全半角 / 大小写换算（换算一次，引文就可以「大致对」，判据随之失效）。不是 ⇒ 命中类 **`引缺`**。**为什么不并进 `档缺`**：`档缺` 说的是「档不在盘」，读者据此去查路径；引文错时路径是对的，合并会把读者指向错的地方。**闸仍是三条**：它是「锚」这条判据内部的第二个判法（路径解析 + 引文存在），verdict 串与命中计数口径不变——两因都计入「锚 N 条」。**边界**：只判**自称依据**的行；**不判依据对不对**（引注释当契约这类，机检照样看不见，归评审面——见 §3.25 评审面）；空引文：**引文面不判**，但该行路径 token 仍归锚面照判（不因引文空而整行让位——让位会让悬空档名凭空少报一条）；零豁免入口（存量天然为零：域内标记形 **0** 行——**读数不入判据**，文档一增就漂，判据只认 0，没有「老的不算」这条口子）。**为什么**：引二手当依据已经真出过两次——一次把一个**不存在**的条文挂到档名下，一次把**注释**当契约（后果 = 照设计档写，写门会把每一笔写都拒）。两次评审都没命中，因为档写反、代码写对，行为判据全绿、两边各自自洽。**触发前提**：本判据只在写作面**教了写法**之后才可能命中——写作面不改，全档 0 标记就是它的终态（死判据）。 |
| **F14** | **写前门（写盘面）——判集 = 本笔触碰的段落** | **挂点**：`write` ∥ `edit` ∥ `insert_after` ∥ `hashline_edit` ∥ `apply_patch`（内容写盘全部经 `thincoder-core/tools/write-path.mjs` 的 `writeThroughPath`，单一写点）。**判集不是整档，也不只判新字——判本次写入落入的那个段落**：目标档不在盘（新建）⇒ 判整份新内容（整档即其笔）；目标档已在盘（含 `write` 整档重写）⇒ 先拿盘上旧内容与本次新内容剥公共前 ∥ 后缀、定出改动区，再定位被触碰的段——段内部改动 ⇒ 该段**整段**（含原有字）；插入空行拆段 ⇒ 拆出来的**两段**；删行并段 ⇒ 并出来的**那一段**；不碰旧段则只判新增段；改动落在围栏块内 ⇒ 判**整块**（含开启 ∥ 闭合标记行，否则块内代码行在片段里成正文、按段长误判）；判面空 ⇒ 零判。锚同样只判该判面里出现的指针——**被本笔碰到的段，其存量悬空指针照拒**（你没碰的段不管）。**面**：只判**文档面 `.md`**（谓词单源 = `thincoder-core/agent/write-face.mjs` 的 `faceDetail(abs).reason === "doc-root"`）；产品面 ∥ 出辖 ∥ 项目状态档 ⇒ 不判。**命中 ⇒ 拒写、零字节落盘**，命中清单回给写者同轮修（F5 ∥ F6 同口径）。**它不是 F1 的三个触发点之一**：F1 判轮末交付，本门判每一笔写盘，两者并存。**为什么**：批档早有门、规范档没有——本仓实读，五份设计档一轮内改完，一次门都没过（`thincoder-core/tools/write-path.mjs` ∥ `thincoder-core/tools/edit-diff.mjs` ∥ `thincoder-core/tools/edit-batch.mjs` 引 `doc-check` 均 false）；坏字当场进盘，只能等轮末交付检查才炸。**为什么不判整档**：整档判会把作者改不动的旧账变成他的写入门槛——某档只要有一条存量悬空指针，谁写该档谁被拒，而拒因不在他这一笔里。**为什么不落到「只判新字」**：把一句话接在既有 289 字段落尾部，新字只有 20 个、个个合规，而读者看到的是 300+ 的一整段——段落是读者读到的单位，判到段为止才既不越界又不漏。**判据句单源** = `docs/core/design/DOC-DISCIPLINE.md` §3.26 |

| **F15** | **逐档行数读数（读数面 · 非判据）** | `report` 面可选参数 `lines`（任意在盘档）：逐档返回一个整数值 + 越线标记。**量法单源 = 引擎的 `countContentLines`**（任何别式量得的值不是「另一种口径」，是错的）。**档类闭集**：源 ∥ 单元测试档（`.mjs` / `.cjs` / `.js`）才标越线（`>800` = 收口硬线（只有收口检查判这条，必拆）∥ `>500` = 设计器硬线（设计时判「改代码前」的长度，必给分拆方案），严格大于，**中间环节一概不判**，单源 = 设计档的行数档位口径）；`.md` 只出数、`tier` 空——文档零尺寸义务。**它不入 `hits`、不入 verdict**；`gate` 面传 `lines` ⇒ 明确拒绝（静默忽略会让调用方以为量过）。**为什么它是需求而不是实现细节**：行数只有一个用途——判该不该拆；而同一个用途在一次会话里被四个尺子量出四个数（`Get-Content \| Measure-Object -Line` ∥ `readFileSync().split(&quot;\n&quot;).length - 1` ∥ 读工具行号 ∥ 编辑器状态栏），每一个都能自称有依据，于是**行数本身就不存在**，只有四份读数。尺子不进工具，就永远有人拿自己的——**口径的统一不能靠申报，只能靠只剩一种**。 |
| **F16** | **批档面互引不判（豁免面）** | 引用方档与目标路径**同在** `docRoot.batches` 根下 ⇒ 该 token **不判**（不进命中、不报 `档缺`）；**规范档引批档照判**（D10 方向纪律的最后一道机检，豁免它等于把那条规则拿掉）。目标路径**先拼后判**（`<项目根>/<token>` 对任何 token 都拼 ∥ `<引用方目录>/<token>` **只对不带目录段的裸名成立**；`..` / `.` 与 `\` 先归一，任一成立的候选落批档基底根下即豁免），**不等解析结果**——收口死锁发生在单元档已删之后，等解析结果才判就永远走不到面判。基底根与批档面同源（声明面 ∪ 缺省回退 `docs/batches`，恒非空）。留痕只在 `report` 面（`批档面互引未判 N 处`，0 也出），`gate` 面零改（首行与命中行形不变） |
| **F17** | **判域按档所属项目根解析（一档一根，不共用坐标系）** | **一个档的根 = 它自己的落点定出来的根**：`rootOf(abs) = owningProject(abs, parse(abs).root) ?? 声明根`；**界 = 该档所在盘的盘根**（与项目根视图同一个界，不是声明根——填声明根会把跨项目的档先判出界、再落回声明根，那正是本批要修的 `档缺`），工作区目录自身没有 `PROJECT-MANIFEST.json` ⇒ 不会被当成根。**「声明根」= 调用方显式给出的根**（引擎面 = 入参 `root`，父侧会话锚即调用方给的根；**工具面 `target` 必须显式传，不传就拒**——不给默认值、不替调用方选一次没有依据的根）——**它不是兜底、不是猜**：**不许回落到兜底根**（不拿 cwd、不拿某个祖先项目、不拿清单里第一个项目的根去顶），**但调用方明确声明了根，用它是执行那个声明，不是猜一个根**。两道分界各管一件事：**有声明根 ⇒ 用它（含夹具临时域，那是调用方声明的坐标系）；连声明根都没有 ⇒ 显式报错**。**一批评审的清单可横跨多个项目**：按 `rootOf` 分组、逐组判，**判定内容（锚 ∥ 段长 ∥ 行号坐标 ∥ 引文）一字不动**——本条改的是「拿哪个根去解析」，不是「判什么」。**报面**：一条 verdict（全文 `DOC-CHECK GATE:` 只出现一次）；清单横跨多根时命中行前置 `[<项目名>]` 且行内路径相对**自身**根，单根时零标签（⇒ 单项目场景的报面与现状逐字相等）。**解析不到根 ⇒ 显式报错**：首行 `DOC-CHECK GATE: ERROR（无法定根 N 档）`，逐档点名档与原因，**N = 清单档条目数（去重后）**。**这是政策，不是公式的推论**：缺声明根 ⇒ **整清单不判**——即使部分档本可由 manifest 祖先定根，也不出半份判定（半份判定在报面上分不出「这档干净」与「这档没判」）；今日缺 `root` 本就是一次 `TypeError`、整次零判定，本支只是把不可读的崩溃换成能读的拒绝。**报文不得断言盘上为假的事**：只有该档祖先链**确实**没有 `PROJECT-MANIFEST.json` 才许这么说；本可定根的档，原因句要说「本次没有声明根，整清单不判——本档本可归 `<该根>`」。**不许静默跳过该档**，也不许替它猜一个根——兜底之后没有任何读数能区分「按自己的根判过」与「按猜的根判过」，那是把「判不了」洗成「判过了」。**为什么**：本机 `D:\teamcode` 是工作区、下有两个项目（`thincoder` ∥ `thincoder.com`）⇒ 一个坐标系覆盖两个项目时，跨仓档一律按错的根解析、判 `档缺`：三份评审因此拿不到令牌，跨仓写入同样被拒，底层伸手到业务仓也是同一个方向问题。**判据句单源** = `docs/core/design/DOC-CHECK.md` §2.1–§2.4 |
| **F18** | **档名识别允许非 ASCII** | 档名的字符类从 `[A-Za-z0-9_.\-]` 放宽到「Unicode 字母与数字（含中日韩）」＋原有 ASCII 符号集；仍排除空白与全角标点。**裸词不得被当成档名**：一个 token 要成为候选，须**含清单内的扩展名**（后缀落在 `index.docCheckExts` 清单内）；**路径分隔符不单独构成候选资格**：**带目录段的一族同判**（后缀落在清单内即成候选）；**裸名另须后缀落在文档名族 `BARE_NAME_EXTS`（`md` ∥ `markdown`）内**，后缀只在代码族里的裸名按散文提及处置、不解析不判（判据单源 = `docs/core/design/DOC-CHECK.md` §2.10.3）。清单按真实文件类型取形（单字符后缀与归档内层不入），可在 manifest 增补。**为什么**：现行正则纯 ASCII，中文档名一律看不见——中文档名、中文目录下的档、纯中文件三种写法全在盲区，作者只好自建扫描器去补，补出来的数又互不可比。**验收**：三例（不存在的中文档 ∥ 中文目录下的档 ∥ 纯中文件）报告态全部判 `档缺`，且在一份正常中文档上跑**误报为零**——「误报为零」与「三例判得出」同等重要：放宽字符集最可能的副作用是把普通中文词认成档名，一旦如此，大批文档瞬间报红，人就开始「为绿改文」 |
| **F19** | **扩展名不按 12 项闭集筛** | 清单 = **`index.docCheckExts`（可配置，缺省覆盖真实文件类型）**：`.py` ∥ `.csv` ∥ `.txt` ∥ `.sql` ∥ `.xml` 这些在缺省清单内。**扩展名清单这条腿两形同看，形分档那条腿按族分**（F18）：带目录段的一族要后缀落在清单内；裸名另须后缀落在 `BARE_NAME_EXTS`，代码族裸名不判。**后缀取形三条**：首字符必须是字母、长度 1–10（否则 `1.5` ∥ `v2.0` 会被认成扩展名）；**单字符后缀不入**（`.x` 是 `20.x/22.x` 的来源）；**归档内层不入**（`tar` ∥ `gz` ∥ `zip` 不单列，`build/app.tar.gz` 整串不当档名）。**为什么选可配置清单、不选「任何点+字母组合」**：开放式会让代码表达式（`JSON.parse` ∥ `process.env` ∥ `console.log`）与版本号一并成为候选——实测在现盘会新增 65 条不可解析命中，那会把工具变成噪音源，人就回去整目录排除，**等于把这个功能废掉**。**验收**：**带目录段**指向不存在的 `.py` ∥ `.csv` ∥ `.txt` 各一处 ⇒ 全部判 `档缺`；`1.5` ∥ `v2.0` ∥ `20.x` ∥ `tar.gz` ⇒ 均不成候选；`JSON.parse` ∥ `console.log` ⇒ 不成候选 |
| **F20** | **逐条豁免登记（第三档的登记面）** | 登记逐条具名：**哪一份档、哪一条命中、为什么不算违规、何时复审**；登记后该条**仍出现在报告里**，只是不阻断交付。**为什么**：这是与「按类排除」不同的一件事——排除是**不看**该档，豁免是**看了、已裁定、不拦**；只有前者时，作者遇到「计划新建件必须留路径」这类必然命中，只剩「删路径」或「整目录排除」两条路，后者把整片区域变成盲区。**验收**：登记一条假阳后重跑，该条仍在清单上、标为已裁、交付门不阻断；撤销登记后重新计入命中 |
| **F21** | **报告第三档：已裁定假阳** | 除「违规」与「不违规」外增设第三档——**已裁定的假阳**：不阻断交付，但每次报告都要列出（哪一条 ∥ 哪一份档 ∥ 理由 ∥ 登记时间）。**为什么**：「计划新建件必须留路径」这类规则要求文档写下一个尚不存在的目标，工具必然判它 `档缺`；没有第三档，作者只有两条路——删掉那个路径（违反规则），或整目录排除（造成假绿）。**验收**：登记一条假阳后重跑，该条仍在清单上且标为已裁、交付门不阻断；撤销登记后该条重新计入命中 |

## 3. 边界（不做什么）

- **不查未改的档**——责任边界 = 本轮触碰面。未触碰档的存量问题属清账，另事处置。
- **不做全仓扫描**——全仓扫描 = 清账动作，不是每轮的交付门；做了会把别的轮次的问题带进本轮，正是「检查范围把开发思路带偏」的成因。**判据句 = 代码内 `scanDirs` 零消费、`anchors.domain` / `anchors.roots` 零存在**：没有全仓基线，就没有「未给清单时」的兜底支。本仓存量里只有「解不到」的那批算债（`#1731`；绝对数已随三批下降，取当前读数）——**工具不为自己仓库的存量债务放宽判据**，放宽一次，判据就再也不是判据。
- **不新增判据——闸 = 锚 + 段长 + 行号坐标三条**（F13 的引文面**挂在「锚」内部**，是它第二个判法，不另立第三条；verdict 串与命中计数口径一字不改）。D2 重复、D8 历史残留、计数三值互斥这类跨句判断不纳入（机器判不了，靠评审）。**F11 的行号坐标已是第三条判据**（2026-11-05 起；原先「只报不拦」的边界作废）——它与锚、段长同级入 `gate`，判法见 F11。**这条边界的对象始终是闸**：数得出来而没资格拦人的，写成清单；有资格拦人的，就得进闸。
- **不改「用户令 > 机检」总则**——机检不得成为拒绝用户指令的理由。
- **不替代评审**——机检只判机器能判的（指针解析 / 段长）；内容质量归评审与执行者。
- **排除面是工具提供的能力，用不用由使用方定**——按类排除（`index.docCheckExcludePaths`）**行为不变**：落进去的档不看、不出命中，全落进去则 `PASS`。**这是明示的取舍**：把一片区域交给排除面，就是选择不去看那片区域；工具照做，**不替使用方决定该不该这么做**。逐条登记（`index.docCheckExemptions`，F21）是另一件事：档照判，只是那一条已裁定不阻断。**两者不是同一件事的两种写法**：一个是「不看」，一个是「看了、已裁定、不拦」。判决依据 = 用户 2026-11-09 15:36「维持免检放行不动」＋ 15:38「允许把一片故意变成盲区是我们提供的功能，用不用是他们的选择」＋ 15:15「一线的需求才是最真实的」。

| **AC-8** | `report` + 显式档集：只报清单内的档（清单外的存量问题**不报**）；不在盘的档 ⇒ **明确报错点名**，不静默跳过；`docs: []` ⇒ **明确报错**；**不给 `docs` ⇒ 明确报错要求显式清单（零遍历、零全域兜底）** | 构造：全域有存量问题档 A、清单只给干净档 B ⇒ 0 命中；清单给 A ⇒ 报 A；给不在盘的档 ⇒ 报错点名；`docs: []` ⇒ 报错；**不给 `docs` ⇒ 报错且不读任何档（读盘计数 = 0）** |
| **AC-9** | `report` 面的行号坐标清单：① **三种写法都报**（紧贴 ∥ 承名 ∥ 段落承名）；② 首行打印抽取式与扫描域；③ **gate 面拦**——同一份档在 `report` 面报出 N 条 ⇒ `gate` 首行判 `REFUSED` 且多出「行号坐标 N 处」一节；两面同源（`lineRefs.body` 逐字相等；`total` 仍含围栏，只作留痕不入判）；④ 空档 ∥ 无命中 ⇒ 显式写「0 处」并带量法，不留空行 | 构造：三条夹具（三种写法各一）+ 一条报不出的对照（节号 `§6.66`、日志行号 `:80` 不排头不跟档名）；同一批档跑 `report` 与 `gate`，两面 `lineRefs.body` 相等且 `gate` 首行带「行号坐标 N 处」 |
| **AC-10** | 豁免判定单一源：① `node scripts/prompt-refs-check.mjs` 改后 = **4 条命中**（改前 10），剩下 4 条逐条可点名；② **结构证据**：两张表不上导出面（`export` 行零含两表名）∥ 三处调用点可 grep | 构造：跑脚本读数 = 4；逐条点名 `thincoder-core/agent-tools/advisor.mjs` 的两处共 4 条；grep `export` 行与调用点 |
| **AC-11** | 依据行逐字引文（F13）：① 引文与源档**逐字相同** ⇒ 放行；② 改一个字（含删字 / 拼接 / 改全半角）⇒ **拒**，命中串含 `✗ 锚·引缺` 且计入既有「锚 N 条」；③ **引文存在但依据错**（拿注释当契约）⇒ **不报**；④ 空引文 ⇒ **引文面不判**（该行路径 token 仍归锚面照判：档名悬空 ⇒ 照出 `档缺`，不因引文空而整行让位）；⑤ **无标记行零误报**——对现盘全域实跑，`引缺` 命中 = **0**（域内文档数不入判据：一增就漂，判据只认 0） | 构造：四条夹具（逐字合 ∥ 一字之差 ∥ 真引文但引错处 ∥ 空引文）+ 全量回扫；②③两条必须分得开，③ 归评审面，机检不假装能判 |
| **AC-12** | 写前门（F14）：① **旧账不拦本笔**——某档旧段含悬空指针、本笔改别处 ⇒ 放行，该档字节正常变；② **新文本悬空 ⇒ 拒写零字节**——本笔写进一个不存在的档名 ⇒ 拒，盘上字节逐字不变；③ **只判文档面**——产品面（`.mjs` ∥ `.ts`）与之无关、出辖目录 ⇒ 不判；④ `apply_patch` 两段式只判暂存段，提交段不判；⑤ **判面空**（新旧内容剥前后缀后无一字）⇒ 零判放行；⑥ **接长当场判到**——把一句接在既有 289 字段落尾部（本次写入 20 字）⇒ **拒**，判面 = 该段整段；删空行并段后越界 ⇒ 同样拒；⑦ **被碰段落里的旧悬空指针照拒**——本笔改的那段含一个不存在档名 ⇒ 拒；同样那个档名在未被碰的段里 ⇒ 放行；⑧ **围栏块内改动**——改代码围栏内一行 ⇒ 判整块、不按段长误判 | 构造：八条夹具各一（旧账档改别处 ∥ 新悬空档名 ∥ 产品面 ∥ `apply_patch` 两段 ∥ 空改 ∥ 接长 ∥ 被碰段的旧悬空指针 ∥ 围栏块内改一行），逐条比写前写后字节 |

| **AC-13** | 逐档行数读数（F15）：① `lines` 报出的整数与 `countContentLines` 对同一档的读数**逐档相等**；② `.mjs` >800 标收口硬线且 >500 标设计器硬线，`.md` 只出数、标记为空且 `tier` 不落；③ 同一次调用的 `lines` **不入 `hits`、不进 verdict**（与不给 `lines` 时报面逐字相等）；④ `gate` 传 `lines` ⇒ 明确拒绝、点名原因、该次不产 verdict 首行（静默忽略会让调用方以为量过；抛出后调用方见 `Error:` 一行 + `ok: false`）；⑤ `lines` 非数组 ∥ 空数组 ∥ 元素非字符串 ∥ 档不在盘 ⇒ 点名报错、整次零读数 | 构造：同一档经两条调用面各读一次比整数；`.mjs` 夹具接 900 行 ∥ `.md` 夹具接 900 行比标记与 `tier`；同清单跑带 ∥ 不带 `lines` 的两份 `report` 逐字比；`gate` + `lines` 拒；四种坏入参各一 |
| **AC-14** | **批档面互引不判（F16）**：① 批档 → 本批单元档（**已删**）⇒ 不判、`batch close` 不被拒（死锁消失）；② **规范档 → 已删批档 ⇒ 仍判 `档缺`**（方向纪律未失，这是本条的立条边界）；③ 批档 → 批档（含前情指针、跨批引用）⇒ 不判；④ `gate` 面首行与命中行形不变、读数不进 `hits`；`report` 面恒出 `批档面互引未判 N 处`（0 也出）；⑤ 既有集成行 `7-6` 改写后仍绿（token 换仓根全路径、指向批档面之外，该行证的东西不变） |
| **AC-15** | **判域按档定根（F17）**：① **跨两个项目的档清单能出 `PASS`**——两档各在各自项目内且都干净 ⇒ 首行 `DOC-CHECK GATE: PASS`，不因清单混了别的仓而判档缺；② **单项目场景零回归**——同一批本仓档，改码前先跑一次 `report` 报面整段存档，改后用同一条命令逐字比 ⇒ **差 0**（比的是命令输出，不是回忆）；③ **无声明根 ⇒ `ERROR` 而非 `PASS`**——`root` 入参缺省 ∥ 空串 ∥ 非字符串 ⇒ 首行 `DOC-CHECK GATE: ERROR（无法定根 N 档）`，逐档点名档与原因，**该档不被静默跳过**，且报面**零 `✗` 命中行**（不出「判了一半」的混合结论）；④ **一条 verdict**——多根清单的全文 `DOC-CHECK GATE:` 出现 **1** 次；⑤ **报面分段**：多根命中行带 `[<项目名>]` 前缀、行内路径相对自身根；单根零标签且与现状逐字相等；⑥ **判定内容零改**——改码前后对同一批夹具的 `hits` 三桶（锚 ∥ 段长 ∥ 行号坐标）逐项相等 | 构造：两个夹具项目（各自一份 manifest、各含一档）+ 一份跨项目清单；无声明根那一半直接调引擎、`root` 缺省 ∥ 空串各一；单项目基线用本仓固定三档存档比对；`grep -c 'DOC-CHECK GATE:'` 计 verdict 出现次数 |
| **AC-16** | **非 ASCII 档名（F18）**：① 指向不存在的中文档 ∥ 中文目录下的档 ∥ 纯中文件 ⇒ 三例全部判 `档缺`；② 一份正常中文档上跑 ⇒ **误报为零**（正文里「需求档」「设计档」这类普通词不得被认成档名） | 构造：三例夹具 + 一份含大量普通中文词的正文；判据 = 误报数为 0 且三例均红 |
| **AC-17** | **扩展名不闭集（F19）**：① 指向不存在的 `.py` ∥ `.csv` ∥ `.txt` ⇒ 三例全部判 `档缺`；② `1.5` ∥ `v2.0` 这类数字不得被识别为档名 | 构造：三例夹具 + 一段含小数点数字的正文；判据 = 三例红且数字零命中 |
| **AC-18** | **排除面与豁免面是两件事（F20）**：① 某档被目录排除 ⇒ 不入判、不出命中（**既有行为不动**）；② 同一档不排除、但某条命中被登记 ⇒ 该档照判、该条标已裁且不阻断；③ 两面对同一档同时作用 ⇒ 排除优先（该档不出现在受检清单里） | 构造：三组夹具各一；判据 = 三种组合的受检清单与阻断与否各按上述 |
| **AC-19** | **已裁定假阳第三档（F21）**：① 登记一条假阳后重跑 ⇒ 该条仍在清单上、标为已裁、`gate` 不阻断；② 撤销登记后 ⇒ 该条重新计入命中 | 构造：一条真悬空登记为假阳 ⇒ 两轮（在册 ∥ 撤销）；判据 = 阻断与否随登记状态翻转 |
