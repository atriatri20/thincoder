# 文档检查（DOC-CHECK）· 需求

> 设计与实现面 = `docs/core/design/DOC-CHECK.md`。
> 本档只规定当前检查需求、边界和验收，不记录历次规则变化。

## 1. 模块目标

给写文档的人和 agent 一个当场反馈：**刚写的这段文字里，有没有让人读不下去的地方、有没有指向空气的地方。**

三件事，出问题当场打回，修完再走。

## 2. 功能点

| # | 要求 | 不这样做会怎样 |
|---|---|---|
| **F1** | **一段文字太长要报**：一个正文段落超过 300 字 ⇒ 报出它所在的位置与字数。表格块、列表块、围栏代码块和缩进代码块整体不参与段长判定，列表续行与无首尾竖线的表格也在排除面内 | 一段三百字以上，读者会整段跳过；跳过的可能正是结论。表格、列表和代码本来就按行组织，把它们的行拼成正文段落会产生误报 |
| **F2** | **拿行号做锚要报**：文中出现「档名 + 冒号 + 数字」这种定位 ⇒ 报 | 行号会漂：上面插一行，它以下所有引用同时失效，而后面的人按它去找会找错地方 |
| **F3** | **悬空指针要报**：文中写了一个该在仓内的档名，仓根下找不到 ⇒ 报 | 指向不存在的档，读者点过去是空的；这类东西留着，谁都不敢删也不敢信 |
| **F4** | **跨仓一律不报**：出仓的相对形、绝对路径、未声明别仓和已声明公共仓的档 ⇒ 一个字都不出；`index.publicRepos` 只开放检索与引用，不扩展 doc_check 的存在性判定 | 门不知道别的仓长什么样，报出来的都是噪音；真写错了是路径没写清，责任在人 |
| **F5** | **在建的档不报**：档名出现在某份在途批档的 §2 机读清单里 ⇒ 不报 | 设计档写「这里要建一个档」时，那个档本来就不存在；不开口子，设计档就写不出要建的东西 |
| **F6** | **批档按两个时点判**：工程模式写的那一刻，落在 `docRoot.batches` 之下的档照判段长与行号锚，但整份不判悬空；收口时点（`batch close` ∥ `status → 已收口` ∥ `doc_check` 工具面），批档整份不进判域——三件一样都不出，连「判了几档」都不数它 | 工程写的那一刻它在被写，写错了当场就要拦；收口看的是几小时前写下的执行记录，而现态已经变了，拿现态的尺去量当时的记录，量出的是时间差不是缺陷。悬空那条另有理由：批档是可整份删掉的执行记录，不是导航——记录里出现一个不存在的档名是**发现**，判它等于把这条发现本身拦在门外。设计档 ∥ 需求档 ∥ 标准档两个时点都照判 |
| **F7** | **`.thincoder/` 下的路径不判悬空**：运行期状态目录（会话、记忆、临时件、运行期操作数）里的路径 ⇒ 不出悬空这一条 | 那不是文档区：判它等于把工具自己的家当当成读者要翻的资料；一条真误报就没人再信这个门 |
| **F8** | **收口门只判本批变更区**：收口那一刻（`batch close` ∥ `status → 已收口`）与 `doc_check` 的 `gate` mode，判域 = 本批变更区；区内的命中照判，区外一个字都不出——不拦、不出行、不出存量读数 | 收口量的是本批干了什么。按整份档量，量到的是这份档里与本笔无关的旧账：它把这笔拦下，却指不出本笔错在哪 |
| **F9** | **排除面收窄判集**：项目在 manifest 的 `index.docCheckExcludePaths` 里声明的路径前缀，其下的档**不进判域**——三件一样都不出，也不计入「范围 N 档」。命中形 = 与该前缀相等，或以「该前缀 + 斜杠」开头。声明读不到 ⇒ 照判，不放行 | 判哪些档是项目自己的事：生成物、供应商目录、语言束文件是项目声明不要判的，门没有立场替它判。而「声明了却不生效」比没有这条声明更坏——写的人以为一劳永逸，读的人还在被拦 |
| **F10** | **工程模式写门判这一笔改的行**：`.md` 落盘前那一道门（`write` ∥ `edit` ∥ `apply_patch`，含批档的 `append` ∥ `edit`），判域 = 本次要写的文本相对盘上现文**改动的行**，算法同下「「变更区」怎么算」一段——变了的行，加上被删掉的那几行所在的缝；没变的行一条都不出。盘上还没有这份档 ∥ 盘上现文读不出来（目标是一份目录、权限拒绝）⇒ 没有可比的旧文本 ⇒ 整份判。读不到这一支的代价照实认：这是本判据「区外不出行」唯一会被整份判顶掉的状态，而它只在盘上那份东西根本读不出来时成立 | 改一行不等于重写整份。按整份判，量到的是这份档里与这一笔无关的旧账：它把这笔拦下，却指不出这一笔错在哪 |

| **F11** | **无项目不运行文档门**：目标及其祖先没有 `PROJECT-MANIFEST.json` ⇒ report 与 gate 都不运行；显式 `target` 和会话锚只定位，不制造项目身份 | 没有项目声明就没有项目判域；把定位参数当成项目身份，会让任意目录被误套项目规则 |

| **F12** | **普通模式不运行文档内容写门**：普通 `.md` 写盘及批档 `append` / `edit` 均不调用内容检查；`doc_check` 主动报告和工程模式写门不受此开关影响 | 普通模式的质量由纪律、验证与评审保证，机械硬拦会破坏该模式的直接工作方式 |

**F5 的「机读清单」指什么**：批档 §2 里那一段——标题行「**受影响文件（机读清单）**」＋围栏内的表，一行一档，只列代码档（源 ∥ 单测）。表带第三列「行数」：该档在批起快照上的内容行数，快照里没有这一档的写 `新`——档位闸据此判读数有没有报、报得对不对，形与判法单源 = `docs/core/design/DOC-CHECK.md` §8。

取哪些行 = `machineListRowsOf`（`thincoder-core/agent-tools/batch-segment-vocab.mjs`）；形单源 = 批档 §2 模板（`thincoder-core/agent-tools/batch-skeleton.mjs`）。**匹配 = token 归一后与该行逐字相等，不走后缀兜底**。**「在途」= 该批档 §1 状态行不是「已收口」**。

**「变更区」怎么算**：算出来的必须是**本批自己改的行**——不按 diff 的 `+` 侧行取（纯删也算变更，删掉的那几行就是区），也不因为「这份档被碰过」就整份进来。段长的判据单位是段：段里含变更行就量整段，整段无变更行不判。

**缝上没有字，所以只喂段长**：删除会让两侧接成一段，这一段的长度是本笔造成的，段长认缝；行号锚与悬空指针只看变更行本身——删掉的那一行若曾写错什么，那是上一笔的责任，且改后文本里也没有可指的行。

**不扩区**：不恢复存量读数（不出 `STOCK_LINE` 一类附加行），不加邻段 ∥ 整块 ∥ 扩区表。`doc_check` 的 `report` mode **不在此列**——它是诊断面，问的是「这份档现在有什么问题」，没有「本笔」可言，判整份。

**没有要判的行 ⇒ 不出任何行**：本批没碰这份档、或变更区判不出来，都等于没有要判的行。回执不多出一句、不点名、不写「无从判」——对方没有需要做的事。

**三条判据之外没有第四条。** 引用的节在不在、引文对不对、文件多少行——都不判。

**F7 不是豁免表**：只有一条路径前缀——没有文件名清单、没有逐条登记、没有按类按文的匹配。

## 3. 边界（不做什么）

- **不判节号**：`§N` 对不对得上标题，不在射程。
- **不判引文**：`依据 X「…」` 里的引文是不是原文，不在射程。
- **不判行数**：文件多少行、超没超过某条档位线，不在射程。
- **不查未改的档**：判的是本轮交付的档，不是全仓。（F5 会读别的在途批档来取清单——那是取声明，不是判那些档。）
- **收口门不看变更区之外**：判域之内再按变更区收窄，本笔没碰过的行与段不判。与「不查未改的档」是两条——那条管哪些档进判域，这条管同一份档里判哪些行。
- **不做路径解析系统**：没有「根」、没有「腿序」、没有豁免登记表。仓内找一次——找不到就报，三个例外见到 F4 ∥ F5 ∥ F7。
- **不出读数**：不报统计、不报分块、不报「顺便发现」——只报违规的那几条。

## 4. 验收

| # | 判据 | 怎么验 |
|---|---|---|
| **AC-1** | 一段 350 字的正文 ⇒ 报出段落位置与字数 | 夹具一档，跑一次 |
| **AC-2** | 文中出现行号锚（`档名` 后跟冒号与数字）⇒ 报「用行号做锚」 | 夹具一档，跑一次 |
| **AC-3** | 文中写一个仓内不存在、但形如路径的档名 ⇒ 报「档不存在」 | 夹具一档，跑一次 |
| **AC-4** | 文中写出仓的相对形 ⇒ **零输出** | 夹具一档，跑一次；比对「一个字都没出」 |
| **AC-5** | 一段 200 字、无行号锚、路径都在盘 ⇒ **零输出** | 干净夹具，确认不误报 |
| **AC-6** | 同一个在途批档 §2 清单上的新档名，目标档**两次都不建**：批在飞 ⇒ **零输出**；把该批 §1 状态行改成「已收口」后同一条 ⇒ 报 | 夹具两次，两次只差状态行；目标档两轮都不建，否则绿是文件存在给的，不是豁免到期给的 |
| **AC-7** | 同一句「某份档不存在」写进批档（`docRoot.batches` 之下的档）⇒ **零输出**；写进设计档 ∥ 需求档 ⇒ 报 | 夹具三档：批档 ∥ 设计档 ∥ 需求档，各跑一次 |
| **AC-8** | 文中写出 `.thincoder/` 下的路径 ⇒ **零输出**；同一份夹具里写一个仓内不存在、形如路径的档名 ⇒ 照报 | 夹具一档，跑一次；两半各看一条 |
| **AC-9** | `.thincoder/` 下的路径后跟冒号与数字 ⇒ 行号锚照报 | 夹具一档：该行两判据不得一免全免 |
| **AC-10** | 一份设计档：本批变更区里干净、区外有一处悬空指针 ⇒ `batch close` **放行**，回执零附加行；把同一处挪进变更区 ⇒ `REFUSED` | 夹具两次，两次只差指针位置；两半各看一条 |
| **AC-11** | 同一份档：区外一段 400 字 ⇒ 放行；区内某段含变更行、整段超 300 字 ⇒ `REFUSED` | 夹具两次，同上 |
| **AC-12** | 声明一个前缀，夹具在该前缀下写一处悬空 ⇒ **零输出**；撤掉同一条声明、同一份夹具 ⇒ 报。前缀边界：声明 `docs/tmp` 时，同一层里名字只多一个连字符的那个目录（`tmp-x`）下的档 ⇒ 照报 | 夹具两次只差声明；边界那一半单独一跑，否则「前缀」会被写成「包含」 |
| **AC-13** | 一份档区外有几十处行号锚、区内只改一行 ⇒ 写门**放行**；把其中一处行号锚写进那一行 ⇒ `REFUSED` 并点名 | 夹具两次，两次只差锚的位置；区外那一半必须是绿的，否则量到的还是旧账 |
| **AC-14** | 纯删一笔：删掉两段之间的空行，使它们接成一段超 300 字 ⇒ 报 | 夹具两次：删空行 ⇒ 报；同时把其中一段也删短到不超 ⇒ 零输出。丢掉缝合位置这一例必须是红的 |
| **AC-15** | 仓外相对形、未声明别仓和已声明公共仓的缺失路径在 doc_check 均 ⇒ **零输出**；公共仓声明仍可检索与引用 | 三类跨仓各一夹具，分别跑一次；再按公共仓主题检索并解析一条合法引用，确认声明能力未被撤销 |
| **AC-16** | 无项目目录即使收到显式 `target` 或位于会话锚下，也不运行 report 或 gate | 无 manifest 夹具分别以显式 `target`、相对会话锚定位调用；两种 mode 均不得进入三项判据 |
| **AC-17** | 超过 300 字的表格块、列表块及其续行均不报段长；同字数普通正文仍 ⇒ 报 | 带首尾竖线与不带首尾竖线的表格、列表缩进续行、疏松列表和提示词面各设夹具；同字数去标记正文作拒绝侧对照 |
| **AC-18** | 超过 300 字的围栏代码块与缩进代码块均不报段长；同字数普通正文仍 ⇒ 报 | 嵌套围栏、四格空格缩进、Tab 缩进及提示词面各设夹具；同字数去围栏正文作拒绝侧对照 |
| **AC-19** | 普通模式的真 edit/write 与批档 append/edit 对 350 字正文均落盘；同内容在工程模式仍 ⇒ 拒 | 普通与工程各跑一次同一输入；普通回执无内容门行，工程目标零字节 |

**可以接受漏判，不能接受误判。** 漏掉一条，读者至多没被提醒；误报一条，人就不再信这个门，紧接着整个门作废——那比漏掉贵得多。判不准的就不判。

## 5. 依赖

- 判据怎么落：`docs/core/design/DOC-CHECK.md`（三件事的实现面）。
- 文档该长什么样：`docs/core/design/DOC-DISCIPLINE.md`（要求在这，判据不在）。
- 三个触发点：设计轮交付 · 实施轮交付 · 父侧收口前，各跑一次。
- **三个触发点与两个时点不是一回事**：三个触发点说的是「什么时候跑一次检查」，时点说的是「这次检查站在哪一侧」。`doc_check` 工具面本身恒站收口那一侧（批档整份不进判域，见 F6）；写时点只属于**工程模式的** `.md` 落盘前那道门与批档 append ∥ edit。所以设计轮交付、实施轮交付、父侧收口前三处跑的，是同一个判域。
