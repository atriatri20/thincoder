# 诊断日志（LOGGING）· 需求

> 设计 = `docs/core/design/LOGGING.md`。

## 1. 目标

常驻本地事件日志记录回合、模型、工具、子代理、异步消化和挂起的关键序列，使故障可复盘，不依赖临时插桩。

## 2. 功能需求

- logEvent 是统一入口，每行一个 JSON 事件。
- 记录时间、事件名、序号、耗时和当前白名单字段。
- LLM 响应头、工具结果头和错误使用当前有界摘要。
- 日志位于 ~/.thincoder/logs，按日命名并机会式清理超龄文件。
- 同一 core 事件语义服务所有宿主。

## 3. 安全与失败

- 工具 args、URL 和敏感字段不进入事件。
- 字段黑名单与密钥形态脱敏先于摘要。
- 单行和错误摘要受当前字符上限。
- 写失败只停用诊断写，不改变业务结果；进程内避免持续空转。
- 测试默认使用隔离目录，不污染真实日志。

## 4. 验收

验证事件序列、字段白名单、脱敏、长度、日轮转、长驻进程清理、写失败不阻断和测试隔离。
