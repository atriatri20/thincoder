## 1. 模块目标

**把文档各层之间的引用关系存成可以反查的边**，让「这条决定是怎么来的」「这条规则还在哪几处说了」「这一节落后代码没有」从人工核对变成一条查询。

**治的病 = 关系只存在于人的记忆里。**同一个晚上实证了三次：

一、`F16` 改口径之后，`F13` 的边界句、`F17` 的新增、设计档四处「今日未落」的现状句、批档验收表、`EDIT-HELPERS.md` 的帧判据——全靠人一处一处读出来。设计席读代码才发现我把 `F17` 写反了。

二、批档 §2 里引着设计档 `§N.M` 的验收行，设计一改它就悄悄过期；收口面照着过期的那份判，会把正确的实现判红。

三、RTM 现在按号手工对齐，需求 → 设计节 → 用例这条链没有可执行的路径。

**这不是新系统。**台账已经是同一张图：`req_doc` ∥ `task_book` ∥ `board` ∥ `executor` 是四条边，六态迁移就是时间维，`close --batch` 就是沿边批量改状态。缺的只是**文档与代码之间**那一条。

## 2. 功能点

| # | 功能点 | 判据 |
|---|---|---|
| **F1** | **边表与台账同库** | 边表与台账行住在**同一个 SQLite 文件**里，不新建第二个库。**为什么**：同一件事存两份，正是本项目所有「说假话」的病根（`#2183` 两个工具两套回执、`#2233` 两处记账）——换个地方再犯一次没有意义 |
| **F2** | **锚点解析复用 `doc_check`，不另写一套** | 文档里的边从既有的锚形状里抽，不新造语法：`doc:section` 形 ∥ `§N.M` 节号 ∥ 反引号里的符号名 ∥ `test/RTM.md` 的行号 ∥ 台账的 `task_book` ∥ 需求编号（`F16` 这类）。`doc_check` 今天**只抽出其中两种**（档 token ∥ `§N` 节号，形单源 = `thincoder-core/doc-check/anchors.mjs` 的 `ANCHOR_RE`）；其余四种（反引号符号名 ∥ `test/RTM.md` 行号 ∥ 台账 `task_book` ∥ 需求编号）**本面新加**，但加在**同一次逐行遍历**里，不写第二个解析器。**为什么**：同一份文档被两套解析器读，两边迟早给出不同答案 |
| **F3** | **三类查询** | ① **正向**（这条引用了谁）；② **反向**（谁引用了它——今天完全答不了的一类）；③ **链路**（从一个需求走到它的设计节、批次、用例、代码符号）。三类都只依赖边表，不依赖文档内容的相似度 |
| **F4** | **每条边带出处** | 边的形是 `(source, kind, target, evidence)`，`evidence` 记**它长在哪一档的哪一处**。**为什么**：没有出处的边就是一条断言；本项目连读数都要求可复跑，关系更不能例外 |
| **F5** | **优雅降级** | 仓库没有需求档 ⇒ 退到「设计 ↔ 代码 ↔ 用例」；连设计也没有 ⇒ 退到「代码 ↔ 会话记录」。降级要有明确读数（「本仓无需求层」），不留空白。**为什么**：用户第一次问就得到空白，会认为这个功能是坏的 |
| **F6** | **换一次说法也能找到** | 同一件事在不同文档里常换写法（「桥面仍全过才写」对「桥面逐条成败」）。**不追求语义理解**：边按**目标身份**连（同一个节号、同一个符号名），不按字面连；因此换了说法的引用只要指向同一目标，仍然连得上。**为什么**：按字面连的检索，我们已经有 `grep` 了 |

## 3. 边界（不做什么）

- **用例→代码的边是 import 边，不是断言边**——用例 `import` 的是被测入口符号（`editTool`），断言里的字符串是**运行结果**，不是引用。把它当边等于要求工具做「字符串 → 符号」的反推，那就是语义匹配，与本档「不引进大模型抽边」的边界相冲。**真想问「哪个用例跑到了这个符号」**，业界唯一的可靠办法是运行时覆盖（TIA 那一派：用覆盖数据建代码→用例的映射），那要插桩、要跑测试，**本版不做**。
- **不做可视化图谱界面**——好看，但用户看不完，也不解决问题。查询面是文字。
- **不引入图数据库 ∥ 向量库 ∥ 大模型抽边**——分别是「服务 + 备份 + 运维」「相似度而非精确边」「会丢且丢得不确定」。`node:sqlite` 是内置的，够用。
- **不要求用户维护边**——需要人填的图没人会填；边从既有文档里抽。
- **不替代 `doc_check`**——`doc_check` 判「这句话还对不对」，本面记「谁和谁有关」。两者判的东西不同，不合并。
- **不判内容质量**——本面只判关系在不在、指向的东西在不在盘；写得对不对归评审。
- **不做全仓常驻索引服务**——查询时按需扫，不新增常驻进程。

## 5. 依赖

- **上游（现成）**：`thincoder-core/doc-check/` 的锚点解析（判 `档缺` ∥ `节缺` ∥ `引缺` 的那套）、`thincoder-core/ledger-db.mjs` 的 `node:sqlite` 句柄、各项目的 `PROJECT-MANIFEST.json` 的 `docRoot` 声明。
