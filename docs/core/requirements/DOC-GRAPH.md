# 文档锚点图（DOC-GRAPH）· 需求

> 板块 = 文档、需求、用例、符号与台账之间的可查询关系。
> 设计 = `docs/core/design/DOC-GRAPH.md`。

## 1. 模块目标

把文档引用关系保存为可反查的边，回答“谁引用了它”“这条需求如何连到设计、用例和代码入口”。

图只表达可静态确认的关系，不用语义相似度猜测，也不替代评审。

## 2. 功能需求

| # | 功能 |
|---|---|
| F1 | 边表 doc_edges 与台账位于同一项目 SQLite 数据库 |
| F2 | 文档边复用 doc_check 的同一次逐行解析，不另写竞争解析器 |
| F3 | 提供 scan、forward、reverse、chain 四种动作 |
| F4 | 每条边携带来源文件、运行时行定位和行首片段作为 evidence |
| F5 | 缺需求层等降级状态有明确说明，不把空结果当降级 |
| F7 | 子代理、会诊与评审可读图；scan 只由 depth-0 主 agent 执行 |

## 3. 节点与边

节点身份支持 req、doc、doc#section、case、symbol、ledger、board、session。

存储边包括：

- cites：文档到文档或节。
- cites-req：文档到需求编号。
- mentions-case：文档到用例编号。
- case-file：RTM 用例到用例文件。
- cites-symbol：文档到反引号符号。
- imports：用例文件到具名 import 符号。

台账 task_book、req_doc、board、executor 在查询时投影，不复制进边表。

## 4. 查询语义

- forward 列出起点出边。
- reverse 列出指向目标的入边。
- chain 按边数分层走查，可正向与反向交替。
- kind 只接受六个存储边类的逗号分隔子集；省略时包含存储边与台账投影。
- 文档整档与节在查询邻接时按档折叠，但每条边保留真实目标。
- 自环不入边。
- chain 超层宽或超深度时必须说明截断与收窄方式。

## 5. 状态与降级

| 状态 | 含义 |
|---|---|
| ok | 文档目标已检查且存在 |
| 目标不在盘 | 文档目标已检查但不存在，边仍保留 |
| 判不了存在性 | 需求、用例、符号、投影或不可检查的仓外目标 |

没有扫描过、数据库不可读、没有该类边和筛选后为空必须可区分。

## 6. 边界

- 不做运行时覆盖率或测试影响分析。
- 不从断言字符串反推代码符号。
- 不做可视化界面、向量库或大模型抽边。
- 不要求用户手维护边。
- 不替代 doc_check 或评审。
- 不做常驻索引服务。

## 7. 验收

1. 同一文档正向与反向查询一致。
2. 整档与节引用都可反查且保留原目标。
3. 目标删除后重扫仍显示原边和目标不在盘。
4. 缺需求层时给出降级和实际可用边类。
5. 子代理无 scan，depth-0 可 scan。
6. kind 非法值明确拒绝，不能变成“没有边”。
7. chain 的宽度与深度截断可见。
8. 台账投影随当前行读取，不形成过期副本。
