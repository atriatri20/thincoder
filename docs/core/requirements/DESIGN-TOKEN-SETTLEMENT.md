# 设计评审凭证结算（DESIGN-TOKEN-SETTLEMENT）· 需求

> 板块 = 凭证的结算、持久化、回读、批归属、封印、清点与消费。
> 设计 = `docs/core/design/DESIGN-TOKEN-SETTLEMENT.md`；生命周期 = `ENG-TOKEN-BINDING.md`。

## 1. 总体目标

设计凭证在挂起、后续回合和进程重启后仍可用；消费后不能从持久槽复活。内存是运行态，槽文件是权威持久面。

## 2. 功能需求

| # | 需求 |
|---|---|
| F-D1 | settle 当场同步落盘；失败则结算失败、可重评，不留下“内存有盘上无”的授权 |
| F-D2 | spawn 门先读内存，miss 回读槽；not found、畸形和过期均拒绝 |
| F-D3 | 保存合并不得让空态或忙时保存误清槽；同 key 按当前新写者规则处理 |
| F-D4 | 单值镜像不再运行时使用；旧会话只做当前兼容迁移 |
| F-D5 | 工程写门资格按任一活槽判断，畸形或过期不构成活槽 |
| F-D6 | consume-design 删除内存与持久槽；失败整体回滚，消费后同 id 不再可用 |
| F-D7 | 凭证记录批档归属；spawn 的 batchDoc 必须与槽归属一致 |
| F-D8 | close 与 status→已收口在状态变更前消费本批槽；失败则拒绝收口 |
| F-D9 | 签发时固化被审文档封印；派单复算，内容变化或不可读时拒绝 |

## 3. 清点与消费

| # | 需求 |
|---|---|
| F-SL1 | design-slots 只读列出 designId、live/expired、龄、到期、批和 designToken；不写槽 |
| F-SL2 | consume-design 支持 designId、designIds、expired、olderThanDays，恰选一个选择器 |
| F-SL3 | 清点行直接提供 designToken；畸形记录标 —，designId 可精确过滤 |

槽文件与内存并集按当前冲突规则读取。无批归属时显示 —，不猜批次。

## 4. 批归属与封印细节

批归属优先取评审实例 run.batchDoc；旧调用形可从 docSetKey 中唯一批档兜底。归属不确定时如实降级，不把批档并入 documents 来改变评审实例键。

封印集合 = 评审 documents 中排除批次档后的文档。按清单顺序读取原始字节，档间以换行分隔，计算 sha256。槽同时保存清单与逐档 hash 供拒文定位。

旧槽缺少归属或封印时按兼容规则处理；读取失败不能伪装成“字段不存在”。

## 5. 非功能需求

- 凭证值不进入需求、设计和批次正文。
- 跨进程恢复保持同一授权结果。
- CLI、VSC、Desktop 等宿主语义一致，存储载体可按宿主生命周期接线。
- 所有失败有可见原因，不用静默降级替代授权判断。
- 验证不依赖真实外部模型；集成场景按真实业务 delta 进入 RTM。

## 6. 范围边界

不做 fire-and-forget 授权落盘，不恢复双真相镜像，不给过期凭证授权通道，不为了“找回已消费凭证”新增恢复机制。
