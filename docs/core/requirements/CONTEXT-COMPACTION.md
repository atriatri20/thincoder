# 上下文压缩与文本预算（CONTEXT-COMPACTION）· 需求

> 设计 = `docs/core/design/CONTEXT-COMPACTION.md`；共享核边界 = `CORE-UNIFICATION.md`。

## 1. 范围

上下文预算、自动与主动压缩、探索蒸馏、恢复回声和文本截断由 core 提供同一语义。宿主负责进度与结果呈现。

会话标题由 core 统一生成与保存，规则见 `SESSION.md` §8；本档只管标题所占的文本预算，不管标题怎么来。

## 2. 自动压缩

- 只在配对安全的边界压缩，不能留下孤立 tool 结果。
- 完整 prompt 预算包含 system、tools 和 history。
- 显式 agent.compactThreshold 优先；缺省时按当前有效窗口与完成预留派生。
- 有效窗口在 tiny 档收敛为 `min(模型窗口, 262144)`；normal 与 engineering 用模型窗口本身。切换档位即生效与解除。有效窗口是每次按当前档位推导出的策略值，**本身不落盘、不跨会话带走**；档位（mode）是另一件事，按 `SESSION.md` 随槽保存和恢复，两者不可互相代入。
- 输入上限 = 有效窗口 − 输出预留。压缩线、尾部预算、用量百分比和发送前守卫一律从输入上限派生，不以窗口为分母各算一套。
- 派生必须单调：窗口增大时输入上限与压缩线都不得减小。
- 自动压缩线 = 输入上限 − 注入余量，并封顶不超过 262,144。余量与上限都是绝对量，不随窗口缩放；取值与依据在设计档。封顶的来由：大窗口模型在超长上下文上注意力会退化，用不到的那部分不让它进上下文。
- 预留使用实发 maxTokens；未发时使用服务端默认输出上限，并与规格 maxOutput 取较小者（思考模型 64K、非思考 8K，`reasoning_effort: max` 档 128K）。预留反映的是实际会占用的输出预算，不是规格上的输出能力上限，因此不取「能力上限封顶」。
- 输出预留不小于有效窗口是配置矛盾：装载期报错并点名窗口、预留与算出的数，不由兜底值代跑。
- 只有预计压缩后能回到阈值下才做普通阈值压缩。
- 超过真实请求预算时允许当前强制压缩与一次越窗自愈；仍失败则 typed error，不静默截断。
- 处置按代价递进：先裁保护尾之外的陈旧工具输出（零模型调用），再摘要，再丢弃最早段；每步后重测，够用即停。摘要失败一次即转丢弃，不等连续失败累计。
- 尾部保留量由压缩线倒推：压缩线减固定开销与摘要预留，不用窗口比例。
- 窗口能力在会话中途变化（切模型、调小窗口、改 reasoningEffort）时，在下一次请求前预判并处置，不等守卫拦下。
- 丢弃最早段是最后手段，丢弃后要在宿主可见状态里交代丢了多少条。

## 3. 估算与校准

- 有服务端实测时以实测为基线，再加增量估算。
- ASCII 与非 ASCII 使用当前加权估算；图像和 tool_calls 纳入。
- 自校准样本随会话槽恢复，估算器版本或模型不符时不复用。
- 比例不得低于当前安全下界，避免把该压缩判成不该压。

## 4. 摘要与双线

- 机读 history 可摘要、截断或 prune；人读线与落盘记录不因压缩而丢失（落盘尺寸约定见 §5）。
- 摘要保留当前任务、设计决策、文件、未决点和约束，区分已完成与进行中。
- 摘要有当前长度目标，但不靠硬切丢尾部。
- 压缩或蒸馏调用不把内部文本流式显示成用户回答。
- 恢复时归并当前病态 reasoning 回声形态，不改写人读记录。

## 5. 轮次边界的机读历史

- 当前运行轮保留完整用户消息、assistant tool_calls、tool 结果和最终回复，保证本轮能依据真实执行结果连续工作。
- 轮次结束后，最近两轮的工具调用和结果保留在机读上下文里；更早轮次的工具过程退出，只留用户请求、最终回复和任务状态。工具调用与结果必须成组移除，不留下孤立配对。
- 保留的两轮跨会话恢复后仍在——重启不改变这条边界。
- 任务状态至少包含当前目标与完成状态、实际修改文件、验证命令及真实结果、关键证据位置、未完成事项和阻塞点。
- 任务状态由运行过程生成，不以模型事后回忆代替执行事实。无工具的简单问答可只保留用户请求与最终回复。
- 折叠掉的过程在任务状态里有一行交代：被折掉的工具结果条数与体量。量低于阈值时不出现这一行。
- 人读历史保存工具过程并可经 read_history 查询；超过 500 字符的工具输出在落盘时只存前 500 字符，取回面必须如实说明这一点，不得声称全文可取。

## 6. context 工具

depth-0 提供 stats/prune/compact：

- stats 报告总量、窗口、压缩线、请求预算、分段和缓存读数。
- prune 只替换保护尾之外的陈旧工具输出内容，保持消息配对与全史。
- compact 携 focus 排队到下一安全点，复用同一压缩机器，回执给全史取回坐标。

子代理没有全史回查面时，不提供这组主动操作；阈值兜底仍有效。子代理的受限回查面（只读父会话、限定本批窗口）不算全史回查面——两者语义不同，不能互相替代。

## 7. 探索蒸馏

run 末尾可把本轮成批探索结果蒸馏为语义摘要。失败不阻塞返回，不删除原始全史。

蒸馏和压缩复用当前会话前缀、tools 声明与 reasoningEffort 规则，不另造协议。

## 8. 体验

压缩开始、进行中、成功、失败和降级都有宿主可见状态。headless 没有回调时安全 no-op。

VSC/TUI/Desktop 的呈现可不同，状态语义一致。

## 9. 边界

不新增 /compact 命令，不自动判断任务转向后强制压缩，不用摘要质量换速度，不通过降低 maxTokens 掩盖预算错误。

## 10. 验收

验证：

- 有效窗口在三档下的取值：tiny 取 `min(模型窗口, 262144)`、其余取模型窗口、切换即生效与解除。
- 输入上限与压缩线从有效窗口单向派生、随窗口单调不减。
- 压缩线在封顶段饱和：窗口再大也不超过 262,144，而输入上限仍随窗口增长。
- 用量百分比与判定同基准。
- 装载期拒绝预留 ≥ 窗口，且无兜底值代跑。
- 处置链在裁剪后够用即停、摘要失败即转丢弃、切换模型时预判并处置。
- 强制压缩只回阈值下且可越窗自愈一次；固定开销单独越线给 typed error 且 `force` 跳不过。
- 轮次边界保留最近两轮工具段而更早轮折叠；折叠提示只报量且低于阈值不出现；回查面截断标记按角色分支。
- 蒸馏失败不阻塞且不删原件。
- `context` 三动作与子代理准入。
- 恢复归并病态相邻回声。
