# 结构债（STRUCTURE-DEBT）· 需求

> 设计方法 = `docs/core/design/STRUCTURE-DEBT.md`；代码判据 = `docs/core/standards/CODE-TIER.md`。

## 1. 总体目标

结构问题必须在当前任务内修复，或由主 agent 在任务范围内明确入账。不能用“原本如此”或“最小补丁”掩盖被当前改动撞到的结构错误。

范围外观察只是猜测，不自动成为债务事实。

## 2. 功能需求

| # | 需求 |
|---|---|
| F-SD1 | 当前任务内确认的结构缺陷有可见处置与证据 |
| F-SD2 | 需要独立交付目标时另起批次，走该模式当前流程 |
| F-SD3 | 被当前改动撞到的结构问题优先修复；确需入账时 trigger 与批次关系真实 |
| F-SD4 | 债务只入 ledger，不在设计档另建平行总账 |

## 3. 非功能需求

| # | 标准 |
|---|---|
| N-SD1 | 文件长度判定时机和阈值以 CODE-TIER 为唯一来源 |
| N-SD2 | 不用额外的中间检查或软线扩大规则 |
| N-SD3 | 函数随生长分解；文件未越线也不能掩盖超长单体函数 |
| N-SD4 | 文档段长、行号锚和悬空指针按 DOC-CHECK；文档不套代码行数档 |
| N-SD5 | 同一仓与共享核使用同一套结构判据 |

## 4. 边界

不自动重构，不把设计档当债务清单，不设存量豁免，不把范围外猜测写成已验证缺陷。
