# agent 主循环与子代理（AGENT-LOOP）· 需求

> 设计总档 = `docs/core/design/AGENT-LOOP.md`。
> 分面 = `AGENT-LOOP-ASYNC-POOL.md`、`AGENT-LOOP-SUBAGENT.md`、`AGENT-LOOP-UPSTREAM.md`。
> 共享核边界 = `CORE-UNIFICATION.md`。

## 1. 总体目标

主循环、工具调度、子代理、评审、挂起和唤醒由 core 提供同一语义。端壳只提供宿主输入、呈现、权限和生命周期接线。

## 2. 主循环与交互

### 2.1 question

question 每次只问一个真正需要用户输入或选择的问题。常规确认走普通回复。问题和选项保持简短，宿主以可读卡片呈现。

### 2.2 顶层异步

depth-0 的 spawn、escalate、advisor 必须显式异步。depth>0 的 spawn 同步执行。异步结果自动送达，不用轮询或阻塞取回。

### 2.3 主循环

- runAgent 负责装配、模型轮、工具批、完成守卫与收尾。
- resume 保留需要跨续跑的验证、评审和写序状态。
- 用户中止优先于撞帽续跑。
- 空响应、缺失 finishReason 和异常结束不得静默当成正常完成。

### 2.4 Stop 钩子

主会话 run 在 done、maxTurns、error 时各触发一次 Stop；用户中止与子代理不触发。载荷含 turn、reason、timestamp 和必要错误，不包含回答正文。

Stop fire-and-forget，失败不影响主流程。无工具名事件不使用工具 matcher。

## 3. 子代理与调度

### 3.1 角色

- explore：只读探索。
- plan：普通模式只读规划。
- coder：普通模式实现。
- eng-designer：工程设计。
- eng-coder：工程实现。
- tester：运行验证并返回读数，只跑不改。

模式、depth 和角色共同决定可用工具。子代理不获得交互式 question/ssh，探索与评审不注入 git 快照。

### 3.2 观测与引导

status 覆盖子代理和后台评审；observe 返回运行中子代理的近期摘要；send 在下一边界向运行中异步子代理投递普通指令。

cancel 只接受明确 id，支持运行和排队条目，幂等且不误停其他任务。

### 3.3 调度

files 声明文件级写入域，dependsOn 声明依赖。相同文件和依赖由调度器排序；files 不是写权。

同一批次档同时只服务一个并发 spawn。顺序交接可复用同一档。

### 3.4 tester

tester 在两种模式都可由 depth-0 派发。它有只读工具与 execute/bash，没有写文件、verify、advisor 或 batch 面。

报告包含命令、退出码、通过/失败读数、失败名称、关键输出和实际写入位置。测试准备产生的临时文件不等于获得实现权限。

## 4. 异步池与结果

### 4.1 分域池

eng-coder、其他子代理和 advisor 分域限流；池满按当前队列规则处理。相同评审 scope 不并发。

统一 settle 负责状态、日志、pending、唤醒、取消和补位；族特有记账通过 hook。

### 4.2 投递时点

- 用户排队消息在用户回合的步边界消费。
- 子上行、结算报告、后台工具返回和 timer 在主会话空闲开启的交付轮消费。
- 用户新回合不夹带未投递的异步结果。
- 无挂起驱动的 headless/ACP/直连面使用不丢件的回退路径。

### 4.3 消化账务

投递不等于销账。消化轮逐条报告处理状态；未覆盖条目保持可见并计未签收轮，达到当前上限后升级为未处理终态并披露完整正文入口。

同一报告不反复重投。状态与面板能读到未消化和已升级条目。

### 4.4 中止

会话中止只丢弃符合当前死亡判据的条目，留下 discarded 终态和一次汇总提醒。依赖方不能把丢弃当成成功报告。

## 5. 上行通道

depth>0 子代理用 notify_parent 发送 ask 或 note，立即返回并继续不受影响的工作。

父在交付窗接收；ask 可唤醒父侧处理，note 留待下一交付窗。回复复用 subagent send。

同一子代理未取走的 ask 至多一条；消息与父队列有当前长度上限。同步子代理只能单向通知，回复不可达时受影响部分不做并在终态说明。

投递标识为 `[上抛·待裁]` 和 `[上抛·知会]`。它们是待处理输入，不是用户裁定。

## 6. 停滞与资源

### 6.1 零产出提醒

eng-designer/eng-coder 连续 50 轮无文件写序推进时向父发 note；异步 advisor 连续 50 轮无评审文本时同样提醒。

提醒只要求父侧 observe/status 后 steer 或 cancel，不自动杀或重派。同文件重复编辑算产出；失败写入不算。

### 6.2 内存上界

子代理人读历史、捕获输出、消化后对象引用和轨迹在途写盘都有当前上界与释放点。释放不能提前删除未消化报告。

### 6.3 abort 来源

中止错误保留结构化 trigger、layer、detail。报告标明 user/timeout/cancel/stop/unknown 与 provider/agent/settle 来源；未知要显式。

## 7. 上下文与模型

- 记忆召回只在 depth-0 非 resume 面注入，子代理按需查询。
- 文档自动注入为本仓与声明源分别保留当前名额，不减少本仓配额。
- 子代理 system 固块包含批次、写域和文档坐标等 spawn 级稳定信息。
- reasoningEcho=required 族的工具轮 assistant 消息恒带 reasoning_content；无推理时为空串，optional/未声明族不带。
- autoThink 默认关闭，模型能力和宿主差异经配置与装配面接线。

## 8. 验收

1. 顶层同步被参数门拒绝，子层同步可用。
2. 状态、取消、依赖、文件冲突与同批占用结果正确。
3. 用户输入优先，异步结果不丢、不重复、不静默销账。
4. 中止、撞帽、空响应、缺失停因有可见终态。
5. tester 只跑不改，能返回真实失败。
6. 上行 ask 可唤醒，note 不错误唤醒，来源标识保留。
7. 资源释放不改变报告可达性。
8. 各端复用 core 语义，宿主差异不改变业务结果。
