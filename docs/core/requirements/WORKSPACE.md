# 工作区约定（WORKSPACE）· 需求

> 本档覆盖技能、规则、同伴实例和项目工作管理面的共享机制。
> 当前设计 = `docs/core/design/WORKSPACE.md`。

## 1. 总体定位

工作区约定是面向任意项目的共享能力。机制由 core 统一实现，端侧只负责宿主适配、界面呈现和必要的环境差异。

## 2. 功能需求

| # | 需求 | 验收 |
|---|---|---|
| F1 | 技能发现 | 支持项目级和用户级技能，项目级优先；支持扁平 `.md` 与子目录 `SKILL.md` |
| F2 | 技能加载 | 列表只提供发现信息，具体内容通过 skill 工具按需加载 |
| F3 | 流规则 | `.thincoder/rules/` 支持 pattern、action 和 repeat，并按当前流处理语义执行 |
| F4 | 作用域规则 | `.cursor/rules/` 支持常驻、路径作用和仅描述条目；注入规则明确且去重 |
| F5 | 同伴实例 | 可发现同工作区或可寻址的其他实例，并提供明确的通信边界 |
| F6 | 工作管理 | 项目工作项与展示逻辑使用 core 的统一数据和规则 |
| F7 | 端侧适配 | 端侧可以转口 core 接口或注入宿主呈现，不维护另一份业务规则 |

## 3. 非功能要求

| # | 维度 | 标准 |
|---|---|---|
| N1 | 确定性 | 技能与规则发现顺序稳定，不受文件系统枚举顺序影响 |
| N2 | 单一来源 | 相同发现、分类和匹配规则只在 core 维护一份 |
| N3 | 可移植 | 不要求特定操作系统、git 仓形状或本仓目录 |
| N4 | 可见失败 | 无法读取或无法执行时按业务语义明确报告，不伪造成功 |
| N5 | 独立验证 | core 机制可独立验证，端侧只增加真实宿主集成场景 |

## 4. 边界

- 不把端侧 UI 样式提升为共享业务规则。
- 不为同一机制维护多套发现或匹配实现。
- 不把历史合并裁决表当作当前需求。
- 不把会话内 task 与项目长期工作项混为一种数据。
