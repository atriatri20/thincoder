# Function Spec · 跨仓写入（`writableRepos`）

> 模块划分权威源 = `docs/core/design/ENGINEERING-MODE-V2.md` §2.2（M1 声明面 / M2 台账 / M4 写门）
>
> 来源 = 外部项目（v2-vibe-coding）issue《需要能写指定的外部项目目录》+ 用户 2026-11-09 17:04 口述方向。

## ① 模块目标

一次开发要同时改两个仓时（业务前端 + 它依赖的底层库），**写权与记账都落在发起方**——不再因为跨仓而被迫开第二本账。

## ② 功能点

1. **声明键 `index.writableRepos`**：路径数组，相对本仓根，缺省 `[]`；与 `index.publicRepos` 同一套归一化（空元素 ∥ 非串元素剔除，非数组 ⇒ 档非法 fail-closed）。
   - **它声明的是写面，不是读面**：`publicRepos` = 可引用的仓（读 / 出边 / 跨仓指针解析），`writableRepos` = 可写的仓。**两个键互不推导。**
2. **写门取根判据**：一笔写落到目标 `p`，解析出它所属项目根 `R`——
   - `R` = 本仓根 ⇒ 今天的行为不变（查本仓账）；
   - **用本仓的账**写外部目标（`project` 指向本仓根）且 `R` 在 `writableRepos` 内 ⇒ **号查本仓台账**（今天查的是 `R` 的账）；
   - **用本仓的账**写外部目标且不在声明内 ⇒ **直接拒**（报文点名 `writableRepos` 与目标）——**不回落到目标仓自己的账**；
   - 不声明写方、改用**目标仓自己**的在途号写它 ⇒ 走现行路（那是目标仓自己的批，不是本仓的跨仓写）。
3. **不推导**：同 workspace 不自动开放；有 `publicRepos` 声明不等于可写；历史上常一起改不自动开放。**用本仓的账写外部目标，唯一入口 = `writableRepos` 逐仓具名**；不声明就只能用目标仓自己的台账号写它——那是目标仓自己的批，不是本仓的跨仓写。
   - **「声明了写方」与「用目标仓自己的号」互斥**：一笔带了 `project` 的写，在此目标上只能走声明的那本账；表外即拒，**不得**因为目标仓台账里恰有同号在途行而放行（台账号按项目各自编号 ⇒ 重号是常态，不是授权）。
4. **不传递**：A 可写 B，不等于 A 可写 B 能写的 C。
   - **入口一刀切**：凡带定位参数、带 `project` 的写型入口（写盘七件 ∥ `execute` 的 `workdir` ∥ `manifest` 的 `target`）走**同一判序**——不因工具不同而给某一把留一条回退路。
   - **目标无项目根时，写权表仍然是界**：会话锚是工作区根、目标取不到项目根时，窄口只在**写权表为空**时维持现状；**表非空 ⇒ 目标必须在表内**，否则拒。
5. **记账归属 = 写方**：跨仓写入记在**写方**的批档与台账行；目标仓账上不留行。
   - **代价（明确）**：目标仓的收口判据不知道自己的文件被改过；它要问「谁动了我的表结构」，只能去写方的批档里翻。
6. **提示词与工具面在本批内一起改**：新键要在**同一批**里出现在它该出现的每一层——schema（`DEFAULT_MANIFEST` 与校验）· 工具描述（`thincoder-core/tool-docs/manifest.md` 的键目录与节点计数）· 提示词（工程模式主 agent 的写门教学段：何时该声明、声明了什么代价）· 设计档（`docs/core/design/MANIFEST.md` 键面 + `docs/core/design/BATCH-LEDGER-REVIEW-UNIFY.md` §2.3 取根判据）。**漏一层 ⇒ 那一层就是下一次「照旧做」的依据。**

## ③ 边界（不做什么）

- **不做双向同意**：目标仓不参与授权。理由（用户 2026-11-09 17:05）：「偷偷改的限制我们会在 git 的权限上控制，能提交就是允许他改」——**真正的门是 git 权限，写面不做第二道锁。**
- **不在目标仓留账**：见 ②.5 的代价，这是选择不是遗漏。
- **不给写面建依赖图、不做环检测**：`publicRepos` 是依赖边（会成环，环有意义）；`writableRepos` 是授权表，A↔B 互相可写不产生歧义——两边写入各记各的账。
- **不改 `publicRepos` 现有语义**（读面 / 出边 / 跨仓指针解析一字不动）。
- **不做跨仓批的收口结构改造**：本批只解决「能不能写 + 记哪本账」。**一个批仍然只对应一本批档、一个仓**——第一笔真正的跨仓批会暴露 §6 交付面、台账核销、回滚都按单仓假设写的；那是下一件事，本批只把它写进已知限界。
- **面的判法不因跨仓而变**：目标落在外部仓时，面按**目标仓自己的** `docRoot` 判，门禁与本地逐条相同——文档面不触发设计门（本地亦然），产品面照拦。本批只复核这一条，不改面判本体、不加第三个面值。

## ④ 验收（逐条可机判）

| # | 判据 | 方式 |
|---|---|---|
| AC-1 | 声明后可写，且号**只在本仓账上**查得到（对侧仓无该号）⇒ 通过 | 对侧仓台账无此行 → 写入期望过 |
| AC-2 | **用本仓的账**写未声明的外部仓 ⇒ 拒，报文含 `writableRepos` 与目标路径 | 本仓在途号 + `project:<本仓根>` → 期望拒 |
| AC-3 | 声明只写了 B，去写 C ⇒ 拒（不传递） | 写 C → 期望拒 |
| AC-4 | 只有 `publicRepos` 声明 B、没有 `writableRepos` ⇒ **用本仓的账**写仍拒（读 ≠ 写） | 本仓在途号 + `project:<本仓根>` → 期望拒 |
| AC-5 | 同 workspace 下未声明 ⇒ **用本仓的账**写拒（不推导） | 本仓在途号 + `project:<本仓根>` 写同级仓 → 期望拒 |
| AC-6 | `writableRepos` 非数组 ⇒ 档非法（fail-closed）；缺键 ⇒ `[]`（不拒） | 构造非法值 → 期望拒；删键 → 期望默认 |
| AC-7 | **表外不回落**：带 `project:<本仓根>`、目标属另一个项目且不在表内 ⇒ **拒**，即使目标仓台账里掐有一条同号**在途**行 | 目标仓先挂一行号→ 同号写表外目标 → 期望拒（改前：放行） |
| AC-8 | **入口一刀切**：`execute` 的 `workdir` ∥ `manifest` 的 `target` 指向表外另一项目 ⇒ 拒绝且目标字节零变 | 两把各一格：带 `project:<本仓根>` 写表外 → 期望拒 |
| AC-9 | **窄口仍以表为界**：会话锚是工作区根、目标取不到项目根 ⇒ **表空**维持现状（放行）；**表非空且目标在表外** ⇒ 拒 | 两格：清空表写无根目录→放行；表非空写表外无根目录→拒 |

- **下游**：无（本批不开放新的消费面；写面不进依赖图是 ③ 的明选）。
