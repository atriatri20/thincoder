# 代码行数档位（CODE-TIER）· 标准

> 层 = 标准层（`docRoot.standards`）。兄弟档 = `docs/core/standards/METHODOLOGY.md`——需求形的那一份：F3-1 给判据、F-R24a 给受影响文件表的归处。
> 本档答一个问题：代码档到了多少行，该怎么处置。规则正文只在这里写一份，其余各面指过来，不各写一份。

## 1. 判定对象：代码档，不是文档

对象 = 源文件 ∥ 测试文件。文档面（设计 ∥ 需求 ∥ 批次 ∥ 台账）不受行数限制，依据 = `docs/core/requirements/ENGINEERING-MODE-V2.md`「文档（设计 / 需求 / 批次 / 台账）不受行数限制——无任何行数义务」。

读到一份 `.md` 的行数，那是读数，不是判据的触发物——不因它启动任何拆分讨论。

## 2. 要的就是机械化：判定时点只有两个

用户 2026-11-11 03:09 定稿，逐字：「我觉得我中间别为代码长度纠结了，就设计器判一次，收口检查判一次，中间其他地方对代码长度的检查一概都取消，这样最干净。」

中间每加一处长度判断，就多一个要解释、要豁免、要吵「这算不算超」的点；两头各判一次，规则才真机械。

**① 设计时判一次 = 500（设计器判；判的是改代码前的长度）**

- **过 500（> 500）⇒ 必须给分拆方案，且分拆在本批内实施**：拆哪几族、切在哪、为什么切在那里，拆出的档在本批落地。硬性义务，没有裁量空间——「另起一批拆」不是方案，「另批再说」一类措辞即逃生口，与本条相反。
- **未过 500（≤ 500）⇒ 不提分拆**：不进分拆讨论，不写方案，也不写「故不拆」一类判断。
- **基准 = 改代码前的长度**：判本批改动**之前**该档的读数。不是改动之后的行数，也不是改动的预测增量。
- **新建档没有「改前」**：判它落盘时的长度——它是本批写出来的那一档。
- **履行位置**：方案写在批档 §2 的受影响文件清单里（归处 = `docs/core/standards/METHODOLOGY.md` 的 F-R24a），由设计轮自己写下，不另设检查面。

**② 收口时判一次 = 800（收口检查判代码长短；另外判一条记录缺件：缺方案 ∥ 缺读数）**

- **过 800（> 800）⇒ 先拆再落**：拆分是落地的前置条件，不与落地并行。
- **未过 800（≤ 800）⇒ 不因代码长短要求拆分**：收口面在长度上只判这一条。它另判的那一件不是长度，是 **§2 的记录缺件**，分两半，同一臂里一遍判完，两半的发现拼成一条拒文。
- **缺方案那一半**：本批改动面里实测越了设计时线的档，§2 必须带其分拆方案。没有越线档 ⇒ 这一半不启动，连 §2 都不看。
- **缺读数那一半**：本批改动面里在盘的每个代码档（源 ∥ 单测），§2 的受影响文件表必须为它带一个行读数，值 = 该档**在批起 sha 上的内容行数**。触发物 = 改动面里有码档，几乎每批都有，所以这一半没有「不启动」的口。
- **为什么要核、核的为什么是基线**：§2 里那个数要成立，得设计时真量过（依据 = `docs/core/standards/METHODOLOGY.md`「列出本批将改的源 / 测试文件，**逐档报出该档的原始行数**」），收口时再核它写没写错。只核「有没有数」等于没核——写个 1 也过。比对基准与 §2 ① 同一指向（改代码**之前**），取值面 = 批起快照上的读数（判法 = `docs/core/design/DOC-CHECK.md` §8），不是收口时盘上的长度。存量批的快照只是一份 HEAD 提交，未提交的改动不在其中——那些批那一格写快照读数，而 §2 ① 的 500 仍按改前长度判。
- **拒绝时会怎样**：收口不下，拒文逐档点名并写出「写的是几、基线是几」；两半的发现合成一条，设计席一次改完再收口，不必为同一张表收口两次。拒文措辞的单源 = `docs/core/design/DOC-CHECK.md` §8，本档不列。
- **批起快照里没有这一档 ⇒ 写 `新`**：快照里没有内容，设计时就没有数可报——写 0 会被读成「量过、是空的」，写别的数就是编。报 `新` 的条件只有一个：批起快照里没有这一档。成因（本批新建 ∥ 前批建了还没提交 ∥ 被 `.gitignore` 挡住）可写在表外，写不写都不进判据——那一格的值形只认数字 ∥ `新`，缀上字就按缺读数拒。反过来，快照里其实有这一档却写 `新` ⇒ 拒。

**③ 判定时点只有两个，中间一概不判**：设计时（500）∥ 收口时（800）。实施轮 ∥ 代码评审 ∥ 其他任何中间环节都**不作代码长度检查**——不是「也判 800」，是**不判**。

别处给中间环节排一个长度检查点、另立第三个判定时点（例如在两条线之间再加一条触发线），或把 500 说成非硬性的、要先自行审视的，都与本条相反；改法 = 指向本档。

## 3. 函数档位：同一张档位表的另一半

档位表先量函数、再量文件——函数是读者真正要读懂的那一层，文件只是它的容器。

- 一个函数 ≤50 行 = 正常；
- 50–100 行 = 审视是否该拆；
- ≥100 行 = 主动审视，拆出子函数；
- ≥300 行 = 必拆骨干。

判的是单个函数，不是文件；判据载体 = `thincoder-core/prompts/discipline-normal.md`。先函数后文件，**相对大小永远不是豁免**——「这文件虽 600 行但都是声明」不成立，声明也是理解成本。

## 4. 数值在哪、语义在哪

- **数值**（两条线各是多少）= 代码与提示词面的字面量：500 落在 `thincoder-core/agent-tools/batch-tier-gate.mjs` 的 `FILE_SOFT_MAX`；800 没有常量承载；判据句在提示词面自带数字（`thincoder-core/prompts/advisor-design.md` ∥ `thincoder-core/prompts/persona-eng-designer.md`）。改数就改这几处，改完用 §6 的按数检索扫一遍——数字不跟着改名走，只有搜过一遍才知道还有谁写着它。
- **语义**（哪条线管哪一面、过线判什么）= 本档。

改数改代码与提示词，改判法改本档——两件事不共用一个家。这两条线在登记处只有两个名字：**设计器硬线 500** ∥ **其他检查硬线 800**；换名字在命名处登记，见 §6。

**旧家那张「同口径共五处，任一处改动须同轮改其余四处」的清单已经退役。** 退役的不是义务，是那张固定清单：它列的五个落点里，两处提示词已改成自带数字的判据句（不再指过来），清单失去对象。义务现在由两处接住——**谁把长度判定派给中间环节 ⇒ 按 §5 改成指本档**；**改数 ∥ 换名 ⇒ 按 §6 的两条检索腿扫射程**，射程写在 §6。一张越列越短的清单，换成了「按判据搜一遍」。

## 5. 漂移怎么读：那一处把长度判定派给了谁

判据是**那一处把长度判定派给了谁**，不是它有没有提到 500 或 800。

- 派给设计时 ∥ 收口时 ⇒ 不是漂移。
- 派给别的时点（实施轮 ∥ 代码评审 ∥ 其他中间环节）、另立一条线，或把 500 说成可自行审视的 ⇒ 是漂移，改法 = 指向本档。

每一处命中按下面两类各落一次处置（判法自足：只看那一句，不必去翻任何批档）：

- **① 规则陈述**：对**将来**下命令、或陈述**当前义务**的那一类——句中带「须 ∥ 必 ∥ 不得」，或写成「过 X ⇒ 要 Y」「触发 = …」「未过 X ⇒ …」。这类**改成**两个判定时点并指本档；判不了的一律按 ① 办（宁改勿留）。
- **② 历批实施记录**：说**某一次已经发生的判断**的那一类——句中带批名 ∥ 「当时」∥「本批」∥「已落」「改后」这类时间锚，且不外推成对别档、别轮的义务。这类**原样保留**，改它等于改历史。
- **② 升 ① 的唯一条件**：那句记录里的判据会被读者当成现行规则去复跑（形如「按 >500 审视线判 ⇒ 不拆」——今天的档照它判一次，它就落进 ① 了）；升级后按 ① 处置。
- **650 那一族只删不点名**：「650 已废」这种话把一个死值放回检索面，写的人以为在清理，读的人以为它还在。

## 6. 候选面 = 两条腿，各补对方的盲区

名字会新增，阈值不会。下面的检索式只负责**找出候选**，本身不判漂移——判据在 §5。

```text
# 腿一 · 按名：句子不报数的那些靠它（「软线内，不拆」这一类）
grep -rnE --exclude-dir=batches "(软线|硬线|顾问线|咨询线|主动审视|拆分触发|advisory|soft limit|hard cap)" docs/ thincoder-core/prompts/ thincoder-core/tool-docs/
# 腿二 · 按数：句子报了数的那些靠它——名字怎么换都不影响，数不跟着改名
grep -rnE --exclude-dir=batches "(500|800|650)" docs/ thincoder-core/prompts/ thincoder-core/tool-docs/ | grep -E "(行数|长度|lines?|file size)"
```

**下一个别名怎么拦：注册点，不是词表。**两条线在本档只有两个名字（设计器硬线 500 ∥ 其他检查硬线 800）。给它们另起名字，只能在命名处登记——改 §4 那句命名，同一次改动把新名加进腿一。名字先出现在别处、本档命名没动 ⇒ 那处本身就是候选（一个没登记的名字），按 §5 的 ① 办。

**注册点是对命名者的义务，不是一条检测**：要发现「名字先出现在别处」，得另有一条按名检索，而**一个没登记的新名恰是腿一抓不到的**。故本法的残余写明在此：**一个既不报数、名字又不在表上的新名，两条腿都看不见**。它靠注册点（改名的人在同一次改动里登记）与逐轮清场兜，工具面兜不住——这不是「已完备」，是一条明写的残量。

**域含英文面**（`thincoder-core/prompts/**` ∥ `thincoder-core/tool-docs/**`）：中文字面串在这里永远零命中。

- 形例（英文面、两个数都在）= `thincoder-cli/AGENTS.md` 的「File size (source and unit-test files only)」条：「above 500 lines ⇒ the design must carry a split plan and the split lands inside this batch (no deferral to another batch)」∥「the check judges 800 lines: above ⇒ split before landing」。
- 腿一按名抓不到这种句子（一个中文别名也没有）：射程内报了数的英文面档位句，只有腿二看得见。

**没有第三条「按形」腿**：长度词 + 任意 `X线`／`X限` 同句的检索式，候选量是名腿的数倍，读的人会直接跳过——读不完的候选面等于不存在。词表不完整是已知代价，靠注册点补，不靠一条读不动的正则。

**射程**：`docs/**`（扣 `docs/batches/**`：历批记录按 §5 的 ② 原样保留，不入检索）+ `thincoder-core/prompts/**` + `thincoder-core/tool-docs/**`；域内文件类 = `.md` ∥ `.mjs` ∥ `.cjs` ∥ `.js` ∥ `.css`。射程与检索域不一致时，本档说的「0 处」只覆盖了检索域的一截——两处一起改，不各改各的。

**代码档头注面另成一路**：源档的档头注（`.mjs` ∥ `.css` 的行首 `//` ∥ `*` ∥ `/*` 行）落在上面射程之外的目录时，两条腿扫不到它，而那一面同样会下派判。该面用**同一串、只看注释行**单跑一遍；「射程内 0 处」只对上面那组路径成立，代码注释面的读数另记（住批档）。

**这条线在不在，看一处就够**：射程内「把长度判定派给中间环节」的陈述应为 0 处——任一处给实施轮 ∥ 代码评审 ∥ 其他中间环节排了长度检查，就是 §5 说的漂移，改法 = 指向本档。读到非 0 ⇒ 记成一张待清账单（哪几档、各改哪句），清账的排期归批的事。**本档只给这个读法，不下判决、不立检查点**——查与判都在 §8 点名的执行面上。

## 7. 量法：一个数只从一把尺取

源码 ∥ 单测档的长度怎么算，单源 = `docs/core/design/DOC-CHECK.md` §1；取数的唯一实现 = `thincoder-core/agent-tools/batch-tier-gate.mjs` 的 `countContentLines`。本档不复述那个定义。

同一个数只从这一把尺取——手数 ∥ 编辑器行号不是另一把尺，是错的：两个数一出来，没人说得出该信哪个。

## 8. 边界（本档不做）

- **不改数值**：500 ∥ 800 ∥ 50 ∥ 100 ∥ 300 各在哪（代码字面量 ∥ 提示词判据句）见 §4，改它们不走本档。
- **不管函数该怎么拆**：拆分的方向、切点与档名是一次设计的活，本档只规定「什么时候必须给、给了要落在哪」。
- **不做门禁**：本档是判据的语义单源，判据的执行面（设计轮自查 ∥ 收口检查 ∥ 评审维度）各在自己的位置，本档不新立检查点。
- **不承载逐批读数**：命中档数 ∥ 分类条数 ∥ 逐档处置属读数，住批档（D12）；**逐档原始行数住批档 §2 的受影响文件表**（归处 = `docs/core/standards/METHODOLOGY.md` 的 F-R24a），本档不载；本档只写阈值与关系。核它的是 §2 ② 的收口臂，比的是**批起 sha** 上的读数，不是收口时盘上的长度——本批实施就是要改长度，改过码档的批这两个数天然不同，拿盘上的去比等于每批拒自己。
