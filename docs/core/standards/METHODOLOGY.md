# 方法论（METHODOLOGY）· 标准

> 上位原则 = `docs/core/requirements/PHILOSOPHY.md`。本档把原则转为可执行的工程判据。
> 运行期落地 = `thincoder-core/prompts/` 与相应机制文档；本档不复制提示词正文，不设置独立设计档。

## 1. 总体定位

普通模式与工程模式使用同一套质量判据，差别在流程强度，不在正确性标准。

需求文档、设计文档和过程记录分别回答“要什么”“当前如何实现”“这一轮做了什么”。任何规则不得通过多份副本获得不同含义。

## 2. 基本流程

| 编号 | 要求 | 验收 |
|---|---|---|
| F2-1 | 开发按需求、设计、开发、测试组织；工程模式的结构约束按当前模式规则执行 | 能定位需求、当前设计、实际实现和验证结果 |
| F2-2 | 需求说明目标、功能、边界、非功能约束和验收 | 每个功能点都可由读者判断满足与否 |
| F2-3 | 需求经用户确认后进入项目约定的工作管理面 | 需求、执行记录和验收能互相对应 |
| F2-4 | 设计写当前结构、方案、理由、接口和边界；一次性文件清单与执行验收归过程记录 | 设计不包含会随本轮结束失效的施工账 |
| F2-5 | 测试与真实业务需求对应，覆盖正常、边界和错误；寿命按 TESTING | 用例指出输入、操作和可观察结果 |
| F2-6 | 设计前先调查同主题现行实现和文档，优先对齐；偏离须给理由 | 能指出最近先例、采用点和不采用的原因 |
| F2-7 | 每个针对输入或状态的分支都有真实观测、用户报告或可复现路径 | 说不出场景的分支被删除，而不是作为想象防御保留 |

## 3. 代码结构

详细阈值与判定时点 = `docs/core/standards/CODE-TIER.md`。

| 编号 | 要求 | 验收 |
|---|---|---|
| F3-1 | 函数和文件都受结构档位约束，不以相对大小或内容类型豁免 | 越档时按标准给出并实施拆分方案 |
| F3-2 | 一函数一概念；骨干与细节分开；边写边分层；模块围住决策；控制流使用 guard；状态机显式 | 读者能局部理解并独立验证 |
| F3-3 | 注释记录决策和坑；多端共享语义不独立漂移；发现错误结构时修复或明确上报 | 不以最小补丁掩盖结构性错误 |
| F3-4 | 拆分前评估理解、影响和可测试性；拆分后保持行为与断言语义 | 重构不借结构调整改变行为 |

## 4. 常用纪律

| 编号 | 要求 | 验收 |
|---|---|---|
| F4-1 | 会话任务与项目级工作项分开管理 | 不把会话内 task 当作项目长期账目 |
| F4-2 | 调试先读完整错误，再查官方资料，必要时二分定位 | 报告能指出实际证据和根因 |
| F4-3 | 阅读无法回答行为问题时，转为运行、日志或实验 | 不靠反复猜测代替实测 |

任何推迟、例外或不做的决定都必须明确呈现。不得让用户误以为某项工作仍会完成。

工程模式是否允许绕过流程由用户和当前模式规则决定。执行者不得自行发明“小改”例外。

## 5. 需求与工作组织

| 编号 | 要求 | 验收 |
|---|---|---|
| F5-1 | 需求按当前项目管理规则登记、归类和实施 | 用户明确要求开工时不再发明额外等待条件 |
| F-R24a | 代码受影响文件及原始行数住当前过程记录；设计状态文档不写一次读数 | 文件清单、基线读数和档位结论可按当前规则复核 |
| F-R24b | 设计评审核查过程记录中的代码档位和拆分计划 | 核查对象是当前过程记录，不要求设计档携带施工表 |
| F-R24c | 不以“最小改动”为借口回避必要的调用方和关联修复 | 接口变化的所有实际影响面得到处理 |

## 6. 文档结构

| 编号 | 要求 | 验收 |
|---|---|---|
| F7-1 | 需求答“要什么”，设计答“当前如何实现”，过程记录答“本轮做了什么” | 每份文档只承载自己层的内容；地图能定位它 |
| F7-2 | 设计写决定与一句持久理由；长期有意义的被否方案可保留其持久理由 | 试验过程、逐轮修订和一次性选型细节不留在状态档 |
| F7-3 | 多实现面语义同源、各自实现，不要求字节一致；业务端差需明确裁定 | 不用复制文本掩盖差异，不用同步脚本代替语义一致 |

## 7. 非功能判据

| 编号 | 要求 |
|---|---|
| N-1 | 评价理解成本和局部推理，不只看文件长度 |
| N-2 | 机械判据必须清晰、稳定、可复核，不随个人解释变化 |
| N-3 | 模块改动尽可能隔离，并能独立验证 |
| N-4 | 多端共享语义由共同设计和明确边界保证，不各自漂移 |

## 8. 验证与边界

- 验证提示词或文档时，不用“某句话仍在场”的散文锚代替行为验证。
- 结构检查可以检查结构和契约，但不得把措辞本身当作正确性的替代物。
- 不复制 PHILOSOPHY 正文，不复制提示词正文。
- 不在本档新增具体产品功能需求。
- 不为每项纪律另建一套工具或台账。
