# ThinCoder Server · 需求

> 设计总览 = `docs/server/design/PROJECT.md`。本档描述产品目标与验收，不记录实施轮次。

## 1. 定位与部署

为单团队提供 OpenAI 兼容模型网关、控制台、团队协同和受控开发工作区。真实上游 key 只在服务端，成员使用可吊销团队 key。

server 单进程单 SQLite 库，runner 为远程 Docker API 节点。server 自带 TLS，无 nginx 依赖；对外可达时启用 TLS、鉴权、限流和审计。缺 runner 只使沙盒不可用，不能阻止其余服务启动。

## 2. 网关、账号与用量

- 支持 chat completions SSE、models、embeddings；上游响应逐块透传，usage 旁路读取，未知/吊销 key、未知模型、配额或限流超限明确拒绝。
- 成员、admin、网页会话、多把具名 key、签发/轮换/吊销、改密与重置、防爆破和审计完整可用。
- 按成员、provider、模型、endpoint、时段计量；平台模型默认配额与成员覆盖按自然月生效，成员禁用模型立即影响清单与派发。
- provider 预设、上游发现、开放模型、别名、元数据、限流、成本权重、代理和配置控制台均有真实写面；保存/生效规则按设计。
- 用量看板、趋势、聚合、明细、导出、key 使用、健康、总览与审计可读；嵌入引擎仅旁路接入，不管理其进程。

## 3. 控制台

登录、我的 key/用量/账号/工作区，管理总览、成员、Provider、服务模型、审计、用量、系统、项目、沙盒、MCP 与对话等按当前信息架构组织。

提供中英界面、公共弹窗与标签页、统一表格/表单/按钮/状态和固定页头页脚的可读布局。管理面 chat 复用 render-core，模型/档位、附件、中止、斜杠、审批和状态行有真实后端，不能摆无源控件。

## 4. 团队协同

客户端直登后派生 server provider，登录态控制团队功能；退出吊销登录 token。个人本地台账与团队服务端台账独立，团队账全局编号、按 git 源标识，显式上送，不自动双向同步或离线缓存。

团队项目与权限先于台账：git 源/PAT、多平台仓列表、三档权限、负责人、单向成员同步、事件或定时/手动同步、删除防护与审计。

团队记忆的目标真源是 Server 数据库，personal/project 本地层不变；该目标由 #2380 承接代码落地，不作为当前实现声明。在场通知、会话协同和资产下发只在各自需求被确认后实施。

## 5. 沙盒、agent 与开发

每工作区一盒，可含多仓；只读根、唯一可写卷、资源/磁盘/TTL/容量限制、休眠/重启/销毁和快照按设计执行。容器必须存在，无伪沙盒降级。

快照恢复必须先验证快照并备份现有工作区，再清卷与解包；失败时须能恢复原工作区。该安全顺序由 #2379 承接代码落地，是恢复能力的验收门，不是当前实现声明。

节点、容器、镜像/镜像源、卷、私有仓凭据、底座派生、可选 TLS 和容器真 PTY 终端均有管理面与审计；秘密零回显。出网管控当前不建立。

管理 agent 提供成员/provider/model/usage/audit/runner/docker/SSH exec/MCP 与环境工具，走本 server 网关计量，timer 与异步任务可交付，工具调用可审计。

成员 web 开发经浏览器→server→盒内 agent，盒只出向；复用 @thincoder/core 与 render-core，不另造会话实现。盒壳自更新须校验和回退，不要求重建镜像。

## 6. 非目标与验收

不做对外计费、多租户、SSO/双因素、完整 git 托管/评审、群聊、CI/CD 编排、非 OpenAI 协议翻译或预建微服务/ORM/消息队列。

验收必须覆盖正常、边界和拒绝路径：401/403/404/429、无效配置零写、审计与秘密零泄漏、SSE/用量一致、沙盒正常开发与越界失败、真实浏览器和 runner 使用面。未实际执行的测试不得标为通过。
