# Server 成员面 Agent · 设计

> 需求与总览 = `docs/server/requirements/PROJECT.md`、`../PROJECT.md`；沙盒 = `../sandbox/EXECUTION.md`。
> 最近先例：管理 chat 与三端 core 壳。对齐 = 盒内核同件、服务器纯中转、本人资源判权。
> 勘察证据：已读盒内会话真源、双杆、拉仓、权限、帧与工具。相关 = 当前成员面。

## 1. 三链与真源

浏览器经 /api/me/chat 与 server 对话，server 经盒出向 SSE/NDJSON 与壳连接，壳经 /v1 调模型；浏览器不直连盒。

会话真源是盒卷内 core 原生槽，服务器不建成员会话表、不落回合消息。读/建/改/删/重命名通过 cmd 指令由盒执行。

## 2. 回合与断线

同会话有在途门，跨会话可并行。盒帧纯转发，支持正文/工具/子代理/审批/任务/压缩/等待与状态读数。

盒离线、掉线或重启明确收尾；浏览器断连不停止盒内回合，重连后从盒槽重读。

## 3. 工作区与拉仓

本人可建/启/停/销毁自己的工作区，受当前成员上限与确认门约束；他人资源不可见且直取 404。

拉仓选择可见项目，缺 Git 凭据时在流内录入，成员凭据加密保存、按次供盒使用且零回显。目录冲突与认证失败真实返回。

## 4. 盒内能力

使用 core assemble/run、原生模式/模型/档位、审批/秘密/提问和子代理，server 域工具只操作本人资源。

MCP 由 server 执行，盒只取无秘密工具表并桥接；桥桩恒为写类，审批由盒内核发起，Server 校验应答者为本工作区负责人并转发 answer。Server 桥没有独立审批或按工具授权层。拒绝时不发 MCP 调用，拒绝文本只进入盒内会话历史，不产生桥 result 帧或调用审计；桥执行错误则回盒并随结果帧审计。中止由盒 signal 传到桥，再传到 Server 侧 MCP execute。细节归 `../mcp/MCP.md`，核默认能力不被第二套实现替代。

## 5. 验证

验证会话真源、盒断线、同会话在途、本人隔离、拉仓凭据、审批、MCP 和真实浏览器开发链。
