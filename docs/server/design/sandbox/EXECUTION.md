# Server 沙盒执行面 · 设计

> 控制面对象 = `SANDBOX.md`。
> 最近先例：Docker 直调、OpenSSH 与 core 盒内会话。对齐 = 节点零驻留、盒只出向、失败可见。
> 勘察证据：已读三通道、生命周期、配额、底座和壳更新。相关 = 当前执行面。

## 1. 通道与生命周期

Docker API 负责网络/容器/镜像/archive，SSH 负责卷目录、磁盘配额和清理，盒出向负责模型与运行时协议。

建盒依次准备卷、配额、底座、网络、容器并启动；各步幂等，失败留行可重试。停止保卷，销毁需确认并完整清理，轮换重建保卷。

快照读取完整 archive 后 gzip 落盘并登记。当前 `restoreWorkspace` 先读取并 gunzip 快照；该步失败时还未停盒或清卷。随后依次停盒、`rm -rf <工作区路径>/*` 清卷、必要时建容器、解包并启动。解包先走 Docker `archivePut`，失败后走 SSH `tar xzf -`；两径都失败则抛错，启动失败也直接抛错。

当前恢复没有旧卷备份或自动恢复：清卷后任一解包失败都会留下空卷或部分恢复内容；启动失败发生在卷内容已被替换之后，代码同样不回滚旧卷。启动后的递归 chown 失败被忽略，不改变恢复终态。这些是当前风险边界，不得表述为安全恢复。

#2379 的安全恢复目标是先验证快照并备份现有工作区，备份和验证成功后才清卷；后续失败须能恢复原工作区。该目标尚未落地，本档其余段落只描述当前实现。放置按在线与容量，TTL/周期快照由 server ticker 驱动。

## 2. 隔离与配额

容器根只读，工作区 bind 是唯一可写卷，cap drop、CPU/内存/pids/磁盘受限，盒内只有工作区 scoped key。

磁盘使用 XFS/EXT4 项目配额或 loopback，读回验证；无法建立配额时建盒失败。loopback 只在确认归属时卸除，数据抹除与恢复必须审计。

## 3. 底座与壳

自定义底座在工作区下次建盒/重建生效。节点按底座与标准镜像 Id 内容寻址派生，私有凭据仅用于拉取，构建不携秘密。

壳启动从 server 取内容寻址工件，校验后换执行；缓存复验，失败回退内建。核仍使用镜像内同版 @thincoder/core，不随壳更新。

## 4. 验证

验证建盒各步失败、幂等、TTL、快照恢复、配额拒绝、越界写、底座缓存/回退和壳坏件不 brick。
