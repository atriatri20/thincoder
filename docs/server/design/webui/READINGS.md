# Server 读数与看板 · 设计

> 壳 = `WEBUI.md`；数据 = `../metering/METERING.md`、`../accounts/ACCOUNTS.md`。
> 最近先例：服务端聚合与健康端点。对齐 = 读数真源、零依赖呈现、失败不刷假值。
> 勘察证据：已读向量、用量、总览、审计和健康。相关 = 当前读数面。

## 1. 用量与总览

管理用量按同一筛选同时读报表和明细，显示 totals、按日 CSS 柱、模型/成员聚合、key 名称与 CSV 下载。

admin overview 显示今日请求/token、成员数、健康、更新和真实快捷入口；user 不可达。

## 2. 审计

审计页按类型/成员/时段筛选，按域模板显示 config keys、沙盒 kind、agent 工具/主语/成败和项目同步等详情，不裸丢 JSON 或秘密。

## 3. 健康与向量

health.mjs 登录后立即并按当前周期读取 /healthz，绿/黄/红分别对应 ok/degraded/不可达，侧栏、系统和总览共享。

系统向量卡显示配置与真实探活/试跑；我的用量只在已配置时显示模型名与调用提示，地址和探活留在 admin。

## 4. 验证

验证聚合逐值、空态、CSV 错误、审计模板、健康三态和角色边界。
