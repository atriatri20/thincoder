## 1. 已有扩展点

- 注册行路由：新增端点增加注册与域处理，不把条件堆进主干。
- PRAGMA user_version 顺序迁移：结构变化追加迁移，不原地改历史迁移。
- DB 会话与配置段：判权有持久真源，新增配置同步校验和 UI。
- 板→域→文件：新文件落本域，代码与文档同构。

## 2. 触发式演进

多实例只在实测承载或高可用需求出现时设计共享写面、负载均衡与 SSE；不提前引入外部数据库。

模型组路由在内部算力集群就位且有真实需求时设计，保持配额、限流、透传与用量语义。

团队记忆的目标真源是 Server 数据库；当前 core 团队层仍由 gitmem 同步，Server 尚无对应存储和读写实现。#2380 承接代码迁移，落地前不得把目标写成现役能力；当前 core 行为归 `docs/core/design/MEMORY.md`。

快照安全恢复的目标是先验证快照并备份现有工作区，再清卷和解包，失败可恢复原工作区。#2379 承接代码修复；当前恢复顺序与风险归 `sandbox/EXECUTION.md`，不得把安全目标写成当前保证。

在场通知、会话协同和资产下发按需求确认逐项设计，不以预留表或空接口冒充能力。

## 3. 不预建

无真实触发不引入消息队列、Redis、微服务、插件系统、ORM、多租户或通用负载均衡。
