# CLI 产品树残留债（CLI-DEBT）· CLI 面 · 设计

> 板块 = **CLI 产品树残留债**——`thincoder-cli/**` 的**档位（行数档）登记活账** + 结构 / 一致性尾项登记。
> 对位册 = `docs/vsc/design/VSC-DEBT.md` §12.1（VSC 越档登记）· 核内对应登记面 = `docs/core/design/DOC-DISCIPLINE.md` §3.10（尺寸档补充登记——该节只给指针、不复述判法）。
> 判据源 = 单源 `docs/core/design/DOC-GRAPH.md` §3「行数档位口径」（设计时判一次 500 ∥ 收口时判一次 800，中间一概不判）+ 各批既有裁定（逐条注源）。
> 论域 = `thincoder-cli/**`（`node_modules/` · `docs/_archive/` 除外；含 `bin/` `src/` `test/`）。

## 1. 定位与收录口径（判据句）

**定位**：CLI 树越线档的**唯一活登记面**——「挂账不处理」防线（同旨先例 = `docs/core/design/STRUCTURE-DEBT.md` §1）。
**本册不承载单批设计正文**：修法住对应板块设计档（D2——本册只登记与路由）。
**设计时的分拆方案不住本册**：>500 的分拆方案住该批设计档的「受影响文件清单与分层结论」一节（单源 §3「① 设计时判一次 = 500」）；本册只收收口面与在册裁定两类。

| # | 判据句（收录口径） | 说明 |
|---|---|---|
| 1 | **必录**：任一档 ≥ **801** 行（越 800 硬限） | 判据 = 单源 §3「② 收口时判一次 = 800」；收口检查发现 ⇒ 先拆再落（拆分是落地前置，不与落地并行）。现读 = **0 档**（越限面空） |
| 2 | **必录**：已有裁定 / 登记案在册（拆分计划 · 「不预拆」· 候选面——**无论读数**） | 裁定原文住记录面（例 = `model-picker.mjs`「不预拆」案） |

- 行维护：① 触及某档的批次在其设计轮刷新该行读数与触发状态（读数以批内实测为最终值）；
② 拆分兑现（无在册裁定）⇒ 移出本册（防回潮——先例 = STRUCTURE-DEBT §3）。

## 4. 边界（本册不做）

- 不承载单批设计正文（修法住对应板块设计档——同 STRUCTURE-DEBT §1 口径）。
- 不做代码档长度判定——长度只在两个时点判（单源 §3）；本册只登记越 800 的档与在册裁定。不设常驻机检门（见 §3-T3）。
- 不代裁需求面（`docs/cli/requirements/**` = 主 agent 笔）；本册判据源 = 单源 §3 + 各批既有裁定（逐条注源）。
