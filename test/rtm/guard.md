## CLI 7. 收口只判本批改过的档

> 目的：收口门判的是本批笔域集里**收口时点要判的档**，而每一档里只判**本批变更区**（判据 = `docs/core/design/DOC-CHECK.md`；行 7-24 ∥ 7-25）——区内照判三件、区外一个字都不出；批档面整份不在判域（批档只在写的那一刻判，行 7-21 ∥ 7-22 ∥ 7-23），且 `doc_check` 的 `report`（诊断面，判整份）与 `gate`（交付判定，判变更区）从今两 mode 不同判（行 7-22）；**工程模式写门**（`.md` 落盘前那道门）与批档 `append` ∥ `edit` 判**这一笔改的行**——盘上现文与改后文本两份求区，区外存量一条不出（行 7-27 ∥ 7-28）；普通模式的这些写入不运行内容门（行 7-29 ∥ 7-30）；**排除面**（判据 = `docs/core/design/DOC-CHECK.md`；行 7-26）：项目在 manifest 的 `index.docCheckExcludePaths` 里声明的路径前缀之下，档不进判域、不计入 `范围 N 档`；范围外的脏档同样不拦收口、也不进回执；判据不分适用面，工具描述面同样入判。另有两道并行前置：**本批改面单测档仍在盘 ⇒ 拒收口**（单测零留存，判据见行 7-4），**本批改面里的码档须在 §2 带行读数且与批起快照一致**（判据 = `docs/core/design/DOC-CHECK.md`；行 7-19 ∥ 7-20）——前一道判的是「该删的删了没」，后一道判的是「量没量、数对不对」，与本门判的「改过的档干净不干净」是三件事。本批**改动面本身也按批判**：写时归属是主判据，提交 diff 只兜底、按别的在途批的认领收窄，被认领的档只进收口回执 `[changed surface]`、不判读数（行 7-32）。

## CLI 12. 写盘与跑命令都要报它替哪条台账行服务（不分面、不分类命令）

> 目的：工程模式下父侧的每一次落盘、每一次 `bash` / `execute` 都要带 `ledger:"#N"`，且同时给出项目（`bash` ∥ `memory` 用 `project`，其余用各自的定位参数）；该号是**声明项目**台账里一条 `status = 在途` 的行；门不判批档状态，也不判命令内容——`git status` 与 `rm -rf` 同判；`manifest` **整把不在本门**（三动作都不带项目不带号，见 12-15）；目标属另一个项目而写方在 `index.writableRepos` 里声明了它时，判据点换成**写方**（12-17，机制 = `docs/core/design/CROSS-REPO-WRITE.md`）；表外而目标属另一个项目 ⇒ **无条件拒**，不查那个项目的账（12-17 末格）；目标取不到项目根时写权表仍是界（12-18）；`execute` 的 `workdir` 同走这一判序（12-19）。
